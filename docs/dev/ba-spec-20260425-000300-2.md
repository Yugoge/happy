The grep across all codex source files returns zero matches for both strings.

- When Codex protocol support lands in a future cycle, the mapper branches can be added and the renderers will activate.

## Edge Cases & Risks

- **Key naming**: `multi_tool_use.parallel` contains a dot — it must be registered as a string literal key in `toolViewRegistry` (e.g., `'multi_tool_use.parallel': CodexParallelView`). JavaScript object keys with dots are valid but require quoted syntax. Dev must confirm `getToolViewComponent()` uses exact string match.
- **`tool_suggest` registry**: if `getToolViewComponent()` returns `null` for unknown tools and the caller already handles `null` by falling back to default rendering, a registry entry for `functions.tool_suggest` may be redundant. Dev must check the call site in `ToolView.tsx` or equivalent.
- **`input.tool_uses` shape**: the exact shape of `tool_uses[]` items is unknown (protocol-blocked). `CodexParallelView.tsx` should handle `undefined`/empty array gracefully with a placeholder ("No parallel tools").
- **i18n**: any new user-visible strings in `CodexParallelView.tsx` must use `t(...)`. If a translation key doesn't exist, add it to all 9 language files.
- **TypeScript strict mode**: `CodexParallelView.tsx` must typecheck cleanly. `input` on `ToolCall` is `unknown` — cast carefully.

'functions.tool_suggest': {
    icon: ICON_REASONING,  // Octicons light-bulb (knownTools.tsx:19)
    noStatus: true,
    extractDescription: (opts) => {
        const name = opts.tool.input?.tool_name;
        return typeof name === 'string' ? `Suggest: ${name}` : t('tools.names.reasoning');
    },
},
'multi_tool_use.parallel': {
    icon: ICON_TASK,  // Octicons rocket
    noStatus: true,
    extractDescription: (opts) => {
        const uses = (opts.tool.input as any)?.tool_uses;
        const count = Array.isArray(uses) ? uses.length : 0;
        return `Parallel: ${count} tool${count !== 1 ? 's' : ''}`;
    },
},
