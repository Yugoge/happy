# BA Specification: Code Block Download Button

**Request ID**: dev-20260403-210447-4
**Created**: 2026-04-03T21:04:47Z

## Goal

Add a download button to code blocks in the markdown renderer so users can save code snippets as files. This is a basic content export capability that all competing products (Claude Desktop, ChatGPT, Gemini) provide but Happy currently lacks entirely.

## Context

The `RenderCodeBlock` component in `MarkdownView.tsx` currently has only a Copy button that appears on hover. There is no way to download code content as a file. The server has a `GET /files/*` route for serving uploaded files, but the primary use case here is client-side blob download of code block content -- no server round-trip needed. The Copy button's existing hover/visibility pattern provides the exact template for the Download button placement.

## Requirements (MoSCoW)

### Must Have
- Add a Download button next to the existing Copy button in code blocks
- Download button triggers a browser file download of the code block content
- File name should be derived from the code block language when available (e.g., `code.py`, `code.ts`, `code.sh`), falling back to `code.txt`
- Download button follows the same hover-to-reveal pattern as the existing Copy button
- Works on web platform (primary target)
- All user-visible strings use `t()` i18n function with translations in all 9 languages

### Should Have
- Show a brief success feedback after download (consistent with Copy button's alert)
- Download icon or text label distinguishable from Copy button
- On native platforms (iOS/Android), use `expo-sharing` or `expo-file-system` to save file

### Could Have
- Allow user to edit filename before download via a prompt
- Support downloading entire message content (all code blocks concatenated)

### Won't Have (Non-Goals)
- Server-side file storage for code block downloads (use client-side blob)
- Download support for non-code content (tables, images, plain text) in this iteration
- Integration with the existing `GET /files/*` server route (that is for uploaded files, not code blocks)
- Mobile share sheet integration (defer to future iteration)

## Edge Cases & Risks

- Code blocks without a language tag: fall back to `.txt` extension
- Very large code blocks: browser blob download handles these fine, no size concern
- Empty code blocks: disable or hide download button when `content` is empty/whitespace-only
- Platform differences: `document.createElement('a')` + `URL.createObjectURL` only works on web; native needs different approach. Scope primary implementation to web with graceful no-op on native.
- Language-to-extension mapping: need a mapping from markdown language identifiers (e.g., `javascript`, `python`, `bash`) to file extensions (`.js`, `.py`, `.sh`)

## Acceptance Criteria

### AC1: Download button visible on hover
- GIVEN a code block is rendered in the session view on web
- WHEN the user hovers over the code block
- THEN a Download button appears next to the Copy button

### AC2: Download triggers file save
- GIVEN the Download button is visible
- WHEN the user clicks the Download button
- THEN the browser downloads a file containing the code block content with an appropriate filename and extension

### AC3: Correct file extension from language
- GIVEN a code block with language `python`
- WHEN the user downloads it
- THEN the downloaded file is named `code.py`

### AC4: Fallback for unknown language
- GIVEN a code block with no language tag or an unmapped language
- WHEN the user downloads it
- THEN the downloaded file is named `code.txt`

### AC5: Empty code block handling
- GIVEN a code block with empty or whitespace-only content
- WHEN the code block is rendered
- THEN the Download button is either hidden or disabled

### AC6: i18n compliance
- GIVEN the app is running in any supported language
- WHEN the Download button label is displayed
- THEN it shows the localized translation of "Download"

## Technical Hints

- Primary file to modify: `packages/happy-app/sources/components/markdown/MarkdownView.tsx` (the `RenderCodeBlock` function, lines 161-207)
- Copy button pattern to replicate: lines 195-206 show the hover wrapper + Pressable pattern
- Translations: add `download` key to `common` section and `codeDownloaded`/`downloadFailed` to `markdown` section in all 9 language files under `packages/happy-app/sources/text/translations/`
- Language-to-extension mapping: create a simple utility object or function (can be inline in MarkdownView or a small utility file)
- Web download mechanism: `const blob = new Blob([content], {type: 'text/plain'}); const url = URL.createObjectURL(blob); const a = document.createElement('a'); a.href = url; a.download = filename; a.click(); URL.revokeObjectURL(url);`
- Existing styles to extend: `copyButton`, `copyButtonText`, `copyButtonWrapper` -- create parallel `downloadButton` styles or share the button styles
- The button wrapper uses `className: 'copy-button-wrapper'` for web CSS hover -- the download button should be inside the same wrapper so both appear/disappear together
