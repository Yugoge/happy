# BA Specification: §5.3 Bash Popup — Command Text Overflows Popup Width

**Request ID**: dev-20260424-143000-4
**Created**: 2026-04-24T14:30:00Z

## Goal

Fix the horizontal overflow of command text in the right-side Bash popup (SidebarBashView) so the command stays inside the popup frame at all viewport widths. Also propagates the fix to CodexBashView (§5.6 inline card) since both share CommandView.

## Context

The right-side popup (SidebarBashView) wraps CommandView inside a horizontal ScrollView. However, CommandView's inner `line` view uses `flexWrap: 'wrap'` combined with `commandText: flex: 1`, causing the ScrollView to lose its ability to scroll horizontally. The browser instead wraps the text onto new lines (or clips it), making the command visually overflow the popup container. This pattern has existed since the initial commit (7f178466) and was never corrected when the sidebar popup was introduced.

## Setup / Environment

- **viewport**: all supported widths — desktop default (≥1280px), narrow desktop (901–1280px), tablet (768–900px), mobile (<768px)
- **theme**: both light and dark (theme does not affect layout)

- **auth_state**: logged-in (requires an active session with a Bash tool call)
- **data_state**: session with at least one Bash tool-call (long command path, e.g., `$ ls /root/docs/dev/ba-spec-...`)

- **url_path**: `/` (session view with right sidebar open on a Bash tool call)

## Evidence (Contract A)

- **Observed**: "打开右侧弹窗显示的bash命令超出了弹窗宽度" — opening the right-side popup for a Bash tool call shows the command text (`$ ls /root/docs/dev/ba-spec-20260423-080000.md /root/docs/dev/con…`) overflowing the popup's horizontal bounds.
- **Measured**: `CommandView.tsx:44-46` — `line` style: `flexDirection: 'row', flexWrap: 'wrap'`; `CommandView.tsx:58-60` — `commandText` style: `flex: 1`. These two properties together instruct React Native to let the `commandText` grow to fill remaining row width, then wrap to the next line if the parent is wider. When the parent is a horizontal ScrollView child, `flex: 1` on the command text still resolves against the parent's measured width (not the scroll content width), breaking the intended horizontal-scroll behaviour.
- **Expected**: The `line` container should NOT use `flexWrap: 'wrap'` when horizontal scrolling is the intended interaction. The command text should have a fixed (or intrinsic) width so the ScrollView content dimension exceeds the popup frame and scrolling works. This matches the pattern used in `BashView.tsx:63-81` (inline card) where the inner `commandLine` view has no `flexWrap` and the `command` Text has no `flex: 1`.
- **Gap**: Remove `flexWrap: 'wrap'` from `CommandView.tsx:45` and remove `flex: 1` from `commandText` style (line 59). This makes the text intrinsic-width, allowing the outer horizontal ScrollView to calculate scroll content size correctly.

## Edge Cases & Risks

- **flexGrow vs flex on scroll children**: The `commandWrapper` in SidebarBashView and BashViewFull already uses `flex: 1, minWidth: '100%'`. After removing `flex: 1` from `commandText` in CommandView, verify the wrapper's `flex: 1` does not re-introduce the problem (it should not — the wrapper is a View inside ScrollView content, not a Text inside a flex row).
- **CodexBashView has no outer ScrollView**: Adding a `ScrollView horizontal` around the CommandView in CodexBashView's bash branch will be a structural change to that branch. Ensure the new wrapper does not break the `ToolSectionView` outer padding.
- **`fullWidth` prop interaction**: SidebarBashView passes `fullWidth` to CommandView (line 55), which injects `width: '100%'` on the container. After removing `flexWrap` + `flex: 1`, `width: '100%'` on the container and intrinsic-width children should still size correctly inside the ScrollView content view.
- **Web-only `overflow: 'hidden'` on container**: CommandView container has `overflow: 'hidden'` (line 37). This clips web scrollbars. The ScrollView is outside CommandView, so this should not interfere — but QA should verify the horizontal scrollbar is visible in the browser.
- **Output text (stdout/stderr)**: Long output lines in CommandView also lack horizontal scrolling. This is in scope for §5.3 "Acceptable solutions" since QA will test the full popup. However, since the instructions hint at removing `flexWrap`/`flex:1` from the command line row only, the output text change is a Should-Have (R5) — dev should address if straightforward.

## Technical Hints

- **Root cause** (inferred, L2 structural): `CommandView.tsx:45` `flexWrap: 'wrap'` and `CommandView.tsx:59` `flex: 1` on `commandText`. These two together defeat the outer horizontal ScrollView because React Native resolves `flex: 1` against the parent row's bounded width, then wraps the text into that width — the ScrollView never sees content wider than the container.
- **Fix A — CommandView only (preferred, minimal)**: In `CommandView.tsx`, change `line` style: remove `flexWrap: 'wrap'` (keep `flexDirection: 'row', alignItems: 'baseline'`). Change `commandText` style: remove `flex: 1`. This makes the command text render at its intrinsic (natural) width, allowing the ScrollView in callers to measure the full content extent and scroll.
- **Fix B — caller-level wrapper (alternative)**: If removing `flex: 1` has unexpected side effects (e.g., output text layout breaks), wrap only the `<View style={styles.line}>` inside a horizontal `ScrollView` inside CommandView itself, and remove the duplicate outer ScrollViews in callers. This is a larger change.
- **Preferred approach**: Fix A — minimal change in CommandView, no changes required in BashViewFull or SidebarBashView callers (they already have the correct ScrollView wrapper).
- **CodexBashView addition**: In `CodexBashView.tsx:86-101` (bash/unknown branch), wrap the `<CommandView ...>` in a `<ScrollView horizontal showsHorizontalScrollIndicator contentContainerStyle={{ flexGrow: 1 }}>` block (mirroring `SidebarBashView.tsx:44-48`).
- **Files to modify**:
  - `packages/happy-app/sources/components/CommandView.tsx` (lines 44-46 and 58-60)
  - `packages/happy-app/sources/components/tools/views/CodexBashView.tsx` (lines 86-101, bash branch — add ScrollView)
- **Files NOT to modify**: `SidebarBashView.tsx`, `BashViewFull.tsx` — their ScrollView wrappers are already correct and will work once CommandView is fixed.
- **Test surface**: open right sidebar on a Bash tool call with a long command. On desktop: horizontal scrollbar appears, command stays in frame. On mobile: modal shows command in frame, drag-scroll works.
