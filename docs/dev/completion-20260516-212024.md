### Phase 2: Codex monitoring in watcher/save — write_json_snapshot fix

**Problem**: `write_json_snapshot` in `/root/bin/happy-session-recovery.sh` (lines 309-321) always constructs `session_file` as a Claude project path for every session entry, regardless of whether the session is a codex session. No `flavor` field exists, making JSON snapshots unable to distinguish codex tids from claude UUIDs.

**Root cause**: The function was written before codex session tracking was added to `scan_running_sessions`. The scan layer (Sources 3a/3b) was correctly updated to include codex sessions, but `write_json_snapshot` was never updated to handle them.

**Solution**: A patch script has been produced at `docs/dev/patches/write_json_snapshot-20260516-212024.sh`. This patch:
1. Adds a `flavor` field ("codex" or "claude") to every session entry in the JSON snapshot
2. For codex entries: sets `session_file` to the rollout path (or empty string if invalid)
3. For claude entries: preserves the existing Claude project path behavior
4. Uses `jq -n --arg` for injection-safe JSON construction (replaces raw `echo` with JSON)
5. Calls `find_codex_rollout` exactly once per entry (efficient)

**Apply the patch**:
```bash
bash docs/dev/patches/write_json_snapshot-20260516-212024.sh --apply
```

**Verify after applying**:

SNAP=$(ls -t ~/.happy/session_backup_history/*.json | head -1)
jq '[.sessions[] | {id: .claude_id, flavor: .flavor}]' "$SNAP"
