# BA Specification: Sidechain Messages Not in Main JSONL -- Scanner Reads Wrong Location

**Request ID**: dev-20260410-0750
**Created**: 2026-04-10T07:50:00Z

## Goal

Determine why the sidechain forwarding changes in sessionScanner.ts and claudeRemoteLauncher.ts have no effect, and identify the correct approach to forward subagent internal messages to the happy-server.

## Context

Two files were modified to forward `isSidechain: true` messages from Claude Code's JSONL session files to the happy-server. After deployment, the Agent tool sidebar in the browser still shows only prompt + tool calls + result, with no subagent internal operations visible.

**Root cause discovered**: Claude Code does NOT write subagent messages to the main session JSONL file. It writes them to SEPARATE files in a `subagents/` subdirectory. The session scanner only reads the main JSONL file, so it never encounters any sidechain messages to forward.

## Root Cause Analysis

### File Storage Architecture (Claude Code)

```
~/.claude/projects/<project-id>/
  <session-id>.jsonl              <-- Main session file (only top-level messages)
  <session-id>/
    subagents/
      agent-<agentId>.jsonl       <-- Subagent messages (isSidechain: true)
      agent-<agentId>.meta.json   <-- Subagent metadata (agentType, description)
```

### Evidence

1. **Main JSONL has ZERO `isSidechain: true` messages** across ALL session files checked (dozens of files, including sessions with multiple Agent tool calls).

2. **Main JSONL has ZERO `parent_tool_use_id` fields** -- this field does not appear in any main session JSONL.

3. **Subagent JSONL files DO have `isSidechain: true`** with fields: `agentId`, `promptId`, `parentUuid`, `sessionId` (same as parent), `isSidechain: true`. They do NOT have `parent_tool_use_id`.

4. **The session scanner reads**: `join(projectDir, sessionId + '.jsonl')` -- only the main file.

5. **The SDK stream-json stdout** emits `parent_tool_use_id` on subagent messages (confirmed in types.ts). This is the LIVE stream path. But the scanner reads from FILES, not the live stream.

### Two Data Paths (Critical Distinction)

| Path | Source | Has sidechain? | Used by |
|------|--------|----------------|---------|
| **Live SDK stream** | claude stdout via `--output-format stream-json --verbose` | YES -- `parent_tool_use_id` present on subagent messages | `sdkToLogConverter.convert()` in `buildOnMessage()` |
| **JSONL files** | Written by Claude Code to `~/.claude/projects/` | NO in main file; YES in `subagents/` subdirectory | `sessionScanner.ts` |

### Why the Fix Has No Effect

The scanner reads `<session-id>.jsonl` and looks for `isSidechain: true` messages. But Claude Code never writes sidechain messages to that file -- it writes them to `<session-id>/subagents/agent-<id>.jsonl` instead.

## Requirements (MoSCoW)

### Must Have
- Subagent internal messages (text, tool calls, tool results, thinking) must be forwarded to happy-server
- Messages must arrive with correct `isSidechain: true` flag and association to the parent Agent tool call
- No duplicate messages (dedup between live stream and file scanner)

### Should Have
- Support for both live stream path AND file scanner path (resume/recovery needs file path)
- Correct ordering of subagent messages relative to parent conversation

### Could Have
- Streaming of subagent messages as they happen (not just at file sync intervals)

### Won't Have (Non-Goals)
- Changes to Claude Code itself (we cannot modify how it writes JSONL files)
- Changes to the happy-app rendering (separate concern)

## Edge Cases & Risks

- **Resume path**: When resuming a session with `--resume`, the scanner must also read subagent files from the previous session
- **Multiple concurrent subagents**: A session can have many subagent files; all must be scanned
- **agentId mapping**: Subagent files use `agentId` (e.g., `ab1359ac8e0b8f863`), not `parent_tool_use_id`. The live stream uses `parent_tool_use_id`. These are different identifiers.
- **File naming**: Subagent files are named `agent-<agentId>.jsonl` with a corresponding `.meta.json`

## Acceptance Criteria

### AC1: Subagent messages forwarded from files
- GIVEN a session with Agent tool calls and subagent files in the `subagents/` directory
- WHEN the session scanner runs
- THEN all messages from subagent JSONL files are read, marked with `isSidechain: true`, and forwarded via `onMessage`

### AC2: No duplicates between live stream and file scanner
- GIVEN a subagent message that was already sent via the live SDK stream path
- WHEN the file scanner encounters the same message in the subagent JSONL
- THEN it is not sent again (dedup by UUID)

### AC3: Resume includes subagent history
- GIVEN a resumed session with `sendExisting: true`
- WHEN the scanner initializes
- THEN subagent JSONL files from the session directory are included in the upload

## Technical Hints

- **Affected files**: `packages/happy-cli/src/claude/utils/sessionScanner.ts`
- **Subagent file location**: `<projectDir>/<sessionId>/subagents/agent-<agentId>.jsonl`
- **Subagent meta**: `<projectDir>/<sessionId>/subagents/agent-<agentId>.meta.json` contains `{ agentType, description }`
- **File watcher**: Needs to watch the `subagents/` directory for new files, plus watch each subagent JSONL for updates
- **Live stream path**: Already works via `sdkToLogConverter.convert()` which checks `parent_tool_use_id` -- this is the OTHER path, handled in `buildOnMessage()`. The scanner is for the FILE path (resume, recovery, catching messages missed by live stream).
