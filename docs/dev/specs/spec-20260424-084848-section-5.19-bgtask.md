### 5.19 后台任务通知不实时刷新到 happy session（critical regression）

**用户原话（多轮陈述合并）**:

1. "刚刚后台任务导致 happy session 不更新的问题重新出现了。只有用户重新发消息才会收到后台任务结束了 claude 的反映（响应/输出）。这个是很严重的问题。"

2. "我在 web 端打开的时候出现了后台任务，然后我关闭了 web。然后重新打开 web 之后我发现我的 happy session 左下角的 claude babling 消失了，只有 online 了，这说明整个 session 断开了实时 update claude code session。"

- AC3: `Last Updated` 时间戳必须随 session 实际活动持续刷新；不应因为 turn 结束而冻结

### Two-Layer Root Cause (interlocked)

**Layer 1 — CLI sender side (H_F, user observation)**:

- `packages/happy-cli/src/claude/session.ts:69-73` starts `keepAlive()` that fires `session-alive` ephemeral every 2s
- `packages/happy-cli/src/api/apiSession.ts:523-533` emits `socket.volatile.emit('session-alive', ...)`
- After Stop hook fires (end of turn), keepAlive timer is **turn-scoped** (suspect): the setInterval may be cleared or the SDK-driven heartbeat cadence collapses
- **Evidence**: User's screenshot shows `Last Updated 25/04/2026, 23:16:47` frozen — server's `lastActiveAt` field stops being updated (proves `session-alive` stopped firing)
- Background-task wake → claude responds → CLI emits `new-message` (persistent) but **NOT** a fresh `thinking=true` ephemeral
- Net effect: persistent message channel works; ephemeral status channel goes silent

**Layer 2 — App receiver side (H_E, Codex finding)**:

- "claude babbling" UI rendered at `packages/happy-app/sources/components/AgentInput.tsx:778-804`, sourced from `session.thinking` local state (not server-persisted)
- Server's Prisma schema (`packages/happy-server/prisma/schema.prisma:93-105`) persists only `active` + `lastActiveAt`, NOT `thinking`
- App uses **single user-scoped global socket**, no per-session subscribe (`packages/happy-app/sources/sync/apiSocket.ts:59-69`)
- On reopen/reconnect:
  - `sync.ts:784-808` (fetchSessions hydrate) **resets `thinking: false` for all sessions**
  - `sync.ts:1647-1729` (fetchMessages) only fetches messages, doesn't replay lifecycle to recover `thinking`
  - `sync.ts:1756-1771` (reconnect callback) only invalidates sync caches; does NOT trigger visible-session re-fetch
- Visible-session catch-up at `SessionView.tsx:278-281` is bound to `realtimeStatus` (voice realtime) NOT `socketStatus` (websocket)
- No server-side "client connect → send current thinking snapshot" logic for sessions (only machines have `socket.ts:103-112`)
- Net effect: app has no recovery path for `thinking` ephemeral after reconnect; can only wait for next CLI emit (which won't come per Layer 1)

### Why Two Layers Interlock

H_F (CLI) creates the trigger (no thinking emit on bg-wake). H_E (app) makes it irrecoverable (reset-on-reopen + no catch-up + no snapshot). Either fix alone is insufficient. Server side also needs minor change (ephemeral snapshot endpoint OR short-TTL thinking persistence).

### Three-pipeline parallel fix (Cycle 6 Dev plan)

**Pipeline 7.1 — CLI keepAlive scope fix (Layer 1 / H_F)**:

- File: `packages/happy-cli/src/claude/session.ts` (lines ~69-93)
- File: `packages/happy-cli/src/api/apiSession.ts` (lines ~151-155, 523-533)
- Goal: ensure `keepAlive` (session-alive emit) is **session-scoped**, NOT turn-scoped — runs continuously while session is alive, regardless of whether claude is in an active turn
- Goal: ensure `thinking=true` is re-emitted whenever claude starts producing output (including from background-task notifications), not just from user prompts
- Layer: L4 (state machine / event emission timing)

**Pipeline 7.2 — Server thinking snapshot on connect (Layer 1.5 / supports H_E recovery)**:

- File: `packages/happy-server/sources/app/api/socket/sessionUpdateHandler.ts`
- File: `packages/happy-server/sources/app/api/socket.ts:103-112` (machine-connect snapshot pattern as reference)
- Goal: on new socket connection, if any session's CLI is currently `active=true`, send the **current** ephemeral activity snapshot (thinking state if known) to the new client
- Optional: short-TTL persistence of `thinking` so server can answer "is X currently thinking?" between heartbeats
- Layer: L4 (server state distribution)

**Pipeline 7.3 — App reconnect catch-up wiring fix (Layer 2 / H_E)**:

- File: `packages/happy-app/sources/-session/SessionView.tsx:275-281` — change `useRealtimeStatus()` dependency to `useSocketStatus()`
- File: `packages/happy-app/sources/sync/sync.ts:1756-1771` — on socket reconnect, trigger visible-session catch-up
- File: `packages/happy-app/sources/sync/sync.ts:784-808` — don't reset `thinking: false` on hydrate; preserve last-known or wait for snapshot
- Goal: when web tab reopens and websocket reconnects, the visible session re-fetches messages AND requests a fresh ephemeral snapshot
- Layer: L4 (data flow wiring)
