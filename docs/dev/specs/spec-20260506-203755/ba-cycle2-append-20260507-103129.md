## Section 1 (Cycle 2): Before — restate the regression precisely

The Cycle 1 fix (working-tree HEAD; dev-report `dev-report-20260507-055611.json`) added inline-span rendering to web table `<td>` and `<th>` paths in `packages/happy-app/sources/components/markdown/MarkdownView.tsx`. The diff shape was:

- **`MarkdownView.tsx:419-426`** (`WebTableRow` body): Cycle 1 replaced `<td>{props.row[colIndex] ?? ''}</td>` with `<td>...><RenderSpans spans={parseMarkdownSpans(props.row[colIndex] ?? '', false)} selectable={...} onLinkPress={...} /></td>`. **No parent `<Text>` wrapper.**
- **`MarkdownView.tsx:444-447`** (`RenderTableBlockWeb` `<thead>` `<th>`): Cycle 1 replaced `<th>{header}</th>` with `<th>...><RenderSpans spans={parseMarkdownSpans(header, false)} selectable={...} onLinkPress={...} /></th>`. **No parent `<Text>` wrapper.**

`RenderSpans` returns a fragment `<>{spans.map((span, i) => <Text key={i} ...>...</Text>)}</>`. On react-native-web (RNW), a `<Text>` element whose immediate ancestor is **not** another `<Text>` defaults to `display: flex` with column-direction (RNW's Text layout falls back to flex when not in a Text-context); each formatted span therefore renders as its own block-line.

User-visible regression confirmed in close-debate Round 2 (`close-report-20260507-055611.md`):

- Cell text `**bold** ~~strike~~ [link](https://example.com) \`code\`` (the AC2 fixture) renders as four stacked rows inside one cell, both at desktop 1440x900 and mobile 390x844.
- Visual evidence: `docs/dev/evidence/20260507-055611/qa-20260507-055611-sessionid-desktop-render.png` and `docs/dev/evidence/20260507-055611/qa-20260507-055611-sessionid-mobile-render.png`.
- The Cycle 1 QA DOM-style measurements (`fontWeight=700`, `textDecorationLine=line-through`, `role=link`, `fontFamily=IBMPlexMono-Regular`) only sampled computed CSS on individual span nodes — none of those measurements expose the inline-vs-block flow at the layout level, which is why the regression was not caught before close.

The native path is **unaffected**: `NativeTableColumn` (`MarkdownView.tsx:478-482`) wraps `RenderSpans` inside `<Text style={style.tableCellText}>...</Text>`, establishing the RNW Text-context that keeps siblings inline. Only the web `<td>`/`<th>` path needs to be made symmetrical.

Git localization for the regression: the Cycle 1 working-tree diff on `MarkdownView.tsx` (HEAD vs working tree, captured in dev-report `dev-report-20260507-055611.json`). The Cycle 1 commit in this overnight cycle that introduced the wrapper-less spans inside `<td>`/`<th>` has not yet been committed (working tree); the prior baseline that emitted plain string cells comes from commit `0dd09cc3` ("fix: align table rendering with prod — empty first cell no longer drops last column"), and the inline-rendering-via-RenderSpans change is the in-progress Cycle 1 working-tree edit at lines 419-426 / 444-447 of `MarkdownView.tsx`.

## Section 7 (Cycle 2): What Must Be Done

### 7.1 (Cycle 2): Minimum-scope fix prescription

Per `close-report-20260507-055611.md` Round 2 codex prescription (ratified by QA), wrap `RenderSpans` output in a single parent `<Text>` container inside both `<td>` and `<th>` on the web table path. Mirror the approach already used in `NativeTableColumn` (which wraps in `<Text style={style.tableCellText}>...</Text>`).

**Concrete file/line targets** (file = `packages/happy-app/sources/components/markdown/MarkdownView.tsx`):

1. **`<th>` wrap** at lines 444-447 (`RenderTableBlockWeb` thead): replace
   ```tsx
   <th key={i} style={...}>
       <RenderSpans spans={parseMarkdownSpans(header, false)}
           selectable={props.selectable} onLinkPress={props.onLinkPress} />
   </th>
   ```
   with
   ```tsx
   <th key={i} style={...}>
       <Text style={style.tableHeaderText} selectable={props.selectable}>
           <RenderSpans spans={parseMarkdownSpans(header, false)}
               baseStyle={style.tableHeaderText}
               selectable={props.selectable} onLinkPress={props.onLinkPress} />
       </Text>
   </th>
   ```

2. **`<td>` wrap** at lines 419-426 (`WebTableRow` body): replace
   ```tsx
   <td key={colIndex} style={...}>
       <RenderSpans spans={parseMarkdownSpans(props.row[colIndex] ?? '', false)}
           selectable={props.selectable} onLinkPress={props.onLinkPress} />
   </td>
   ```
   with
   ```tsx
   <td key={colIndex} style={...}>
       <Text style={style.tableCellText} selectable={props.selectable}>
           <RenderSpans spans={parseMarkdownSpans(props.row[colIndex] ?? '', false)}
               baseStyle={style.tableCellText}
               selectable={props.selectable} onLinkPress={props.onLinkPress} />
       </Text>
   </td>
   ```

The native path at lines 478-482 already has the parent `<Text style={style.tableCellText}>` wrapper and MUST NOT be modified by Cycle 2 (mirror, do not duplicate the change).

The `<Text>` styles (`style.tableHeaderText` / `style.tableCellText`) already exist in the same file's `style = StyleSheet.create(...)` declaration and are used by the native path — reuse them for visual parity with native, NOT a new Unistyles entry, NOT a new RNW-only class.

### 7.2 (Cycle 2): Test additions (x-coordinate flow measurement)

QA's verification recipe for Cycle 2 MUST include explicit x/y bounding-rect flow measurement, not just computed-style assertions:

1. Resend the AC2 fixture into the same dev UI session used in Cycle 1 (or a new one created via the UI flow), in both desktop 1440x900 and mobile 390x844 viewports.
2. Locate the first data-row cell that contains the inline `bold strike link code` text. Selector candidate: `table tbody tr:first-of-type td:first-of-type` within the AC2 message bubble.
3. Within that cell, query each formatted span by its known styling (bold via `[style*="font-weight: 700"]`, strike via `[style*="line-through"]`, link via `a[href="https://example.com"]` or `[role="link"]`, code via `[style*="IBMPlexMono"]`).
4. Read each span's `getBoundingClientRect()` → `{x, y, width, height}`.
5. Compute `maxYDelta = max(rects.map(r => r.y)) - min(rects.map(r => r.y))`.
6. Assert `maxYDelta <= 2` at both desktop and mobile when cell width permits a single line. (When cell content overflows the cell width and natural wrapping kicks in, the assertion MAY be relaxed to "spans on the same wrap-line share the same y" — the AC2 fixture's first cell `bold strike link code` is short enough that a single line is expected at both viewports.)
7. Save the raw measurement at `docs/dev/evidence/<TASK_ID>/inline-flow-measurement.json` per the AC-NEW-1 recipe.

The Cycle 1 parser regression suite (`parseMarkdown.test.ts`) MUST continue to pass unchanged — Cycle 2 does NOT touch `parseMarkdownSpans.ts` or the parser tests. The wrapper change is a pure renderer fix.
