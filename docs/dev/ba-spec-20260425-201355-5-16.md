### Decision Note (mid-line `$$…$$` rendering mode)

The user wrote `block` LaTeX, so semantically `$$…$$` mid-line should
render as **block** (display) math. Pure markdown convention requires
`$$…$$` on its own line; mixing it with prose is informal but commonly
expected to break onto its own visual line. Two acceptable behaviours:

1. **Treat mid-line `$$…$$` as inline display** (KaTeX `displayMode:true`
   inside an inline span). Mathematically correct; visually a tall
   formula squeezed onto the prose line.
2. **Hoist mid-line `$$…$$` to its own block** (insert a virtual line
   break before/after, route through `LatexRenderer` with `displayMode:true`).
   Visually closer to user expectation; structurally invasive.

Recommendation: option 1 (in-place inline display). It is a 5-line span
parser change and matches "block was good" semantically — the user gets
a typeset formula with `displayMode:true`. Option 2 should be a separate
follow-up if visual squeeze proves too cramped.

## Edge Cases & Risks

- **Greedy vs lazy `$$` regex**: a line containing TWO `$$…$$` formulas
  must match each independently. Use lazy `\$\$([\s\S]+?)\$\$` so the
  closing `$$` is the FIRST one after content, not the last.
- **`$$$` triple dollar** (e.g. `$$$alpha$$$`): unusual; not a markdown
  convention. Acceptable to leave as-is (will render as `$<KaTeX(alpha)>$`).
- **`$$` adjacent to other markdown syntax** (e.g. `**bold $$E=mc^2$$ end**`):
  the bold `**…**` regex runs alongside the new `$$…$$` alternative; the
  global regex's first match wins. Test that bold containing math doesn't
  break.
- **Dev environment risk**: rebuild + redeploy of `happy-web-dev` is required
  for verification (per CLAUDE.md "Dev-Overnight Worktree Build & Deploy").
  Build from worktree, NEVER from `/root/happy`. Use
  `--build-arg HAPPY_SERVER_URL=https://api-dev.life-ai.app`.
