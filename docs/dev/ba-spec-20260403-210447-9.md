# BA Specification: Mermaid Timeline Diagram Chinese Character / Empty Event Rendering Fix

**Request ID**: dev-20260403-210447-9
**Created**: 2026-04-03T21:04:47Z

## Goal

Fix Mermaid timeline diagrams that fail to render when they contain Chinese characters or empty event entries, causing fallback to raw source display with a "Mermaid diagram syntax error" message.

## Context

MermaidRenderer.tsx handles rendering of Mermaid diagrams on both web (direct SVG via mermaid.render()) and native (WebView). The mermaid library has known issues parsing non-ASCII characters in timeline diagram types specifically. When mermaid.render() throws, the component catches the error and shows the raw diagram source with an error message -- a poor user experience. A previous sanitization fix was attempted and reverted, suggesting the approach needs to be more targeted.

## Requirements (MoSCoW)

### Must Have
- Pre-process timeline diagram content before passing to mermaid.render() to handle Chinese characters
- Remove or skip empty event entries that cause parse failures
- Maintain a graceful fallback: show a user-friendly "Timeline diagram could not be rendered" message instead of raw Mermaid source code when rendering still fails after sanitization

### Should Have
- Preserve the semantic meaning of timeline entries when transliterating/replacing Chinese characters (e.g., replace with pinyin or descriptive ASCII equivalents where feasible)
- Apply sanitization only to timeline diagram types (not flowcharts, sequence diagrams, etc. which handle Unicode fine)

### Could Have
- Log the original diagram content at warn level for debugging

### Won't Have (Non-Goals)
- Full CJK transliteration library integration
- Fixing mermaid library upstream
- Changing native (WebView) rendering path -- focus on web platform where the issue manifests

## Edge Cases & Risks

- Sanitization may alter diagram semantics if Chinese text is meaningful labels
- Other non-ASCII scripts (Japanese, Korean, Arabic) may have similar issues -- sanitizer should handle broadly
- Mermaid version updates may fix or change parsing behavior
- Empty lines vs. empty events need distinct handling

## Acceptance Criteria

### AC1: Chinese character timeline renders
- GIVEN a Mermaid timeline diagram containing Chinese characters
- WHEN the MermaidRenderer processes it on web
- THEN the diagram renders as SVG without falling back to raw source display

### AC2: Empty event timeline renders
- GIVEN a Mermaid timeline diagram with empty event entries
- WHEN the MermaidRenderer processes it on web
- THEN empty entries are stripped and the diagram renders successfully

### AC3: Graceful fallback on unrecoverable error
- GIVEN a Mermaid diagram that still fails after sanitization
- WHEN rendering fails
- THEN a user-friendly message is shown (not raw Mermaid source code)

### AC4: Non-timeline diagrams unaffected
- GIVEN a flowchart or sequence diagram with Unicode characters
- WHEN rendered through MermaidRenderer
- THEN no sanitization is applied and rendering works as before
