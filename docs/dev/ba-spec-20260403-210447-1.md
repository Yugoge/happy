# BA Specification: Re-wire File Attachment UI in AgentInput

**Request ID**: dev-20260403-210447-1
**Created**: 2026-04-03T21:04:47Z

## Goal

Re-integrate the file attachment/upload button and attachment strip into the AgentInput toolbar and SessionView, restoring functionality that was lost during the upstream merge commit `925f5960`.

## Context

Commit `f8b208fa` (2026-03-23) introduced end-to-end file upload support: `useAttachments.ts` hook, `AttachmentStrip.tsx` component, server endpoint `POST /v3/sessions/:id/upload`, and wiring in both `AgentInput.tsx` and `SessionView.tsx`. The subsequent merge commit `925f5960` ("Merge upstream slopus/happy -- 153 commits: Expo SDK 55, new session composer, voice refactor, OpenClaw, profile removal, SIGPIPE fix") rewrote `AgentInput.tsx` and `SessionView.tsx` extensively, dropping all attachment imports, props, and UI elements. The hook and component files survived the merge intact but are now orphaned -- never imported or used.

## Requirements (MoSCoW)

### Must Have
- Add `useAttachments` hook call in `SessionView.tsx` with the current `sessionId`
- Pass attachment-related props from `SessionView.tsx` to `AgentInput`: `pendingAttachments`, `onAttachImage`, `onAttachDocument`, `onRemoveAttachment`
- Add paperclip/attach button to `AgentInput.tsx` action button row (left side, alongside gear/agent/abort/git buttons)
- Render `AttachmentStrip` above the input field inside `AgentInput.tsx` when attachments are present
- Pass `readyAttachments` to `sync.sendMessage()` and call `clearAttachments()` on send
- Allow sending a message when text is empty but attachments are present (`hasAttachments`)

### Should Have
- Attach button should open a menu/action-sheet with "Image" and "Document" options (matching original `f8b208fa` implementation pattern)
- Support paste-to-attach on web (integrate `addFileFromPaste` from the hook)

### Could Have
- Drag-and-drop file attachment on web platform
- Attachment count badge on the paperclip button when attachments are pending

### Won't Have (Non-Goals)
- Changes to the server upload endpoint (already working)
- Changes to `useAttachments.ts` hook logic (already complete)
- Changes to `AttachmentStrip.tsx` component (already complete)
- Changes to `sync.ts` sendMessage/uploadAttachment (already complete)
- Attachment support in the new session composer (`/new/index.tsx`)

## Edge Cases & Risks

- The `AgentInput` component is shared across session types (Claude, Codex, Gemini, OpenClaw) -- the attach button should work for all agent types
- The `onSend` callback in `SessionView.tsx` currently only checks `message.trim()` -- must also allow send when `hasAttachments` is true even with empty text
- The `canPressSendButton` logic in `AgentInput.tsx` needs to account for pending attachments
- Upload failures should not block message sending (the hook already handles error states per-attachment)
- Persisted attachments should restore correctly on session re-open (already handled by hook)

## Acceptance Criteria

### AC1: Paperclip button visible in input toolbar
- GIVEN a user is viewing an active session
- WHEN the session view renders with AgentInput
- THEN a paperclip/attach icon button is visible in the action buttons row

### AC2: Image picker opens from attach button
- GIVEN a user taps the paperclip button
- WHEN they select "Image" from the menu
- THEN the image picker opens and a selected image appears in the AttachmentStrip above the input

### AC3: Document picker opens from attach button
- GIVEN a user taps the paperclip button
- WHEN they select "Document" from the menu
- THEN the document picker opens and a selected file appears in the AttachmentStrip

### AC4: Attachments sent with message
- GIVEN a user has one or more ready attachments and types a message
- WHEN they press Send
- THEN `sync.sendMessage()` is called with both the text and the ready attachment metadata, and the attachment strip clears

### AC5: Send enabled with attachments but no text
- GIVEN a user has one or more ready attachments but the text input is empty
- WHEN the send button state is evaluated
- THEN the send button is enabled and pressing it sends the attachments

### AC6: Attachment strip renders above input
- GIVEN one or more attachments are pending
- WHEN the AgentInput renders
- THEN the AttachmentStrip component is visible between the context info box and the unified panel

## Technical Hints

- Affected files: `packages/happy-app/sources/-session/SessionView.tsx`, `packages/happy-app/sources/components/AgentInput.tsx`
- Related patterns: The original wiring from commit `f8b208fa` shows the exact prop names and integration points that were removed
- The `AgentInput` props interface needs 4 new optional props: `pendingAttachments`, `onAttachImage`, `onAttachDocument`, `onRemoveAttachment`
- The `canPressSendButton` logic (line ~307) needs a `hasAttachments` condition
- The `onSend` handler in SessionView needs to check `hasAttachments` in addition to `message.trim()`
- Use `Ionicons` name `"attach"` or `"attach-outline"` for the paperclip icon (consistent with existing Ionicons usage)
- Attach menu can use a simple `Pressable` with two options or leverage the existing `FloatingOverlay` pattern
