# BA Specification: Add wrapped event rendering to AgentEventBlock

**Request ID**: dev-20260403-210447-2
**Created**: 2026-04-03T21:04:47Z

## Goal

Add a `wrapped` case to the `AgentEventBlock` switch in `MessageView.tsx` so that `wrap` envelope types (skill/command prompts) render as collapsible blocks with label and content, instead of falling through to the "Unknown event" default.

## Context

The session protocol defines a `wrap` envelope type for skill/command prompts (e.g., `/commit`, `/review-pr`). The CLI mapper in `sessionProtocolMapper.ts` sends these as `wrap` envelopes, and `typesRaw.ts` correctly normalizes them to `{ type: 'wrapped', label: string, content: string }` AgentEvents. However, `AgentEventBlock` in `MessageView.tsx` only handles `switch`, `message`, and `limit-reached` -- it has no case for `wrapped`, causing all wrap envelopes to render as "Unknown event" (the default fallback at line 144-148).

## Requirements (MoSCoW)

### Must Have
- Add a `wrapped` case to `AgentEventBlock` that renders label as a header and content as expandable/collapsible body
- Content should default to collapsed state (user expands on tap)
- Use existing styling patterns from the codebase (Pressable, Unistyles theme)
- Support markdown rendering in the content body (wrap content can contain markdown)

### Should Have
- Visual indicator for expand/collapse state (chevron icon or similar)
- Smooth transition consistent with other expandable UI in the app
- Add i18n translation key for any new user-visible strings (if any static strings are needed)

### Could Have
- Animated expand/collapse transition

### Won't Have (Non-Goals)
- Changes to the protocol or envelope normalization (typesRaw.ts is correct as-is)
- Changes to sessionProtocol.ts or sessionProtocolMapper.ts
- New component file -- this should be inline in MessageView.tsx or a small helper in the same file

## Edge Cases & Risks

- Empty label: should still render the collapsible block (show content only)
- Empty content: should render the label with no expandable body
- Very long content: markdown renderer handles this, but ensure no layout overflow
- Rapid expand/collapse: ensure state is stable (simple boolean toggle)

## Acceptance Criteria

### AC1: Wrapped events render with label header
- GIVEN a session contains a message with a `wrap` envelope (e.g., a `/commit` skill invocation)
- WHEN the message is rendered in MessageView
- THEN the wrap label appears as a styled header text (not "Unknown event")

### AC2: Content is collapsible
- GIVEN a wrapped event is rendered with non-empty content
- WHEN the user taps/clicks the label header
- THEN the content body expands to show the full markdown content

### AC3: Content defaults to collapsed
- GIVEN a wrapped event is rendered
- WHEN the component first mounts
- THEN the content body is collapsed (only label visible)

### AC4: No regression on other event types
- GIVEN existing event types (switch, message, limit-reached)
- WHEN rendered in MessageView
- THEN they continue to render exactly as before
