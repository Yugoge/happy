## Goal

Implement five Codex subagent lifecycle tool renderers (functions.spawn_agent, functions.send_input, functions.wait_agent, functions.resume_agent, functions.close_agent) sharing ONE new CodexSubagentView.tsx component and five new knownTools.tsx entries, mirroring the Agent/Task tool visibility pattern. This closes §5.13 (Codex subagent tasks not displayed).

**Critical protocol finding (OBJ-1 resolution)**: The Codex codexAppServerClient.ts does NOT emit spawn_agent_begin, send_input_begin, etc. events. These subagent verbs are Codex model-level tool calls whose invocations are not surfaced through the current event stream. The EventMsg type is { type: string } and Record<string, unknown> with no discriminated union for subagent verbs. Confirmed by reading codexAppServerClient.ts lines 280-364 exhaustively: only commandExecution, fileChange, and agentMessage item types are mapped to events. The five subagent verbs are protocol-blocked in the current Codex integration.

**Strategy**: Ship the renderer and toolViewRegistry entries dormant (waiting for future protocol support). The sessionProtocolMapper.ts cannot be wired today — there are no events to map. A TODO comment documents the dormant wiring for future activation.

## Context

Phase A (10 web tools) complete. Phase B (local-exec tools) is the concurrent pipeline. Phase C is the subagent delegation group. No functions.spawn_agent, functions.send_input, functions.wait_agent, functions.resume_agent, or functions.close_agent entries exist in knownTools.tsx today. The Codex CLI does not emit protocol events for these tool invocations, so no sessionProtocolMapper.ts branch can be wired until the protocol is extended.

Phase B BA (concurrent pipeline) independently confirmed the same limitation: 7 of 9 Phase B tools are protocol-blocked.
