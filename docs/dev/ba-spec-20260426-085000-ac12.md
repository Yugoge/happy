## Edge Cases & Risks

- E1: `git symbolic-ref refs/remotes/origin/HEAD` requires the synthetic
  repos to actually configure `origin/HEAD`. Setup must run
  `git remote set-head origin -a` (or equivalent) after pushing initial
  commits to the bare remote. Otherwise resolver falls through to the
  `master` fallback and Scenario A would FAIL spuriously.
- E2: `git diff --name-only $DEFAULT_BRANCH...$BRANCH_NAME` returns empty
  when the worktree branch has zero commits ahead. Scenario A's preflight
  intersection will therefore be empty, and overlap won't be detected
  even if the parent has untracked overlap — that's the intended R3b
  behaviour for the zero-ahead case but worth documenting so QA doesn't
  flag a false negative.
- E3: `git worktree list` parsing in Step 4 (`awk '$0 ~ "\\["b"\\]$"'`)
  is sensitive to the worktree path having no trailing whitespace and
  the branch literal not containing regex metachars. Scenarios use plain
  branch names like `worktree-overnight-A` to stay within the safe set.
- E4: The harness running on the real working repo would risk corrupting
  it. Hard requirement: harness writes ONLY under `/tmp/ac12-repo-*` and
  reads merge.md from `/root/.claude/commands/merge.md`. The verifier
  then compares dot-claude `git status` before and after.
- E5: Exit codes — Step 3 exits 2 on overlap, Step 4 exits 0 on clean
  worktree, exits 2 on missing worktree dir. Scenario assertions must
  match exact exit codes.

## Acceptance Criteria

### AC-AC12-1: Scenario A produces target=main

- GIVEN /tmp/ac12-repo-A is a git repo whose `origin/HEAD` points to `main`,
  with a worktree branch `worktree-overnight-A` zero-ahead but dirty
- WHEN run_merge worktree-overnight-A is invoked
- THEN stdout contains the literal line `target=main`

### AC-AC12-2: Scenario A produces an auto-bulk commit on main

- GIVEN AC-AC12-1 setup
- WHEN run_merge completes
- THEN main's tip commit subject equals
  `auto-bulk: end-of-cycle commit for worktree-overnight-A`
- AND `git log --oneline main` shows the auto-bulk commit
- AND the worktree branch's tip is the same commit (merged fast-forward
  is acceptable; merge commit is acceptable; both preserve the auto-bulk)

### AC-AC12-3: Scenario C surfaces "untracked overlap detected:" and exits non-zero

- GIVEN /tmp/ac12-repo-C has parent untracked file at a path the worktree
  branch's diff would touch
- WHEN run_merge worktree-overnight-C is invoked
- THEN stdout contains the literal line `untracked overlap detected:`
- AND exit code is non-zero (specifically 2 per Step 3)
- AND `git log --oneline main` is unchanged from before the run

### AC-AC12-4: No manual git commit across all scenarios

- GIVEN all three scenarios have run
- WHEN the harness audit log is examined
- THEN every `git commit` invocation outside the run_merge function is
  tagged `setup-only` and listed in an explicit allow-list
- AND no `git commit` invocations exist that aren't in the allow-list or
  inside run_merge

### AC-AC12-5: No manual mv in the harness

- GIVEN the harness scripts
- WHEN grep -n '^[[:space:]]*mv ' is run on the harness source
- THEN zero matches are returned

### AC-AC12-6: No edit to /merge command source

- GIVEN the snapshot of `cd /root/.claude && git status --porcelain
  -- commands/merge.md` taken before harness run
- WHEN the harness has finished and the same command is run again
- THEN the two outputs are byte-identical
- AND `git diff -- commands/merge.md` is empty

### AC-AC12-B: Scenario B produces target=master (master-default repo)

- GIVEN /tmp/ac12-repo-B's `origin/HEAD` points to `master`
- WHEN run_merge worktree-overnight-B is invoked
- THEN stdout contains the literal line `target=master`

## Technical Hints

### Affected files (to CREATE under /dev/shm/dev-workspace/happy-dev)

- `tests/ac12/run_merge.sh` — extracts the four bash blocks from merge.md
  into a callable function. NOT a copy of merge.md; the dev should `sed`
  or otherwise extract the exact line ranges so drift between merge.md
  and the harness is impossible.
- `tests/ac12/setup_scenario_a.sh` — builds /tmp/ac12-repo-A
- `tests/ac12/setup_scenario_b.sh` — builds /tmp/ac12-repo-B
  (master-default)
- `tests/ac12/setup_scenario_c.sh` — builds /tmp/ac12-repo-C with
  parent untracked overlap
- `tests/ac12/run_all.sh` — wipes /tmp/ac12-repo-*, runs all three
  setups, runs run_merge for each, captures everything
- `tests/ac12/verify.sh` — reads the captures and emits
  `tests/ac12/ac12-report.json`
- `tests/ac12/captures/` — directory of stdout/stderr/exit-code files
  per scenario
- `tests/ac12/ac12-report.json` — final machine-readable verdict

### Constraints

- All scripts use `set -euo pipefail` and `IFS=$'\n\t'`.
- All scripts MUST be executable (`chmod +x`) but not call any tool
  outside the standard POSIX + git toolchain; in particular no jq
  dependency for emitting the JSON report (use printf-based JSON).
- The setup_scenario_* scripts are the ONLY allow-listed setup-time
  git committers. They populate this allow-list literally:
  - `setup_scenario_a.sh: git commit -m "init A"` (one commit on main
    in the bare-pushed repo)
  - `setup_scenario_b.sh: git commit -m "init B"` (one commit on
    master)
  - `setup_scenario_c.sh: git commit -m "init C"` plus one worktree-side
    commit creating the file the parent will then untrack-overlap on
- run_merge.sh MUST source the bash blocks; it MUST NOT inline a
  paraphrase. The dev's job is mechanical extraction, not interpretation.

### Validation approach

QA will:
1. Run `tests/ac12/run_all.sh` and `tests/ac12/verify.sh`
2. Read `tests/ac12/ac12-report.json` and verify all seven booleans are
   `true` (six AC12 conditions plus the master-default scenario).
3. Independently verify AC-AC12-6 by running
   `cd /root/.claude && git status -- commands/merge.md` before and after
   the harness invocation.
4. Spot-check AC-AC12-2 by reading
   `tests/ac12/captures/A-stdout.log` for the literal commit subject
   and `tests/ac12/captures/A-post-git-log.log` for the auto-bulk commit
   on main.

## Standards to Enforce

- No hardcoded values (DEFAULT_BRANCH derived per merge.md's resolver)
- Bash scripts: `set -euo pipefail`, `IFS=$'\n\t'`
- Integer step numbering (Step 1..N)
- Meaningful naming (run_merge, setup_scenario_a, verify, ac12-report.json)
- Reference merge.md by absolute path with line ranges in extraction
