## Goal

Land three independent hook-layer fixes in the nested `.claude` repo at `/dev/shm/dev-workspace/dot-claude` (working tree at `/root/.claude/`):
1. Block all subagent direct writes to `cp-state-*.json` so `spec-check.py` is the only legal writer (Bug 1).
2. Make the SubagentStop hook actually finalize orphaned cp-state slots that survived a misbehaving subagent's exit (Bug 2).
3. Eliminate the path where a fresh `dev` subagent inherits a stale `ba` cp-state's `agent_id` and gets misclassified as `ba` by the tool-policy resolver (Bug 3).

## Context

Three independent bugs were diagnosed in this session via codex (full forensic at `/var/tmp/codex-outputs/codex-output-2821653-1778158499.txt` and validation at `/var/tmp/codex-outputs/codex-output-4128518-1778164293.txt`).

**Bug 1 forensic**: `/dev/shm/dev-workspace/happy-dev/.claude/specs/spec-20260506-203755/cp-state-ba.json` is the only cp-state in the repo containing per-checkpoint `evidence` strings. `spec-check.py:_apply_mark_transition` (lines 402-413) only writes `state` / `waived_reason` / `updated_at`; an `evidence` field can only appear via direct `Edit` / `Write` / `Bash` heredoc on the cp-state file, not through `spec-check.py`. Today this is policy-allowed: `tool-policy.v1.json` grants every cp-state-owning role direct write access to its own slot (e.g. `ba.allowed_write_path_prefixes` contains `*/.claude/specs/*/cp-state-ba.json`). Direct write bypasses `_write_payload_with_auto_checkout` (lines 374-379), so `is_running:true` persists past BA exit; downstream agents inherit a poisoned cp-state.

**Bug 2 forensic**: same forensic file currently shows `agent_id: None`, `is_running: false`, `checked_out_at: 2026-05-07T14:27:54Z`. Stop hook DID eventually finalize. But the `agent_id` field was cleared (the only way to reach `agent_id: None` is `check-out` on line 538 of spec-check.py OR a direct Edit clobber). The dispatch chain in `subagentstop-cp-enforce.py:_dispatch` (lines 304-312) finds slots ONLY by exact `agent_id` match (`_match_agent` line 61, `_find_all_slots_for_agent` filter at line 99). A slot whose `agent_id` was clobbered to `null` while `is_running:true` becomes invisible to the stop event of any subagent, leaving an orphan that no Stop hook can finalize via the normal path.

**Bug 3 forensic**: `agent_resolver._scan_cp_state_files` (line 77-94) returns `matches[0].get("agent_type")` as a legacy fallback when no slot has `is_running=true`. If a `dev` subagent's `agent_id` matches a stale, inactive `ba` cp-state slot, the resolver returns `"ba"` and tool-policy denies dev's writes with `{"role":"ba",...}`. Codex confirmed this path at `agent_resolver.py:91-94` (preference for active matches, fallback to first inactive match). The dev-registry `agent-index.json` lookup at line 97-103 is checked SECOND, so a stale cp-state shadows a fresh agent-index entry.

These three bugs compose: Bug 1 produces poisoned cp-state, Bug 2 lets the poison survive across Stop, Bug 3 lets the poisoned cp-state re-classify the next subagent that happens to get a colliding `agent_id`.

AND `python3 /root/.claude/scripts/spec-check.py mark|waive|check-in|check-out ...` invocations via Bash MUST continue to succeed (they have no shell write targets, so the policy hook authorizes only the Bash tool itself; the script's internal `fcntl` writes are not visible to the policy layer — verified at `pretool-tool-policy.py:64-66` per codex)

### AC-2: Stop hook finalizes orphaned cp-state slots

GIVEN a SubagentStop event with `agent_id=A`
AND a cp-state slot exists with `is_running:true` AND no pending checkpoints (or all timed out)
AND the slot's `agent_id` field is `null` OR does not equal `A` (orphaned because `agent_id` was clobbered, OR a different subagent's slot was left running)
WHEN `subagentstop-cp-enforce.py` runs
THEN the hook MUST scan ALL cp-state files under `<project>/.claude/specs/*/cp-state-*.json` and finalize (`is_running=false`, stamp `checked_out_at=now`) any slot that meets ALL of:
  - `is_running:true`
  - no pending checkpoints (M11 invariant: pending blocks are still pending; this AC only finalizes terminal-or-empty checkpoint sets)
  - `agent_id` is `null` (orphaned) OR the recorded `pid` (if present) is not alive
AND the existing `_dispatch` flow (lines 304-312) MUST be unchanged for the normal case (active slot owned by stopping `agent_id`).
AND the orphan-finalization path MUST emit a stderr line `"SUBAGENT STOP orphan-finalize: <cp_file> (was is_running=true, agent_id=<id>, pid=<pid|none>)"` so out-of-band finalizations are visible.

**Implementation requirements (binding for dev)**:
1. Add a new function `_finalize_orphans()` to `subagentstop-cp-enforce.py` that:
   - Iterates `_cp_root().glob("*/cp-state-*.json")` (skipping `.lock` files via the `.json` suffix already used at line 74).
   - For each file: parse, check `is_running:true` AND no pending checkpoints (`_has_pending(payload) is False`) AND (`payload.get("agent_id") is None` OR (`payload.get("pid")` exists AND `_is_pid_alive(payload["pid"]) is False`)).
   - Call `_clean_exit(payload)` and `_write_payload(cp_file, payload)`.
   - Emit stderr log line.
2. Call `_finalize_orphans()` from `main()` after `_dispatch(agent_id, data)` returns 0 (clean exit). Do NOT call when `_dispatch` returns 2 (pending block) — pending enforcement is non-negotiable per M11.
3. Verifiable test:

   - Trigger SubagentStop with any `agent_id`.

   - Stderr MUST contain the orphan-finalize log line.
