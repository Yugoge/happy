# BA Specification: §5.8 Markdown Table Horizontal Scroll — Port from Happy Prod

**Request ID**: dev-20260424-143000-7
**Created**: 2026-04-24T14:30:00Z

## Goal

Port the markdown table horizontal-scroll fix from happy production (commit `a59b3795`) to this worktree. The fix prevents wide tables from bleeding outside the message card boundary by (a) constraining the web table wrapper with `overflowX: auto` and a viewport-relative `maxWidth`, and (b) adding `minWidth: 0` + `overflow: hidden` to the flex container ancestors in `MessageView.tsx`.

## Context

In happy-dev, markdown messages containing wide tables overflow the card's right edge. This exact problem was solved in happy production on 2026-03-25 via commit `a59b3795` ("fix: table font mismatch and mobile overflow on web"). The production fix touched two files: `MarkdownView.tsx` and `MessageView.tsx`. The MarkdownView.tsx fix is already present in the dev worktree; only the `MessageView.tsx` ancestor-container constraints are missing.

## Edge Cases & Risks

- `minWidth: 0` on `messageContent` can affect all flex children of the message row if any other child relies on content-based sizing. Prod has shipped this for ~30 days with no regression — risk is low.
- `overflow: 'hidden'` on `agentMessageContainer` could clip absolutely-positioned children (tooltips, copy-button overlays). Code review of `MessageView.tsx` shows no absolutely-positioned children in this container, so risk is low.
- The `MarkdownView.tsx` dev version has additional features not in prod (`RenderImageBlock`, `CodeBlockDownloadButton`, `useTableStyles` hook, `onLinkPress` prop). None of these interact with the two MessageView style properties being added — no conflict risk.

## Acceptance Criteria

### AC1: Wide table stays inside card
- GIVEN a conversation message containing a markdown table with 3+ wide columns
- WHEN the user views the message on a 1440x900 desktop browser
- THEN no table content is clipped or bleeds outside the card's right edge; the table is horizontally scrollable within the card

### AC2: Mobile layout intact
- GIVEN the same wide-table message
- WHEN the viewport is resized to 390x844 (iPhone 14)
- THEN the card occupies full content width, the table scrolls horizontally within it, and no card content overflows the screen edge

### AC3: No regression on normal messages
- GIVEN a conversation with short text messages and single-column tables
- WHEN the user views those messages after the fix
- THEN the layout is visually identical to pre-fix state
