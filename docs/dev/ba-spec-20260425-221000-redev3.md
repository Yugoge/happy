## Edge Cases & Risks

- **E1. Edit on a file that does not exist on disk yet**: `Path(file_path).read_text()` raises. Hook treats as "no pre-state" → measure post-state against hard thresholds. (Falls under M3.)
- **E2. Edit whose `old_string` does not match (current code returns `current` unchanged at line 74)**: post-state = pre-state, so trivially no metric worsens — but this is an internal anomaly, not a real edit. Behavior should be unchanged from today (the existing code returns the unchanged `current` and proceeds to check it; if it passes, it passes; if it doesn't, it rejects). Document but do not change.
- **E3. Function-by-function delta**: the hook's TS/Python detectors return a list of violation strings. To compare pre vs post per-function, Dev must produce a structured representation, e.g., a list of `(function_name, line_count)` tuples. Helpers must return structured data; the existing string-builder logic is then layered on top.
- **E4. Function rename**: if a function is renamed mid-edit, name-based matching might lose track. Use a robust fallback: if a same-named function does not exist in pre-state, treat it as a NEW function and require ≤ 30 lines. (Bias: be strict on names that didn't exist before.)
- **E5. The hook running on itself**: if the modified hook violates its own thresholds, the next Edit on the hook will reject. Dev MUST design helpers to keep every function ≤ 30 lines.
- **E6. Pre-edit Read failure on Edit (file readable but encoding broken)**: existing code returns `('', file_path)` at line 65. Treat as "no pre-state" (consistent with E1).
- **E7. claude-config-guard interaction**: editing `/root/.claude/hooks/*.py` requires the `.hook-refactor-allow` sentinel. The sentinel currently exists (per orchestrator prompt). Dev must verify `ls /root/.claude/.hook-refactor-allow` before starting; if missing, ABORT with a REQUEST to the user.
- **E8. Two violations in the same file, one shrinks and one grows**: e.g., function A goes 35→34 lines (improvement) but function B goes 20→32 lines (new violation). Per-metric rule: function B's growth blocks. Confirm test coverage.

### Concrete fix design (Option α)

The current `main()` function at lines 209-247 measures POST-edit `content` only. The fix introduces a parallel measurement of PRE-edit content (read from disk) and a delta comparator.

#### New helper functions

Add three new helpers (each ≤ 30 lines) BEFORE `main()`:

1. **`get_pre_content(data: dict) -> str`** (≤ 10 lines)
   - For `Edit`: read `tool_input['file_path']` from disk; on failure return `''`.
   - For `Write`: try to read file_path; if it doesn't exist or read fails, return `''` (Write to a non-existent file has no pre-state).

2. **`compute_metrics(content: str, ext: str) -> dict`** (≤ 25 lines)
   - Returns `{"file_lines": int, "functions": dict[str, int], "max_nesting": int}`.
   - `file_lines = len(content.split('\n'))`.
   - `functions`: extract per-function `{name: length}` map by refactoring the existing `check_function_length_*` to also return structured data, OR by adding a sibling `extract_function_lengths_*` that returns the dict (RECOMMENDED — leaves existing functions as-is for backwards compat / minimal diff).
   - `max_nesting`: refactor or duplicate logic from `check_nesting_depth` to return the integer max (existing returns violation strings).

3. **`metric_did_not_worsen(pre: dict, post: dict) -> tuple[bool, str]`** (≤ 25 lines)
   - **Symmetric `post <= pre` semantics across ALL three metrics (QA OBJ-3).** No `max(pre, MAX_*)` permissiveness — this was an asymmetry in the previous BA draft and is corrected here.
   - Compare `post['file_lines'] <= pre['file_lines']`. If False, return `(False, f"file: {pre} → {post} grew")`.
   - **Per-function comparison (QA OBJ-2 — required by AC-M6-7)**: iterate every function name appearing in either `pre['functions']` OR `post['functions']`:
     - If function name exists in BOTH: require `post[name] <= pre[name]`. If False, return `(False, f"Function '{name}' grew from {pre[name]} to {post[name]} lines")`.
     - If function name exists ONLY in post (new function): require `post[name] <= MAX_FUNC_LINES`. If False, return `(False, f"New function '{name}' is {post[name]} lines (max {MAX_FUNC_LINES})")`.
     - If function name exists ONLY in pre (function was removed): no constraint, skip.
   - **Important**: this MUST be done per-function-name. An aggregate sum comparison would let A=50→40 and B=40→50 pass (sum unchanged at 90); the per-function check correctly catches B's growth.
   - Compare `post['max_nesting'] <= pre['max_nesting']` (symmetric, post ≤ pre). If False, return `(False, f"nesting: {pre} → {post} grew")`.
   - If all checks pass, return `(True, '')`.
   - Caller uses the second element of the tuple to populate stderr when `worsened` so AC-M6-7 can name the offending function.

#### Modified main()

Pseudocode (target ≤ 30 lines):

```python
def main() -> None:
    data = json.load(sys.stdin)
    tool_name = data.get('tool_name', '')
    if tool_name not in ('Write', 'Edit'):
        sys.exit(0)
    post_content, file_path = get_final_content(data)
    if not post_content or not file_path or is_exempt(file_path):
        sys.exit(0)
    ext = Path(file_path).suffix
    post_violations = collect_violations(post_content, ext)
    if not post_violations:
        sys.exit(0)
    # Post-state has violations. Check if pre-state was already non-compliant
    # AND this edit didn't make any metric worse.
    pre_content = get_pre_content(data)
    if pre_content:
        pre_metrics = compute_metrics(pre_content, ext)
        post_metrics = compute_metrics(post_content, ext)
        if metric_did_not_worsen(pre_metrics, post_metrics):
            print(f'QUALITY GATE [grandfathered] — {file_path}: '
                  f'pre-existing violations preserved, no metric worsened.',
                  file=sys.stderr)
            sys.exit(0)
    # Either no pre-state (new file / new content) OR a metric worsened.
    emit_violations(file_path, post_violations)
    sys.exit(2)
```

To stay within the function-length budget, extract `collect_violations` and `emit_violations` as separate helpers (each ≤ 15 lines).
