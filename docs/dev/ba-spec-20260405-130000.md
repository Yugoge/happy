# BA Specification: Fix File/Image Upload in happy-dev

**Request ID**: dev-20260405-130000
**Created**: 2026-04-05T13:00:00Z

## Goal

Restore file and image upload functionality in happy-dev which broke after the upstream merge (commit `925f5960`). The root cause is a missing export in `happy-wire/src/index.ts` -- the `messageMeta` module export was overwritten by the upstream `voice` export during the merge.

## Context

The upstream merge (153 commits, Expo SDK 55 + new session composer) replaced the local `happy-wire/src/index.ts` line `export * from './messageMeta'` with `export * from './voice'`. The upstream repo does not have the attachment feature, so their index only exports messages, legacyProtocol, sessionProtocol, and voice. Our local `messageMeta.ts` file (containing `AttachmentMetadata` and `MessageMeta` types) still exists but is no longer exported from the package entry point.

This causes 5 TypeScript errors across the app where `AttachmentMetadata` is imported from `@slopus/happy-wire`. The server-side upload endpoint works correctly (tested via curl). The issue is purely a build/type export problem on the client side.

## Requirements (MoSCoW)

### Must Have
- Add `export * from './messageMeta'` back to `happy-wire/src/index.ts` (alongside the existing voice export)
- Verify `yarn typecheck` passes for happy-app (at least the 5 AttachmentMetadata errors must be resolved)
- Rebuild happy-web-dev Docker image and verify upload works in browser

### Should Have
- Fix the other typecheck errors found during investigation:
  - `applySessionUsage` missing from StorageState (sync.ts:2272)
  - `sidebarCollapsed` not in local settings type (SidebarNavigator.tsx:15)
  - `MessageAttachments.tsx` AttachmentMetadata import (same root cause)

### Could Have
- Re-add paste and drag-and-drop file upload handlers that were removed by upstream merge from AgentInput.tsx

### Won't Have (Non-Goals)
- Changes to happy-server upload logic (already working)
- Changes to happy-cli file download logic
- Production deployment

## Edge Cases & Risks

- The `voice` export was added by upstream and must be KEPT -- the fix is to add messageMeta as an additional line, not replace voice
- The Expo web build may succeed even with TS errors (it uses Babel, not tsc), but runtime behavior is undefined when types don't resolve
- After fixing the export, the happy-wire package must be rebuilt before happy-app can consume it

## Acceptance Criteria

### AC1: AttachmentMetadata export restored
- GIVEN happy-wire/src/index.ts is missing messageMeta export
- WHEN `export * from './messageMeta'` is added to index.ts
- THEN `import { AttachmentMetadata } from '@slopus/happy-wire'` resolves in all consuming files

### AC2: TypeScript compilation
- GIVEN the fix is applied
- WHEN `yarn workspace happy-app typecheck` is run
- THEN the 5 AttachmentMetadata errors are gone

### AC3: Upload works end-to-end
- GIVEN happy-web-dev is rebuilt with the fix
- WHEN a user clicks the attach button and selects a file
- THEN the file uploads successfully and appears in the attachment strip
