## Summary

Three race conditions in the daemon auto-upgrade handoff path were fixed:

- F1: TOCTOU split-target kill in `stopDaemon()` — single-snapshot pattern + self-kill guard
- F2: Lock double-unlink race — `clearDaemonState()` no longer touches lock file; `releaseDaemonLock()` called before `cleanupDaemonState()` at both cleanup sites
- F3: Exit code semantics — `process.exit(0)` moved inside try block; catch block now calls `process.exit(1)` with FATAL log

Additionally, the hook URL gap (`pretool-bash-safety.sh`) was addressed, and three pending manual user actions were documented.

## Changes

### F1 — TOCTOU race in stopDaemon() (controlClient.ts)

Reads `daemon.state.json` exactly once (single-snapshot) into `state`. Self-kill guard: if `state.pid === process.pid`, returns without killing. Liveness check: `process.kill(state.pid, 0)` — returns early if process is already dead. HTTP stop inlines `fetch` to `state.httpPort` directly (no helper that re-reads state). SIGKILL uses `state.pid` from same snapshot.

### F2 — Lock file double-unlink (persistence.ts + run.ts)

`clearDaemonState()` lock file deletion block removed — function now deletes only `daemonStateFile`. `releaseDaemonLock(daemonLockHandle)` called BEFORE `cleanupDaemonState()` at both cleanup sites: heartbeat handoff (`run.ts:765-766`) and `cleanupAndShutdown` (`run.ts:833-834`). `releaseDaemonLock()` already handles ENOENT via `catch {}` — confirmed no change needed.

### F3 — Exit code semantics (run.ts)

`process.exit(0)` moved inside try block immediately after `spawnHappyCLI()` succeeds. Catch block now calls `process.exit(1)` with FATAL log `[DAEMON RUN][FATAL] Failed to spawn new daemon — all subsystems already torn down; exiting with code 1`. Enables systemd `Restart=on-failure` to respawn on spawn failure.

### Hook fix (~/.claude/hooks/pretool-bash-safety.sh)

Added block preventing production API URL in dev docker builds. Fixed error message to show correct dev API URL.
