# BA Specification: Bug #62 -- Session Title Not Updating in Sidebar/Header After MCP change_title

**Request ID**: dev-20260403-210447-6
**Created**: 2026-04-03T21:04:47Z

## Goal

Fix the `change_title` MCP tool so that when Claude sets a session title via this tool, the title updates in both the sidebar session list and the session header, not just as a service message in the chat.

## Context

The Happy MCP server exposes a `change_title` tool that Claude can invoke to set a session title. The tool works end-to-end in a narrow sense: a service message appears in the chat saying "Title changed to X". However, the actual session metadata (which drives the sidebar and header title) does not update -- both sessions continue showing the working directory basename (e.g., "root") instead of the MCP-set title.

The title display chain involves:
1. MCP tool handler sends `{ type: 'summary', summary: title, leafUuid: uuid }` via `sendClaudeSessionMessage`
2. `sendClaudeSessionMessage` calls `updateMetadata` to set `metadata.summary` on the server
3. Server broadcasts `update-session` with encrypted metadata to all interested clients
4. App receives `update-session`, decrypts metadata, calls `applySessions`
5. `getSessionName(session)` checks `session.metadata?.summary?.text` and returns it if present

The service message visible in chat comes from a SEPARATE path: `messageToEvent.ts` detects the `mcp__happy__change_title` tool-call content block and converts it to a display-only service event.

## Requirements (MoSCoW)

### Must Have
- When `change_title` MCP tool is invoked, `metadata.summary` must be persisted to the server and propagated to the app
- Sidebar session list must display the MCP-set title via `getSessionName()` within seconds of the tool call
- Session header (in `SessionView.tsx`) must display the MCP-set title within seconds of the tool call
- The `updateMetadata` call must not silently swallow errors -- failures should be logged and the MCP tool should return failure

### Should Have
- Debug logging at each stage of the metadata update chain (CLI `updateMetadata` call, server `update-metadata` handler, app `update-session` handler)
- The MCP tool handler should await `updateMetadata` completion before returning success

### Could Have
- Optimistic title update in the app when the tool-call message is received (before the metadata update arrives)

### Won't Have (Non-Goals)
- Changes to the `getSessionName()` function itself (it correctly prioritizes `metadata.summary`)
- Changes to the service message display in chat (this already works)
- Smart title generation or auto-titling (separate feature)

## Edge Cases & Risks

- **Version mismatch**: If another metadata update is in flight when `change_title` fires, the optimistic concurrency in `updateMetadata` may fail. The backoff retry should handle this, but if it exhausts retries, the title is lost.
- **Socket disconnect**: If the CLI WebSocket is temporarily disconnected when `updateMetadata` runs, the `emitWithAck` may timeout. The `.catch()` swallows the error.
- **Encryption mismatch**: If `decryptMetadata` fails on the app side (e.g., key rotation), the old metadata is kept silently.
- **FlatList optimization**: React Native `FlatList` may not re-render `SessionItem` if it doesn't detect a prop change. Currently there is no `extraData` prop on the FlatList.

## Acceptance Criteria

### AC1: Title propagates to sidebar
- GIVEN a session is active and visible in the sidebar
- WHEN Claude invokes `mcp__happy__change_title` with title "My New Title"
- THEN the sidebar session item displays "My New Title" instead of the directory basename within 5 seconds

### AC2: Title propagates to header
- GIVEN a session is open in the session view
- WHEN Claude invokes `mcp__happy__change_title` with title "My New Title"
- THEN the session header displays "My New Title" instead of the directory basename within 5 seconds

### AC3: MCP tool reports failure on metadata update error
- GIVEN the metadata update fails (e.g., socket disconnected)
- WHEN Claude invokes `mcp__happy__change_title`
- THEN the MCP tool returns `isError: true` with an error message

### AC4: Title persists across app reload
- GIVEN the title was successfully changed via MCP
- WHEN the app is reloaded (page refresh or re-open)
- THEN the title still displays the MCP-set value

## Technical Hints

- **Root cause investigation**: The `updateMetadata` in `startHappyServer.ts:66-74` is fire-and-forget (`.catch()` swallows errors). The handler returns `{ success: true }` before the metadata actually persists.
- **Affected files**:
  - `packages/happy-cli/src/claude/utils/startHappyServer.ts` -- MCP handler must await `updateMetadata`
  - `packages/happy-cli/src/api/apiSession.ts:414-424` -- `updateMetadata` call and error handling
  - `packages/happy-app/sources/sync/sync.ts:1900-1934` -- `update-session` handler
  - `packages/happy-app/sources/components/SessionsList.tsx` -- FlatList may need `extraData`
- **Related patterns**: `updateAgentState` in the same file follows a similar pattern and works correctly
- **Constraints**: All metadata is E2E encrypted; changes must go through the `updateMetadata` path, not direct server writes
