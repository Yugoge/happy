## Edge Cases & Risks

- **Edge case 1**: Bash invocations that are NOT git commands. The hook already handles this via `_looks_like_git_*` predicates returning False; `_evaluate_command` is a no-op for non-git commands. Fix preserves this.
- **Edge case 2**: Bash invocations that contain `git commit` in a comment or string literal. The hook uses regex `(?:^|[\s;&|()`])git\s+commit\b` which is intentionally loose. This is the same regex Cycle 2 shipped — risk profile unchanged.
- **Edge case 3**: `git commit --amend` on the user's own terminal. NOT routed through Bash tool — unaffected.
- **Edge case 4**: The b5d447e shape exact replay (`git commit -am "chore(claude): sync uncommitted ..."`). With α: caught by `_evaluate_commit` because message doesn't match `auto-bulk: end-of-cycle commit for `. Exit 2.
- **Risk 1**: Agent legitimately needs to commit during a /redev cycle. Resolution: documented in Section 6 Gap D — user commits from terminal. The /redev work itself is committed by /merge's auto-bulk bridge, which IS whitelisted.
- **Risk 2**: Some unmaintained slash-command attempts a non-blessed `git commit` and is now blocked. Resolution: the spec (5.2.4) explicitly requires this behavior. Any slash-command that needs to commit must use the blessed-bridge pattern. This is a feature, not a bug.
