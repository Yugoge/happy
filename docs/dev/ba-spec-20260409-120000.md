# BA Specification: Subagent Sidechain Envelope Visibility

**Request ID**: dev-20260409-120000
**Created**: 2026-04-09T12:00:00Z

## Goal

Make subagent (Agent/Task tool) internal operations visible in the sidebar by sending them as `sidechain` envelopes through the wire protocol, so the App can link child messages to their parent tool call and render the full subagent conversation.

## Context

Currently, clicking an Agent/Task tool card in the sidebar shows only the prompt and final result. The subagent's internal operations (tool calls, text, thinking) are missing. The root cause spans 5 layers: the wire protocol lacks a `sidechain` event type, the CLI mapper sends sidechain root messages as plain `text`, the App normalizer does not produce `sidechain` content, no synthetic sidechain root is created for Agent tools (only Task), and the App tracer cannot link children because the subagent CUID2 is not registered in its UUID map.

## Requirements (MoSCoW)

### Must Have
- Add `sidechain` event type to `sessionProtocol.ts` wire protocol schema
- CLI mapper emits `sidechain` event (not `text`) for sidechain root user messages
- CLI launcher creates synthetic sidechain root for both Agent and Task tools (currently Task only)
- App normalizer handles `sidechain` event and produces `sidechain` content type
- App tracer registers subagent CUID2 from `tool-call-start` input so children inherit `sidechainId`

### Should Have
- All existing sidechain behavior for Task tool remains unchanged (no regression)

### Could Have
- Improved sidebar rendering of deeply nested subagent chains

### Won't Have (Non-Goals)
- Changes to the sidebar UI component itself (rendering logic)
- Changes to server-side message storage or relay
- New API endpoints

## Edge Cases & Risks

- Agent tools that do not include `sessionSubagent` in their input will not register in the tracer; children will not be linked. This is acceptable as the CUID2 is always present in SDK output.
- Existing persisted messages with `text` type for sidechain roots will not retroactively become `sidechain` type. Only new messages benefit.
- The discriminated union in Zod requires `t` to be unique across all event schemas; `sidechain` must not conflict with existing values.

## Acceptance Criteria

### AC1: Wire protocol accepts sidechain events
- GIVEN a session envelope with `ev.t === 'sidechain'` and `ev.prompt` as a string
- WHEN parsed through `sessionEventSchema`
- THEN it validates successfully

### AC2: CLI emits sidechain event for subagent root
- GIVEN a Claude SDK message with `isSidechain === true` and role `user`
- WHEN the sessionProtocolMapper processes it
- THEN it emits an envelope with `{ t: 'sidechain', prompt: <text> }` instead of `{ t: 'text', text: <text> }`

### AC3: Agent tool gets synthetic sidechain root
- GIVEN an assistant message containing a `tool_use` block with `name === 'Agent'`
- WHEN the claudeRemoteLauncher processes it
- THEN it creates a synthetic sidechain user message (same as it does for Task)

### AC4: App normalizer produces sidechain content
- GIVEN a session envelope with `ev.t === 'sidechain'`
- WHEN `normalizeSessionEnvelope()` processes it
- THEN it returns a NormalizedMessage with `content[0].type === 'sidechain'` and `isSidechain === true`

### AC5: App tracer links children to parent
- GIVEN a tool-call-start envelope with `input.sessionSubagent` set to a CUID2
- WHEN the reducerTracer processes it
- THEN it registers the CUID2 in `state.uuidToSidechainId` mapping to the tool-call message ID
- AND subsequent child messages with `parentUUID === CUID2` inherit the correct `sidechainId`

### AC6: End-to-end sidebar visibility
- GIVEN a session where an Agent tool is invoked
- WHEN the user clicks the Agent tool card in the sidebar
- THEN the sidebar shows the subagent's full conversation (tool calls, text, thinking)
- AND this works on both desktop and mobile (390x844) viewports
