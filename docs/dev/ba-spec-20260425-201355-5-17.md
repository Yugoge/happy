## Goal

Two surgical visual fixes to `packages/happy-app/sources/components/markdown/MarkdownView.tsx`:

1. **H1 (level=1) typography**: enlarge `header1` so its font-size is strictly greater than body text (currently 16px = body 16px, only fontWeight 900 differentiates), and likewise raise `header3` (currently 16px). Restore the conventional H1 > H2 > H3 > body size cascade.
2. **List rendering leak**: replace the literal `"- "` / `"{n}. "` prefix that `RenderListBlock` and `RenderNumberedListBlock` paste into the `<Text>` content with a real visual list marker (bullet glyph + leading indent for unordered, properly aligned number for ordered) so that DOM textContent no longer reads as raw markdown source. On web, additionally emit semantic `<ul>`/`<ol>`/`<li>` so the rendering matches user expectation of a list.

Both fixes target `MarkdownView.tsx`. The parser is already detecting headings and lists correctly — verified live.

## Edge Cases & Risks

- **Pure-text platforms (iOS/Android React Native)**: `accessibilityRole='list'` on RN does NOT generate semantic HTML — only on web. The fix MUST work cross-platform: marker as separate `<View>`/`<Text>` is the lowest common denominator. Web-semantic emission is purely additive.
- **Long-press text selection**: `MarkdownView.tsx:103-152` has a long-press copy-text gesture that depends on `selectable={true}` Text nodes. Splitting the marker into a separate node MUST keep the item-content node `selectable={selectable}` so users can still long-press and select the list item content (excluding the marker is acceptable).
- **Nested list depth**: The current `paddingLeft: item.depth * 16` indent at `MarkdownView.tsx:176` is correct; preserve it. The marker character `•` should sit AT `paddingLeft` and the content text should sit further right (e.g., flexDirection row with marker as fixed-width column).
- **Numbered list right-alignment**: `"1. "` and `"10. "` are different widths. If implementing aligned numbers, fix-width the marker column to `2ch` (or use CSS counter on web) to prevent ragged text edges.
- **Header semantic on web**: `accessibilityRole='header'` + `aria-level` produces a `<div role="heading" aria-level="1">` (NOT a real `<h1>`). True `<h1>` requires emitting platform-specific JSX; this is web-only and complex. AC R8 is "should have", not "must" — visual fix is sufficient for R1-R4.
- **§5.16 LaTeX co-residence**: §5.16 is a separate parallel pipeline. This BA does not touch LaTeX renderers; safe.
- **Quality gate**: `MarkdownView.tsx` is in `EXEMPT_PATHS` (added 2026-04-24 cycle). Edits are unblocked.
