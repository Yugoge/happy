## Edge Cases & Risks

- **Race**: the watcher might enumerate 019dd077 between snapshot and recovery if its `scan_running_sessions` (Source 1/2/3 union) ever picks it up. The script's per-tid spawn lock (`/tmp/happy-codex-spawn-019dd077-…lock`) prevents double-spawn; `recover <uuid>` checks `scan_running_sessions` first (line 1170-1176) and skips if already running.
- **Stale auth**: dev daemon's `access.key` (mtime Mar 29) is older than the rollout. This is fine — the access.key authorizes the dev daemon as a happy-server client; it doesn't gate codex thread access. Codex auth lives in `/root/.codex/auth.json` (separate).
- **Rollout payload.cwd = `/root/.codex`**: `recover_session` Source 4 (line 1239-1246) reads payload.cwd from the rollout and uses it as the spawn directory. `/root/.codex` exists, so the precondition (`[ -d "$work_dir" ]` at line 1254) passes. The codex CLI then runs in `/root/.codex` — slightly unusual cwd but harmless for resume.
- **New session-tag**: the recovered session appears as a NEW card in the dev sidebar (not the old 019dd077 card from before kill — the old card is now offline/gone). The user must understand: the rollout history is preserved; the happy-server session record is new. The user-sim's mental model "see my session in the sidebar, click it, and pick up the conversation" is satisfied if the new card shows the resumed conversation.
- **Subagent tids on the watcher's radar**: the subagent filter at `_validate_codex_rollout:779-783` ensures even if a subagent's rollout had a live fd, it would be skipped. Subagents will NOT be auto-restored. Aligned with user-sim.
- **Hook-blocked recovery script**: BA cannot test the recovery command in this session (`pretool-bash-safety.sh` blocks `happy-session-recovery.sh`). The plan therefore relies on read-only verification of the script's source code (lines 1115-1310 reviewed) to predict behavior. User runs the actual command.
- **Path C → maybe Path B fallback**: if the user runs the recovery and the new card shows empty history, that's user-sim Scenario B (silent partial failure). Diagnostic in AC4.
