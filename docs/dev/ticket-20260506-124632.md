# Ticket 20260506-124632: Inline rendering for image-like tool outputs

## Goal

Fix the observed Happy dev conversation rendering failures where image-like tool outputs are shown only as tool-call metadata or filesystem paths instead of visible inline images.

## Requirements

1. Playwright screenshot tool results must show the actual screenshot image inline in the conversation view.
2. AI-generated image outputs must show the generated image inline in the conversation view.
3. Path-only image view outputs must either render an inline image when a readable image artifact is available or show an explicit unavailable state.
4. Existing rendering that already worked must remain intact: title/status text, Terminal cards, and generic non-image tool-call cards.
5. The fix must stay scoped to tool/non-text image output visibility, not a general Happy rendering redesign.

## Evidence

Measured current behavior from user screenshots and conversation:
- Title change renders as a small textual status.
- Terminal output renders as a Terminal card.
- Playwright browser navigation renders as an MCP tool-call card with JSON input/output.
- Playwright screenshot completion renders only as an MCP tool-call card; the image is not visible.
- Image generation completes and writes an image artifact, but no generated image is visible inline.

Expected behavior source:
- User request: `/dev 修复以上渲染问题` after confirming the missing screenshot/generated-image rendering.
- Specialist findings: product-owner, user, ui-specialist, and architect all identify image-like tool outputs as first-class visual artifacts that should render inline.

## Root Cause Hypothesis

The client can render inline images when a tool payload contains a preview URI, but screenshot and generated-image tool results reach the renderer as generic MCP/tool JSON or path-only records. The renderer therefore has no browser-loadable preview value to pass to the existing image presentation path.

## Development Approach

Smallest safe change: preserve existing terminal/status/generic tool rendering, and add canonical image preview extraction/rendering for image-like tool outputs already present in the tool result payload. Prefer reusing the existing image preview/card components and fixture patterns rather than adding a new rendering system.

## Acceptance Criteria

1. A Playwright screenshot result displays an inline image in the Happy conversation view, not only an MCP JSON card.
2. An AI-generated image result displays an inline image in the Happy conversation view, not only a path or completion text.
3. A path-only image-view result is explicitly handled and verified.
4. Existing title/status, Terminal, and generic non-image MCP tool-call rendering remains unchanged.
5. Desktop and mobile widths do not get page-level horizontal overflow from rendered images.
6. Verification uses dev web only and avoids production access or API-created sessions.
