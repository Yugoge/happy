# BA Specification: §5.3 Right detail panel — Bash command overflow (cycle-2 retry)

**Request ID**: dev-20260425-201355-5-3
**Created**: 2026-04-25T20:18:00Z
**Issue ID**: 5.3
**Cycle**: 2 (retry of cycle 1; cycle 5 QA was overturned by audit)

## Goal

The right-side detail popup that opens when the user taps a Bash tool call
must KEEP THE COMMAND TEXT VISIBLY INSIDE THE POPUP. The cycle 1 fix removed
`flexWrap: 'wrap'` + `flex: 1` from `CommandView` so the outer horizontal
`<ScrollView>` could compute a content width — that fix lives. But on the
right detail panel (SidebarBashView), the resulting horizontal scroll
affordance is invisible at rest on web (mobile and desktop), and the
command text appears cut off at the popup boundary with no discoverable
way to read the rest. Fix this **at the SidebarBashView layer**, not
inside CommandView.

## Context

This is a retry for the right-side detail panel only. CommandView itself is
shared by SidebarBashView (the popup), BashViewFull (the in-message detail
view), and CodexBashView. The cycle 1 fix unified all three around
horizontal-scroll. For the popup specifically, horizontal-scroll is the
wrong UX — the popup is narrow (450px desktop / 390px mobile) and a
terminal command line can be 1000+ chars. The user wants the command to be
fully visible in-place, not hidden behind a touch-only scroll affordance.

## Edge Cases & Risks

- **Word-break: break-all on web**: long unbroken paths (e.g.,
  `/root/docs/dev/ba-spec-20260423-080000.md`) need `wordBreak: 'break-all'`
  to wrap mid-token. This is web-only CSS; on iOS/Android RN the equivalent
  is letter-by-letter wrapping — needs verification by QA on at least one
  native platform OR documented as web-only with native fallback to
  break-on-space.
- **Removing the SidebarBashView outer ScrollView**: the existing
  `commandWrapper { flex: 1, minWidth: '100%' }` is sized against the
  ScrollView's content area. If the ScrollView is removed, the wrapper
  needs revisited dimensions (likely just `width: '100%'` is enough).
- **CommandView container `overflow: 'hidden'` (line 37)**: this clips
  internal layout — when wrap mode is enabled, vertical scroll inside
  CommandView (for very long output) might be needed. CommandView already
  supports `maxHeight` prop; wrap mode should still respect it.
- **Theme contrast**: dark mode terminal background is dark; wrapped text
  on multiple lines with `lineHeight: 20` should remain readable — verify
  visually.
- **Long output**: a multi-page stdout in wrap mode could push the popup
  to a very tall height. The popup container should already vertical-scroll;
  verify this still works.
