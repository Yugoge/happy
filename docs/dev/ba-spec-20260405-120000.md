# BA Specification: Edit Tool Full View Missing Standard Detail Sections

**Request ID**: dev-20260405-120000
**Created**: 2026-04-05T12:00:00+08:00

## Goal

Add standard detail sections (Description, Input Parameters, Output/Error) to the Edit tool's full view page so it matches the layout shown by tools that use the generic fallback (e.g., Read), while keeping the existing diff view as additional content.

## Context

When a user clicks on a tool call in the session message list, the app navigates to a detail page rendered by `ToolFullView`. This component checks `toolFullViewRegistry` for a specialized view. If one exists, it renders ONLY that specialized view, completely replacing the generic sections (Description, Input Parameters, Output). The Edit tool has `EditViewFull` registered, which renders only a `ToolDiffView` -- no description, no input parameters, no output/error sections. By contrast, tools without a specialized full view (like Read, Glob, WebFetch) get the generic fallback which shows all standard sections. The user wants Edit to show both the standard sections AND the diff view.

## Requirements (MoSCoW)

### Must Have
- Edit tool full view must display Description section (when `tool.description` exists)
- Edit tool full view must display Input Parameters section (showing `file_path`, `old_string`, `new_string`, `replace_all` as JSON)
- Edit tool full view must display Output section (when `tool.state === 'completed'` and `tool.result` exists)
- Edit tool full view must display Error section (when `tool.state === 'error'`)
- Edit tool full view must retain the existing diff view showing old_string vs new_string changes
- The diff view should appear as a dedicated section alongside (not replacing) the standard sections

### Should Have
- Consistent visual styling with the generic fallback sections (same icons, fonts, spacing)
- Diff section should have its own section header (e.g., "Changes" with an appropriate icon)

### Could Have
- Apply same pattern to MultiEditViewFull (also missing standard sections, only shows diffs)

### Won't Have (Non-Goals)
- Changing the inline (non-full) Edit tool view in the message list
- Changing the generic ToolFullView fallback logic
- Adding new tool types or modifying other tool views

## Edge Cases & Risks

- Edit tool calls where `tool.description` is undefined -- section should simply not render (matches generic behavior)
- Edit tool calls still in `running` state -- should show diff but no output/error section
- Edit tool calls with `state === 'completed'` but `tool.result` is null/empty -- should show "Completed successfully" empty state
- Large diff content combined with large output -- ScrollView must handle both gracefully

## Acceptance Criteria

### AC1: Standard sections visible on Edit detail page
- GIVEN a completed Edit tool call with description, input, and result
- WHEN user navigates to the Edit tool detail page
- THEN Description, Input Parameters, and Output sections are all visible with correct content

### AC2: Diff view still present
- GIVEN an Edit tool call with old_string and new_string
- WHEN user navigates to the Edit tool detail page
- THEN the diff view (red=removed, green=added) is visible as a section alongside the standard sections

### AC3: Error state rendering
- GIVEN an Edit tool call with `state === 'error'`
- WHEN user navigates to the Edit tool detail page
- THEN the Error section is displayed with the error message, and no Output section is shown

### AC4: No description graceful handling
- GIVEN an Edit tool call without a description field
- WHEN user navigates to the Edit tool detail page
- THEN the Description section is omitted, but Input Parameters and Output/Error sections still render
