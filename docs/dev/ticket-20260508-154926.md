## Goal

Close the cycle-6 closure-blocker: §5.3.D bullet 5 (`final_summary` in subagent
lifecycle card) must be populated by REAL Codex protocol data in production
sessions, not fixture-injected synthetic data. This fix replaces hallucinated
field reads with the actual protocol path `agentsStates[receiverThreadId].message`,
forwards `agentsStates` through the bridge, and persists `subagentLifecycles`
state across mapper invocations in the production orchestrator.

## Context

Cycle 6 landed a renderer + state machine for the merged subagent lifecycle
card and closed cycle-6 QA on a fixture. Codex round 1-3 (in cycle-6 close)
sustained: the production protocol does NOT carry `event.message.final_summary`
or `message.finalSummary` — those fields were hallucinated by cycle-6 dev.
Real protocol path (verified against `/tmp/codex-ts-v0.125.0/v2/CollabAgentState.ts`
+ `ThreadItem.ts:90-101`): `event.agentsStates: { [threadId]?: { status, message }}`.

Codex TUI itself (`/tmp/codex-src/codex-rs/tui/src/multi_agents.rs:495-535`,
`status_summary_spans` 559-586) surfaces this `message` on the `wait_agent`
end (when `CollabAgentStatus.Completed` is reached), via `wait_complete_lines`.

Adversarial codex review (this cycle) discovered a THIRD layer that the
orchestrator's two-layer plan missed: `runCodex.ts:286-289, 618-627` does
NOT persist `subagentLifecycles` across mapper invocations. State carries
only 4 fields (`currentTurnId`, `startedSubagents`, `activeSubagents`,
`providerSubagentToSessionSubagent`); `subagentLifecycles?` is optional on
`CodexTurnState` (sessionProtocolMapper.ts:21) so `getSubagentLifecycles(state)`
returns a fresh empty Map each invocation. Result: `emitLifecycleStart` writes
to a Map that vanishes by the next event; `emitLifecycleEnd` always sees an
empty map and emits no lifecycle terminal in production.

## Edge Cases & Risks

- **Risk: silent regression on agentsStates schema drift**: if a
  future Codex protocol version renames `agentsStates` or changes
  `CollabAgentState.message` to `summary`, the mapper read path will
  silently return null and the renderer will display the lifecycle card
  without summary text. **Mitigation**: M2's read uses the real path
  with safe optional chaining; M6/M7/M8 tests assert the path against
  the canonical type; if future schema changes happen, those tests will
  fail and force re-investigation. Out-of-scope: write a runtime schema
  validator against the upstream ts-rs types.

- **Risk: idempotency of lifecycle terminal**: the orchestrator's plan
  said "buffer in subagentLifecycles helper if close_agent path also
  needs to inherit". Codex review flagged duplicate-terminal risk if
  both wait and close emit terminal. **Mitigation**: M3 explicitly states
  wait_agent end does NOT emit lifecycle terminal — it only buffers
  the summary. close_agent end is the sole terminal trigger. If close
  is skipped (turn_aborted), the existing `flushOpenLifecycles` path
  handles cleanup. Verified by S1/M6 test cases.

- **Risk: empty `agentsStates` (Codex returns `{}` on completion)**:
  Codex protocol allows `agentsStates: {}` if no thread state is
  collected. **Mitigation**: M2 chains `?.message ?? null`; the
  emit path skips the `final_summary` field when null (consistent with
  cycle-6's existing optional emit on line 655). UI renders "Completed
  · <duration>" without summary text — graceful degradation.

- **Risk: receiverThreadIds order ambiguity**: `wait` may target multiple
  thread IDs. **Mitigation**: S1 codifies "first thread's message" per
  Codex's `first_agent_state` precedent. Single-thread case (the common
  one in v0.125 Codex) is unambiguous.

- **Risk: cycle-6 view file claims "primary: result.final_summary →
  fallback to prompt"**: the comment block at
  `CodexSubagentLifecycleView.tsx:23` says fallback is `prompt`. **No
  change required for cycle 7** — that fallback chain is renderer-side
  graceful degradation and is independent of the mapper's data source.

- **Risk: legacy session blobs**: encrypted SessionMessage blobs from
  cycle-6 contain envelopes with the old `final_summary` shape. **Mitigation**:
  M2 deletes the hallucinated read path entirely. Old session blobs
  containing the synthetic field at the envelope's `result.final_summary`
  level are still rendered by the view (which reads `result.final_summary`
  unconditionally). The mapper's input source change does not affect
  already-stored envelope blobs because the view reads from the
  envelope, not from the mapper's input. The renderer remains backward-compatible.
