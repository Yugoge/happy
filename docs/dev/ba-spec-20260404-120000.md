# BA Specification: Fix MCP Title Change - Stateless Transport Reuse Error

**Request ID**: dev-20260404-120000
**Created**: 2026-04-04T12:00:00Z

## Goal

Fix the MCP `change_title` tool which fails with "endpoint connection error" because the production code reuses a single stateless `StreamableHTTPServerTransport` across multiple HTTP requests, violating a guard added in MCP SDK 1.27.1.

## Context

The Happy CLI wraps Claude Code and provides an MCP server with a `change_title` tool. The architecture is:

1. `startHappyServer()` creates an HTTP MCP server on localhost (random port)
2. A bridge process (`happyMcpStdioBridge.mjs`) is spawned by Claude SDK, connecting STDIO (for Claude) to HTTP (for the MCP server)
3. When Claude calls `mcp__happy__change_title`, the bridge forwards via `StreamableHTTPClientTransport` to the HTTP server

The fix commit `0fd4112f` ("fix: MCP server broken by SDK 1.27 transport reuse rejection") exists in the worktree but was **never applied to the production code at `/root/happy`**.

## Root Cause

**MCP SDK 1.27.1** added a guard in `WebStandardStreamableHTTPServerTransport.handleRequest()` (line 139-141 of `webStandardStreamableHttp.js`):

```js
if (!this.sessionIdGenerator && this._hasHandledRequest) {
    throw new Error('Stateless transport cannot be reused across requests. Create a new transport per request.');
}
this._hasHandledRequest = true;
```

The **production** `startHappyServer.ts` creates ONE `StreamableHTTPServerTransport` at startup and reuses it for every request:

```js
const transport = new StreamableHTTPServerTransport({ sessionIdGenerator: undefined });
await mcp.connect(transport);
const server = createServer(async (req, res) => {
    await transport.handleRequest(req, res);  // FAILS on 2nd+ request
});
```

The first request (bridge `initialize`) succeeds and sets `_hasHandledRequest = true`. The second request (`notifications/initialized`) throws. The error is caught by `@hono/node-server`'s `getRequestListener` which returns HTTP 500 silently -- the outer try-catch never sees it, so nothing is logged.

From the bridge's perspective: `StreamableHTTPClientTransport` gets a 500 back and throws "Streamable HTTP error: Error POSTing to endpoint:" -- which Claude reports as "endpoint connection error".

## Requirements (MoSCoW)

### Must Have
- Apply the per-request transport pattern from commit `0fd4112f` to `/root/happy/packages/happy-cli/src/claude/utils/startHappyServer.ts`
- Each HTTP request must create a fresh `McpServer` + `StreamableHTTPServerTransport` pair
- The `persistTitle` fix from the worktree version (awaiting metadata update before returning success) should also be applied
- Rebuild and reinstall the CLI after the fix

### Should Have
- Add error logging when `@hono/node-server` swallows errors (log the HTTP status code after `await handler(req, res)` returns)
- Verify the fix works by testing the bridge-to-server connection end-to-end

### Could Have
- Add a health check endpoint to the MCP HTTP server for debugging

### Won't Have (Non-Goals)
- UI changes to how `change_title` is rendered in the app
- Changes to the bridge process itself (it works correctly)
- Changes to the hook exemption (already applied)

## Edge Cases & Risks

- The production daemon (PID 2025675) running the old code needs a restart after the CLI is rebuilt
- The `persistTitle` function depends on `ApiSessionClient.updateMetadata()` -- ensure the client reference is still valid when the handler fires
- Memory: creating a new `McpServer` per request could leak if `mcp.close()` is not called -- the `res.on('close', ...)` handler must reliably fire

## Acceptance Criteria

### AC1: MCP title change succeeds
- GIVEN a running Claude session with the fixed CLI
- WHEN Claude calls `mcp__happy__change_title` with a title string
- THEN the HTTP server returns 200 and the session title is updated in server metadata

### AC2: Multiple title changes work
- GIVEN a running Claude session with the fixed CLI
- WHEN Claude calls `mcp__happy__change_title` three times in succession
- THEN all three calls succeed (no "endpoint connection error")

### AC3: Bridge connectivity verified
- GIVEN the fixed HTTP MCP server is running
- WHEN a `StreamableHTTPClientTransport` connects, initializes, and calls `change_title`
- THEN the full round-trip completes with success response
