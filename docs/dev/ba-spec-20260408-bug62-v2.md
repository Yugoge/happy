# BA Specification: Event-Driven Session Recovery Architecture

**Request ID**: dev-20260408-bug62-v2
**Created**: 2026-04-08T12:00:00Z

## Goal

Replace the count-based watcher auto-restore with an event-driven architecture where the daemon itself respawns crashed sessions (non-zero exit code), and the watcher becomes a passive observer that only maintains snapshots. This eliminates all cascade bugs caused by the watcher misinterpreting count drops.

## Context

The current session recovery system uses a bash watcher that polls process state every 60s, computes diffs, and triggers auto-restore when sessions "disappear." This design is fundamentally flawed:

1. **Count-based logic cannot distinguish crash from archive.** When a user archives a session (clean exit), the watcher sees a count drop and restores the archived session.
2. **Peak merge resurrects dead sessions.** The zero-drop -> peak merge path restores sessions the user intentionally removed.
3. **Watcher/ExecStartPost race conditions.** Two independent restore triggers compete and cascade.

The user's insight: "count is meaningless. Just detect events." The six events are:
- Server reboot -> ExecStartPost -> restore all from snapshot
- Daemon crash/restart -> ExecStartPost -> restore all from snapshot
- OOM kills a session -> daemon detects non-zero exit -> respawn that session
- User archives a session -> daemon detects clean exit -> do NOT respawn
- User archives all sessions -> same as above for each -> count goes to 0 naturally
- Session natural exit (Claude finishes) -> daemon detects clean exit -> do NOT respawn

## Requirements (MoSCoW)

### Must Have

1. **Daemon respawns crashed sessions**: Modify `onChildExited` in `run.ts` to receive exit code/signal from the `happyProcess.on('exit')` handler. When exit code is non-zero (crash, OOM=137, SIGTERM=143), respawn the session using the stored working directory and Claude session ID. When exit code is 0 or null (clean exit / archive), do NOT respawn.
2. **Store respawn metadata in TrackedSession**: Add `workingDirectory: string` and `claudeSessionId?: string` fields to `TrackedSession` so the daemon has the info needed to respawn without external state.
3. **Remove watcher auto-restore trigger**: Delete the `if [ "$nr" -gt 0 ]` auto-restore block (lines 643-649) from `watch_sessions()`. The watcher should only record state changes, never trigger restores.
4. **Fix `find_peak_snapshot` first-home-only bug (Issue #3)**: Remove `break` on line 391 so all homes are searched.
5. **Fix `read_snapshot_count` first-home-only bug (Issue #4)**: Make it aggregate counts across all homes, or scope to `SCOPE_HOME` when set.
6. **Fix qijie `home_dir=""` convention (Issue #5)**: Default daemon should use explicit `/root/.happy` in session_dirs.txt, not empty string. Update `scan_running_sessions()` to emit the actual home path for default daemon.

### Should Have

7. **Respawn backoff**: When respawning crashed sessions, use exponential backoff (5s, 10s, 20s) with a max of 3 retries to prevent respawn loops for sessions that crash immediately.
8. **Log respawn events**: Add structured log entries when daemon respawns a session, including exit code, signal, session ID, and working directory.
9. **Distinguish SIGTERM from crash**: When the daemon sends SIGTERM to a session via `stopSession()`, mark the TrackedSession with a `stoppingByDaemon` flag so `onChildExited` does NOT treat the resulting SIGTERM exit as a crash requiring respawn.

### Could Have

10. **Expose respawn status via daemon HTTP `/list`**: Include respawn count and last crash info in the session listing.
11. **Notify app of respawn**: Send a session event to connected clients when a session is respawned.

### Won't Have (Non-Goals)

- Removing ExecStartPost restore entirely (still needed for daemon restart / server reboot)
- Changing the heartbeat or timeout system
- Modifying the Claude SDK's exit behavior
- Changing how the watcher writes snapshots (snapshot mechanism is fine, only the auto-restore trigger is removed)

## Edge Cases & Risks

- **Session crashes during startup (before webhook)**: `TrackedSession` may not have `claudeSessionId` yet. In this case, the daemon cannot `--resume` and should NOT respawn (the session never established itself).
- **Daemon restart kills all sessions**: Sessions spawned with `detached: true` survive daemon stop, but if daemon sends SIGTERM, they die. ExecStartPost handles this path, not daemon respawn logic.
- **Exit code 0 from `killThisHappy`**: `runClaude.ts:480` calls `process.exit(0)` in cleanup. This is correct -- killSession (archive) produces exit 0, which the daemon should NOT respawn.
- **Exit code 1 from uncaught exception**: `runClaude.ts:483` calls `process.exit(1)`. This IS a crash and SHOULD be respawned.
- **MAX_CONSECUTIVE_CRASHES (5) in claudeRemoteLauncher**: The inner while loop already handles Claude SDK crashes by restarting the Claude process within the same happy-cli process. The daemon-level respawn handles the outer process dying entirely.
- **SIGTERM from `stopSession()`**: Must NOT trigger respawn. Use a flag on TrackedSession.

## Acceptance Criteria

### AC1: Daemon respawns OOM-killed session
- GIVEN a session running under the daemon with a known Claude session ID
- WHEN the OOM killer sends SIGKILL (exit code 137) to the session process
- THEN the daemon detects the non-zero exit, logs the event, and respawns the session with `--resume <claudeSessionId>` in the same working directory within 5 seconds

### AC2: Daemon does NOT respawn archived session
- GIVEN a session running under the daemon
- WHEN the user archives the session via the app (killSession RPC -> process.exit(0))
- THEN the daemon detects exit code 0, logs the event, and does NOT respawn

### AC3: Daemon does NOT respawn stopped session
- GIVEN a session running under the daemon
- WHEN `stopSession()` sends SIGTERM to the process
- THEN the daemon detects the SIGTERM exit with `stoppingByDaemon` flag set, and does NOT respawn

### AC4: Watcher no longer triggers auto-restore
- GIVEN the watcher running and observing sessions
- WHEN a session disappears (count drops)
- THEN the watcher logs the change and updates snapshots, but does NOT call `restore_online_sessions`

### AC5: ExecStartPost still works for daemon restart
- GIVEN a daemon that crashed and is restarting via systemd
- WHEN ExecStartPost fires
- THEN sessions are restored from the per-home snapshot with `--kill-orphans`

### AC6: Qijie archives all sessions
- GIVEN qijie has 5 active sessions
- WHEN qijie archives all 5 sessions via the app
- THEN each exits with code 0, daemon does not respawn any, watcher records count=0, no restore is triggered

### AC7: find_peak_snapshot checks all homes
- GIVEN snapshots exist in /root/.happy-jade/session_backup_history/ but not /root/.happy/
- WHEN find_peak_snapshot is called
- THEN it finds and returns the jade snapshot (does not stop at first home)

## Technical Hints

- Affected TypeScript files:
  - `packages/happy-cli/src/daemon/run.ts` -- `onChildExited` handler (line 655), `happyProcess.on('exit')` handler (line 558), `stopSession` (line 616)
  - `packages/happy-cli/src/daemon/types.ts` -- `TrackedSession` interface
- Affected bash files:
  - `/root/bin/happy-session-recovery.sh` -- `watch_sessions()` (line 643-649), `find_peak_snapshot()` (line 391), `read_snapshot_count()` (line 356), `scan_running_sessions()` (home_dir handling)
- Exit code reference:
  - `0` = clean exit (archive via `killThisHappy` -> `process.exit(0)`, or natural completion)
  - `1` = uncaught exception (`process.exit(1)`)
  - `137` = SIGKILL (OOM killer)
  - `143` = SIGTERM (external signal, OR `stopSession()`)
  - `null` = signal-based exit (Node.js convention: code is null when signal is present)
- The `spawnSession()` function already accepts `resumeSessionId` in options -- reuse this for respawn
- `TrackedSession` gets working directory from `spawnSession`'s `directory` parameter and from `happySessionMetadataFromLocalWebhook.path` for externally-started sessions
- `claudeSessionId` comes from the metadata webhook: `session.happySessionMetadataFromLocalWebhook.claudeSessionId`
