# BA Specification: §5.6 — Unify CodexBashView with BashView/CommandView Primitives

**Request ID**: dev-20260424-143000-3
**Created**: 2026-04-24T14:30:00Z

## Goal

Migrate `CodexBashView.tsx` so all three Codex operation branches (read, write, bash) render through the same `BashView` / `CommandView` primitives already used by the Claude Code flavor. The result must be visually and behaviourally identical to the Claude Code popup modulo Codex-specific labels and icons, and must include the horizontal-scroll / overflow behaviour from §5.3 that now lives in `SidebarBashView`.

## Context

`CodexBashView` was created in commit `cdbcb9ab` ("wip: working on codex bash", 2025-09-03) before the Claude Code side received its compact-inline + sidebar-verbose treatment. Commit `1c85cc62` ("normalize bash tool command rendering", 2026-03-21) later normalized `BashView` and introduced `CommandView`, `BashViewFull`, and `SidebarBashView` — but did NOT update `CodexBashView`. The two code paths have since diverged:

| Aspect | Claude Code (BashView / CommandView) | Codex (CodexBashView) |
|--------|-------------------------------------|-----------------------|
| Inline view | `ScrollView` horizontal → compact prompt+output | Custom `readContainer` / `iconRow` layout |
| Container bg | none (transparent, inner `CommandView` uses `terminal.background`) | `surfaceHigh` + `borderRadius: 8` + `padding: 12` |
| Sidebar view | `SidebarBashView` → `ScrollView` horizontal + `CommandView` fullWidth | Same `SidebarBashView` (already unified — read lines 19-19) |
| Read/write branch | N/A — Bash has no file ops | Custom icon + `operationText` + `commandText` — no `ScrollView`, no `CommandView` |
| Bash branch | `ScrollView` + inline prompt/output | `CommandView` only (no `ScrollView` wrapper) — already partially unified |
| Overflow handling | Horizontal `ScrollView` on outer container | Missing for read/write; partial for bash |

The inline view for `read` and `write` operations (`CodexBashView` lines 52–85) never adopted `CommandView`, so long file paths and commands have no horizontal-scroll protection. The `bash` branch (lines 86–101) wraps `CommandView` directly without a horizontal `ScrollView`, diverging from `BashView`'s outer `ScrollView` pattern.

## Edge Cases & Risks

- `parsed_cmd` may be `null` / empty for some Codex invocations — the fallback to `stringifyToolCommand(command)` must be preserved.
- `result` for the `read` branch may also carry output (file content) — currently ignored. Keep ignoring for now (R7 out of scope).
- Removing `surfaceHigh` background from `CodexBashView` means the card body will inherit whatever background `ToolView`'s `content` area provides (`paddingHorizontal: 12`). Verify visually that the result looks correct, not "floating" with no container.
- `ToolView.tsx` icon resolution (lines 168–174) special-cases `CodexBash` to read `parsed_cmd[0].type` directly, bypassing `knownTools.icon`. If `CodexBashView` is refactored, this special-case in `ToolView` is still valid for the _header_ row icon — do not inadvertently remove it unless the knownTools definition is updated to handle the same branching.
