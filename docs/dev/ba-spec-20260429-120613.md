## Goal

Implement `scripts/rollback.sh`, the symmetric companion to the already-shipped `scripts/deploy.sh`. It must restore production happy-cli source to a previously-tagged pre-deploy snapshot and **force** the three production daemons (default / jade / qijie) onto that older code, with the same safety properties deploy.sh provides PLUS stricter polling/exit semantics that reflect rollback's higher-stakes role: preflight gates, mandatory recovery snapshot, version sanity check (codex #3), bounded daemon-health polling, abort-on-failure with phase-aware next-step messages, and audit-logging. Rollback is local-only by design; **no remote push and no operator-copyable push command** (codex review point 11 — pushing a backward-reset main is a force-push footgun).

## Requirements (MoSCoW)

### Must Have

- **M1**: Create `scripts/rollback.sh` that accepts exactly one positional argument: a pre-deploy tag name (e.g. `stable/2026-04-29-120613-41900760-pre-deploy`).
- **M2**: Reject argument unless it matches `^stable/[0-9]{4}-[0-9]{2}-[0-9]{2}-[0-9]{6}-[0-9a-f]{7,40}-pre-deploy$`. Additionally:
  - Require annotated tag (`git for-each-ref --format='%(objecttype)' refs/tags/<tag>` returns `tag`, not `commit`).
  - Run `git check-ref-format "refs/tags/<tag>"` and abort if it fails (codex review point 10).
- **M3**: cwd guard — abort unless `realpath PWD == realpath /root/happy` AND `git rev-parse --show-toplevel == /root/happy` (codex #5 carry-forward).
- **M3b** (added per codex review point 2): Git-state gate — abort unless ALL of:
  - `git rev-parse --abbrev-ref HEAD` returns exactly `main` (not detached HEAD, not another branch).
  - No active merge: `[ ! -f .git/MERGE_HEAD ]`.
  - No active rebase: `[ ! -d .git/rebase-merge ] && [ ! -d .git/rebase-apply ]`.
  - No active cherry-pick / revert / bisect: `[ ! -f .git/CHERRY_PICK_HEAD ] && [ ! -f .git/REVERT_HEAD ] && [ ! -f .git/BISECT_LOG ]`.
  - No active sequencer: `[ ! -d .git/sequencer ]`.
- **M4**: Tag must exist locally (`git rev-parse --verify -q "refs/tags/<tag>^{commit}"`) and be reachable from `main` (`git merge-base --is-ancestor <tag> main`). Abort with explicit error if not.
- **M5** (revised per codex review point 9): Working tree must be **strictly clean**:
  - No staged changes (`git diff --cached --quiet`).
  - No unstaged modifications (`git diff --quiet`).
  - **Reject** untracked files under any of: `packages/happy-cli/**`, top-level `package.json`, top-level `yarn.lock`, top-level `package-lock.json`, top-level `npm-shrinkwrap.json`. These paths feed `npm install -g .`; untracked files there could be packed into the rolled-back global install. Untracked files OUTSIDE these paths trigger the same `confirm()` as deploy.sh:131-136 (mirror).
- **M6**: Mandatory `bash /root/bin/happy-session-recovery.sh save` BEFORE any destructive operation; abort on save failure (no skip-with-confirm, unlike deploy.sh — rollback is itself a recovery action and must never run without a snapshot).
- **M7**: Capture `PRE_ROLLBACK_HEAD = git rev-parse HEAD` and `PRE_ROLLBACK_VERSION = jq -r .version packages/happy-cli/package.json` BEFORE reset. Capture `TARGET_VERSION` from `git show <tag>:packages/happy-cli/package.json | jq -r .version` BEFORE reset.
- **M8** (revised per codex review point 3 + QA-iter2 OBJ-1): Codex #3 carry-forward — abort if `TARGET_VERSION == PRE_ROLLBACK_VERSION` (silent no-op trap). Abort message MUST contain BOTH:
  1. The two version strings.
  2. An explicit operator path: "Daemon auto-upgrade is heartbeat-driven and only fires on version mismatch. To force daemon migration onto code that is at the same version string, either (a) pick a different rollback tag whose package.json version differs, or (b) abort this rollback, run `npm install -g .` from the desired tag, then restart daemons manually using one of: `bash /root/bin/happy-restart.sh` (restarts all three daemons + Docker; verified extant) OR per-daemon `systemctl restart happy-daemon.service` / `happy-daemon-jade.service` / `happy-daemon-qijie.service`. The previously-referenced `/root/bin/safe-daemon-restart.sh` does NOT exist on this server (verified 2026-04-29 via `ls /root/bin/safe*` returning only `safe-swap-drain.sh`); substitute the systemctl forms above."
- **M9**: Confirmation prompt (`confirm "Reset HEAD from $PRE_ROLLBACK_HEAD to $TAG ($PRE_ROLLBACK_VERSION → $TARGET_VERSION)?"`) before `git reset --hard <tag>`.
- **M10**: After reset, verify `git rev-parse HEAD == git rev-parse <tag>^{commit}`. Abort on mismatch.
- **M11**: `npm install -g .` after reset.
- **M12** (revised per codex review point 4): **Bounded polling**, not single sleep. Poll daemon state files every 10s; on each pass count daemons whose `daemon.state.json:.startedWithCliVersion == TARGET_VERSION`. Stop early when all reach TARGET_VERSION. Hard deadline: `DAEMON_AUTO_UPGRADE_WAIT_SECONDS` (90s, same constant as deploy.sh). After deadline:
  - **All daemons at TARGET_VERSION** → success epilogue, exit 0.
  - **Any daemon stale** → exit 1 (per codex review point 1; rollback's job is to FORCE migration, stale daemon is a failure). Print phase-aware abort message (M14): which daemons are stale, the manual restart invocation per daemon (routed through M14b `daemon_restart_hint()` so the systemctl form is emitted when `safe-daemon-restart.sh` is absent — current state on this server), and the recheck one-liner.
  - **Daemon home dir absent or `daemon.state.json` missing** → reported as "daemon not running"; counted neither stale nor OK; success-exit policy: count this as "OK by absence" (a stopped daemon is not running stale code), but PRINT it as a warning so the operator notices.
- **M13**: Audit log every action via `log()` (mirroring deploy.sh:62 timestamp format) to `/var/log/happy-rollback.log`. Pre-flight: `touch /var/log/happy-rollback.log 2>/dev/null || abort "/var/log/happy-rollback.log not writable; run as root."`
- **M14** (revised per codex review point 12): Phase-aware abort instructions. The script must be in exactly one of four phases at any abort point; each phase has distinct recovery hints:
  - **Phase P0 (preflight)**: argv invalid, cwd wrong, tag invalid, tree dirty, snapshot save failed. **Recovery hint**: "No source files were modified. Re-run after fixing the named issue."
  - **Phase P1 (post-snapshot, pre-reset)**: M7 capture failed, version-diff check failed, user declined the M9 confirm. **Recovery hint**: "Source files unchanged; safety tag not yet created. Recovery snapshot was saved at `<path printed by recovery-script>`."
  - **Phase P2 (post-reset, pre-install or install failed)**: `git reset --hard` succeeded but verification mismatch (M10), or `npm install -g .` failed. **Recovery hint**: "HEAD has been reset to <tag>. Safety tag is `<safety-tag>`. To restore PRE_ROLLBACK_HEAD: `git reset --hard $PRE_ROLLBACK_HEAD && npm install -g .`. Daemons will then heartbeat back to the prior version."
  - **Phase P3 (post-install, daemon migration incomplete)**: bounded polling exited with stale daemons. **Recovery hint** (revised per QA-iter2 OBJ-1): "HEAD is at <tag>; global install succeeded; some daemons did not migrate within ${DAEMON_AUTO_UPGRADE_WAIT_SECONDS}s. To force the stale daemon(s) to pick up the new code, the script must perform runtime detection (M14b below) and emit ONE of these two recovery blocks:
    - **If `[ -x /root/bin/safe-daemon-restart.sh ]`** (currently FALSE on this server, verified 2026-04-29; reserved for forward-compat if the SOP is later authored): "Per-daemon manual restart: `bash /root/bin/safe-daemon-restart.sh <name> --reason 'rollback to <tag>'`."
    - **Else (current state, file absent)**: "Per-daemon manual restart via systemd (verified extant unit names): `systemctl restart happy-daemon.service` / `systemctl restart happy-daemon-jade.service` / `systemctl restart happy-daemon-qijie.service`. Or, to restart all three daemons + Docker containers in one shot: `bash /root/bin/happy-restart.sh` (verified extant: `/root/bin/happy-restart.sh`, 5710 bytes)."
    - **In both branches append**: "Recheck: `for h in /root/.happy{,-jade,-qijie}; do jq -r .startedWithCliVersion $h/daemon.state.json; done`."

- **M14b** (NEW per QA-iter2 OBJ-1): Runtime test-and-degrade for the recovery script. Before printing the P3 (or M8) recovery hint, the script must execute `[ -x /root/bin/safe-daemon-restart.sh ]` and route output:
  - On hit (file exists and is executable): print the safe-daemon-restart.sh form.
  - On miss (current state, since file does not exist): print the systemctl form (and the `happy-restart.sh` shortcut). Do NOT print BOTH — pick one.
  - This is implemented as a single bash function (e.g. `daemon_restart_hint()`) that is called from both M8's silent-no-op abort path and M14 P3's polling-deadline abort path. Centralizing in one function ensures the test-and-degrade rule cannot drift between the two emit sites.
- **M15** (revised per codex review point 11 + QA-iter2 OBJ-2): NO remote push. Local-only rollback. **Do NOT print a copyable `git push` command.** Success epilogue contains two distinct blocks:

  **Block 1 — no-push warning (carry-forward from prior iter)**: "Rollback is local-only. Pushing this state to the fork would force-rewrite history (the rolled-back commit is no longer fast-forward from `fork/main`). If you need to share this rollback with collaborators, that is a separate, deliberate decision the operator must make manually with full understanding of force-push consequences."

  **Block 2 — fork-divergence advisory (NEW per QA-iter2 OBJ-2)**: After a successful local rollback, `fork/main` is now AHEAD of `/root/happy/main`. The script MUST compute and print the exact divergence at the moment the epilogue runs, then enumerate the two forward paths:
  - The script computes `DIVERGENCE_AHEAD = git rev-list --count HEAD..fork/main 2>/dev/null` (capture stderr; on failure default to "?" with a sub-hint that fork remote is missing). Use the LAST KNOWN fetch state — do NOT auto-fetch from inside the rollback script (an in-script fetch could surface other surprise commits and is itself a side effect).
  - Print exactly: `fork/main is now AHEAD of HEAD by ${DIVERGENCE_AHEAD} commit(s). The bad commit(s) you just rolled away from are still on the fork. Until they are removed from the fork, the next deploy.sh invocation in /root/happy will see them via 'git fetch fork' and they may re-enter your tree.`
  - Then enumerate the two valid forward paths:
    - **(a) Force-push the rolled-back state to fork/main** — symmetrical undo, makes fork match local. **MANUAL operator decision; rollback.sh MUST NOT auto-execute.** Operator command (printed for copy WITHOUT execution): `git push --force-with-lease=main:<fork/main commit at fetch time> fork main:main`. Recommended for the common case (single failed deploy whose bad commit you want to disappear from collaborator history).
    - **(b) Tag-based forward roll** — leave fork ahead, plan a NEW dev-SHA that itself reverts or fixes the regression, and run a future `deploy.sh <new-dev-sha>` from /root/happy. The next deploy.sh's `git fetch fork` plus `git merge dev-SHA` will land the new corrective commit on top of the rolled-back HEAD without surfacing the bad commits as a separate merge target. Recommended when the bad change introduces new history that collaborators have already pulled and a force-push would be disruptive.
  - **Recommendation line**: "For the common single-commit failed-deploy case, path (a) is recommended; for multi-collaborator scenarios where collaborators have pulled the bad commits, prefer path (b)."
  - The advisory must NOT auto-execute either path. The script prints, the operator decides.

- **M15b** (NEW per QA-iter2 OBJ-2): Documentation comment block in the script body — under a section header titled "Fork divergence after rollback" — explains the asymmetry (deploy.sh pushes; rollback.sh does not) and references the M15 Block 2 logic. This is a code-comment artifact, not a runtime printout — it ensures future maintainers reading rollback.sh understand WHY the success epilogue includes the divergence advisory.
- **M16**: Script header comment block enumerates the out-of-scope rollback domains: database migrations, Docker images (happy-server / happy-web / happy-web-dev), `/root/bin/` shell scripts. Documented as deferred / manual operator action; no doc cross-reference (DEPLOYMENT.md does not yet exist).
- **M17** (revised per codex review point 5): Static script-body audit. Beyond the header comment in M16, the script body must NOT contain any of these patterns (verifiable via grep on the saved file): `docker `, `prisma migrate`, `psql`, `pg_restore`, `/root/bin/[a-zA-Z_-]+\.sh` (where `[a-zA-Z_-]+` is anything other than `happy-session-recovery` or `safe-daemon-restart`). The recovery script call (M6) and the safe-daemon-restart hint string (M14 P3) are the only allowed exceptions. This converts AC11 from documentation-only to enforceable.
- **M18**: `set -uo pipefail` (matches deploy.sh:27). Do NOT use `set -e` — explicit `if !` checks are the project's convention.
- **M19**: Exit codes:
  - `0` success (HEAD reset, install succeeded, all daemons at TARGET_VERSION OR absent).
  - `1` runtime abort (validation gate, gate failure, user decline, daemon health timeout with stale daemons, install failure).
  - `2` argument-shape error (wrong argv count, bad tag-name format).

## Edge Cases & Risks

- **E1: Tag exists but unreachable from main**. Possible if a previous rollback was applied without retiring its pre-deploy tag, and the original commit is now on a discarded branch. Gate M4 catches this; abort with "tag is unreachable from main; investigate manually before rollback."
- **E2: Recovery script unavailable / hook-blocked**. If `/root/bin/happy-session-recovery.sh` is missing or non-executable, M6 aborts (no `confirm` skip — rollback without snapshot is unacceptable).
- **E3: `git reset --hard` after merge / rebase / cherry-pick state**. M3b (added) prevents this BEFORE M5 dirty-tree check.
- **E4: Daemon offline at rollback time**. M12 reports the daemon as "no daemon.state.json (daemon not running?)" and counts it as OK-by-absence; success epilogue notes this distinctly from migrated daemons.
- **E5: Heartbeat-driven auto-upgrade slower than 90s**. M12 polls every 10s; if some daemons remain stale at the 90s deadline, exit 1 with M14 P3 hints. The 90s is consistent with deploy.sh's known-good window.
- **E6: User picks a pre-deploy tag from a much older deploy whose package.json version is again equal to current** (e.g. linear version bumps then a manual revert). M8 catches the silent no-op with operator-path message.
- **E7: `npm install -g` fails (e.g. network)**. S3 + M14 P2 hint; PRE_ROLLBACK state preserved via S2 safety tag.
- **E8: User invokes from a worktree of /root/happy** (e.g. /dev/shm/dev-workspace/happy-dev). M3's `realpath PWD == realpath /root/happy` gate rejects this.
- **E9: Audit log location not writable**. M13 pre-flight: `touch /var/log/happy-rollback.log 2>/dev/null || abort`.
- **E10 (new, per codex review point 9)**: Untracked `packages/happy-cli/index.js` (from a developer hand-edit). Without M5's stricter check, that file would be packed into the global install. M5 rejects untracked files under `packages/happy-cli/**` outright.
- **E11 (new, per codex review point 8)**: Two rollback retries of the same HEAD within one second collide on `safety/<ts>-<sha>-pre-rollback`. S2 detects and appends random suffix.
- **E12 (new, per codex review point 11)**: Operator copies the success-epilogue push command and accidentally force-rewrites `fork/main`. M15 removes the copyable command.

## Acceptance Criteria

### AC1: rollback.sh file existence and executability
- GIVEN the dev subagent has finished implementation
- WHEN `ls /dev/shm/dev-workspace/happy-dev/scripts/rollback.sh` is run
- THEN the file exists, is non-empty, and `head -1` reads `#!/bin/bash`

### AC2: rollback.sh argument validation
- GIVEN rollback.sh is invoked with `bash rollback.sh foo` from `/root/happy`
- WHEN argument validation runs
- THEN script exits with code 2 and stderr contains the word "tag" (rejecting invalid tag-name shape)

### AC3: cwd guard (codex #5)
- GIVEN rollback.sh is invoked from any directory other than `/root/happy`
- WHEN preflight runs
- THEN script exits with code 1 and stderr/log contains "Must run from /root/happy"

### AC3b (new): git-state gate (codex review point 2)
- GIVEN rollback.sh is invoked while `.git/MERGE_HEAD` exists (mid-merge), OR HEAD is detached, OR a rebase is in progress
- WHEN M3b runs
- THEN script exits with code 1 and stderr/log identifies which condition was violated (e.g. "active merge: .git/MERGE_HEAD present" or "HEAD detached: not on main")

### AC4 (revised per QA-iter2 OBJ-1): silent no-op detection (codex #3)
- GIVEN a pre-deploy tag whose `packages/happy-cli/package.json` version equals the currently-installed version
- WHEN rollback.sh validates the version diff
- THEN script aborts with code 1 BEFORE running `git reset` or `npm install`
- AND the abort message names both versions
- AND the abort message routes through `daemon_restart_hint()` (M14b) and prints exactly ONE of: (i) the `/root/bin/safe-daemon-restart.sh` form (only if `[ -x /root/bin/safe-daemon-restart.sh ]` is TRUE at runtime — currently FALSE on this server), OR (ii) the systemctl form (`systemctl restart happy-daemon.service` / `happy-daemon-jade.service` / `happy-daemon-qijie.service`) plus the `happy-restart.sh` shortcut. Static-grep verification: the literal string `safe-daemon-restart.sh` MAY appear in the script body (it is the test-and-degrade hit branch) but the systemctl unit names MUST also appear (test-and-degrade miss branch). A spec compliance failure occurs ONLY if the safe-daemon-restart.sh form is the ONLY recovery path emitted (i.e., the systemctl fallback is missing).

### AC5: recovery snapshot is mandatory
- GIVEN `/root/bin/happy-session-recovery.sh` is missing or returns non-zero
- WHEN rollback.sh tries to save a snapshot
- THEN script aborts with code 1 (no `confirm` skip — UNLIKE deploy.sh)

### AC6: tag reachability gate (M4)
- GIVEN a tag that exists locally but is not an ancestor of `main`
- WHEN rollback.sh checks `git merge-base --is-ancestor <tag> main`
- THEN script aborts with code 1 and message names the tag and the unreachability condition

### AC7: post-reset HEAD verification (M10)

### OBJ-2 resolution — fork divergence after local-only rollback

**QA finding**: deploy.sh:363 pushes to `fork` remote, but rollback.sh:M15 forbids push. After successful rollback, `fork/main` is AHEAD of `/root/happy/main` by N commits. The next deploy.sh run does `git fetch fork` (deploy.sh:144) and the bad commits become candidates for re-merge.

**Worked example** showing the divergence direction immediately after rollback:

Setup state (immediately after the failed deploy.sh that the operator wants to roll back):

```
HEAD       (= /root/happy/main local) ──● <bad-commit> 0a1b2c3d "Deploy: <topic>"
                                        │
fork/main  (= last fetch state)         ──● <bad-commit> 0a1b2c3d  ← deploy.sh:363 just pushed this
                                        │
PRE_TAG    refs/tags/stable/...-pre-deploy ──● <good-commit> 9z8y7x6w (one commit before HEAD)
```

Operator runs `bash scripts/rollback.sh stable/2026-04-29-103045-9z8y7x6w-pre-deploy`.

State immediately AFTER successful rollback:

```
HEAD       (= /root/happy/main local) ──● <good-commit> 9z8y7x6w  ← reset --hard <PRE_TAG>
                                        │
fork/main  (= last fetch state)         ──● <bad-commit> 0a1b2c3d  ← UNCHANGED (rollback.sh did not push)
                                        │
                                        ↑
                                        DIVERGENCE: fork/main is 1 commit ahead of HEAD.
                                        The bad commit 0a1b2c3d is still on the fork.
```

`git log fork/main..HEAD` (the commits on local but not on fork): empty. `git log HEAD..fork/main` (the commits on fork but not on local): `0a1b2c3d <bad-commit>`. **Direction is the latter** — fork is ahead, local is behind.

**Literal advisory text rollback.sh will print** (verbatim, this is what AC17 enforces):

```
=== ROLLBACK OK ===
HEAD: 9z8y7x6w (= refs/tags/stable/2026-04-29-103045-9z8y7x6w-pre-deploy)
Daemons confirmed: 3/3 at <TARGET_VERSION>

WARNING: Rollback is local-only.
Pushing this state to the fork would force-rewrite history (the rolled-back
commit is no longer fast-forward from fork/main). If you need to share this
rollback with collaborators, that is a separate, deliberate decision the
operator must make manually with full understanding of force-push consequences.

=== Fork divergence after rollback ===
fork/main is now AHEAD of HEAD by 1 commit(s). The bad commit(s) you just
rolled away from are still on the fork. Until they are removed from the fork,
the next deploy.sh invocation in /root/happy will see them via 'git fetch fork'
and they may re-enter your tree.

Two forward paths:
  (a) Force-push the rolled-back state to fork/main (symmetrical undo, makes
      fork match local). MANUAL operator decision; rollback.sh did not execute
      it. Operator command (copy and run from /root/happy in your TTY):

        git push --force-with-lease=main:0a1b2c3d fork main:main

      Recommended for the common single-commit failed-deploy case.

  (b) Tag-based forward roll — leave fork ahead, plan a NEW dev-SHA that itself
      reverts or fixes the regression, and run a future
        bash scripts/deploy.sh <new-dev-sha>
      from /root/happy. The next deploy.sh's `git fetch fork` plus
      `git merge dev-SHA` will land the new corrective commit on top of the
      rolled-back HEAD without surfacing the bad commits as a separate merge
      target. Recommended when collaborators have already pulled the bad
      commits and a force-push would be disruptive.

For the common single-commit failed-deploy case, path (a) is recommended;
for multi-collaborator scenarios, prefer path (b).
```

**Resolution path chosen**: Add to the success epilogue (M15 Block 2) the divergence count, the two forward paths labeled (a) and (b), the recommendation, and a non-executing copy-string for path (a). M15b adds a section-heading code-comment in the script body so future maintainers see the asymmetry rationale. AC17 enforces all of the above; static-grep audit also forbids `git fetch` and `git push` from running in the script body (only appearing inside the printed advisory string and code comments).
