# BA Specification: Fix BashView Inline Preview CSS Bugs

**Request ID**: dev-20260408-0700
**Created**: 2026-04-08T07:00:00Z

## Goal

Fix two CSS layout bugs in BashView inline preview (message list) caused by `borderBottomLeftRadius`/`borderBottomRightRadius`/`overflow:hidden` being applied to the outer container that wraps both the ScrollView and the "+N more lines" indicator.

## Context

Commit `a529bf91` added bottom border radius and overflow hidden to the BashView container to make terminal blocks visually match the parent ToolView card's rounded corners (borderRadius: 8). However, the container wraps both the horizontal ScrollView (code content) and the moreContainer ("+N more lines" text), causing two distinct visual bugs.

The parent ToolView has `borderRadius: 8` and `overflow: 'hidden'` on its own container, plus `paddingHorizontal: 12`, `paddingTop: 8`, `borderTopWidth: 1` on its content area. BashView uses negative margins to fill edge-to-edge.

## Requirements (MoSCoW)

### Must Have
- Fix Bug 1: Horizontal scrollbar must not overlap with "+N more lines" text on long output
- Fix Bug 2: Bottom rounded corners must render cleanly on short output (no moreContainer)
- Maintain edge-to-edge terminal background fill within the ToolView card
- Preserve the visual appearance of rounded bottom corners on the terminal block

### Should Have
- Clean separation of concerns: radius applied to the actual bottom-most element

### Could Have
- N/A

### Won't Have (Non-Goals)
- Changes to ToolView container styles
- Changes to CommandView component
- Changes to sidebar/full view BashView rendering
- Any functional logic changes (truncation, line counting)

## Edge Cases & Risks

- ScrollView horizontal scrollbar visibility varies by platform (web shows scrollbar, native may not)
- The `showsHorizontalScrollIndicator={false}` was set in the same commit — if re-enabled, scrollbar positioning matters
- Negative margins must still align with ToolView content padding after changes

## Acceptance Criteria

### AC1: Long output — no scrollbar/text overlap
- GIVEN a bash tool call with output exceeding MAX_PREVIEW_LINES (2 lines)
- WHEN the inline BashView renders in the message list
- THEN the "+N more lines" text is fully visible and not overlapped by any scrollbar or clipped content

### AC2: Short output — clean bottom corners
- GIVEN a bash tool call with output of 2 lines or fewer (no moreContainer shown)
- WHEN the inline BashView renders in the message list
- THEN the bottom corners of the terminal block are cleanly rounded without visual artifacts

### AC3: Edge-to-edge fill preserved
- GIVEN any bash tool call
- WHEN the inline BashView renders
- THEN the terminal background fills edge-to-edge within the ToolView card (no gaps at sides or bottom)

## Technical Hints

- Affected file: `packages/happy-app/sources/components/tools/views/BashView.tsx`
- Root cause: `borderBottomLeftRadius: 11`, `borderBottomRightRadius: 11`, `overflow: 'hidden'` on container (lines 90-92)
- Parent styles: ToolView container `borderRadius: 8`, content `paddingHorizontal: 12`, `paddingTop: 8`
- Fix approach: Remove border radius from container. Apply bottom radius to the ScrollView wrapper when no moreContainer exists, or to the moreContainer when it exists. Keep `overflow: 'hidden'` on container for general clipping.
- BashView uses `borderBottomLeftRadius: 11` (not 8) to account for 12px negative margin + 1px border = inner radius that visually matches outer 8px radius
