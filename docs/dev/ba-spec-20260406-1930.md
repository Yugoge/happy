# BA Specification: Fix 5 Remaining UI Issues (Edit File View, AskUserQuestion Persistence, Subagent Sidebar, Bash/Detail Confirmation)

**Request ID**: dev-20260406-1930
**Created**: 2026-04-06T19:30:00Z

## Goal

Fix 3 active UI bugs and confirm 2 already-fixed issues in happy-app. The bugs span CLI-to-app data flow (Edit tool file content), app state persistence (AskUserQuestion answers), and reducer sidechain population (subagent sidebar content).

## Context

The happy-app UI has been through multiple rounds of sidebar and tool rendering improvements. Three issues remain where data is missing or lost: (1) Edit tool sidebar cannot show full file content because the CLI only sends diff fields, (2) AskUserQuestion answers vanish on re-entry because they are never persisted to the tool/permission state, (3) subagent sidebar shows empty because the reducer sidechain map may not receive all internal subagent messages. Two previously reported issues (Bash truncation, detail page sidebar takeover) are already fixed and need confirmation only.

## Requirements (MoSCoW)

### Must Have
- **Issue 1**: In CLI sessionProtocolMapper.ts, when emitting `tool-call-end` for Edit tool, read the file at `file_path` and attach the content to the `output` field so the app can display it in SidebarFileView
- **Issue 2**: In app's sync/ops.ts `sessionAllow`, after sending the RPC, write the `answers` record into the tool's permission object in local state so `AskUserQuestionView` can recover answers on remount via `tool.permission.answers`
- **Issue 3**: Investigate and fix why subagent internal messages (text, TodoWrite) are not appearing in the reducer sidechain map, resulting in empty SidebarAgentConversation

### Should Have
- Issue 1: Limit file content to a reasonable size (e.g., 100KB) to avoid bloating messages
- Issue 2: Also persist answers through the `completedRequests` agentState path so the data survives full session reload

### Could Have
- Issue 1: Show syntax-highlighted full file in sidebar with diff overlaid
- Issue 3: Add logging/debugging hooks to trace sidechain message flow

### Won't Have (Non-Goals)
- Changing the Claude SDK's Edit tool interface
- Modifying the happy-server message storage format
- Adding new RPC endpoints
- Modifying BashView or ToolView (already confirmed fixed)

## Edge Cases & Risks

- Issue 1: Large files could bloat message payloads; must cap file read size
- Issue 1: File may not exist at `file_path` by the time tool-call-end fires (deleted between edit and result); handle gracefully
- Issue 2: Race condition if component unmounts before RPC completes; answers must be written to state before the async RPC call
- Issue 3: Session protocol messages from subagents may lack `isSidechain` flag or have different `parentUuid` structure than expected

## Acceptance Criteria

### AC1: Edit tool shows file content in sidebar
- GIVEN an Edit tool call has completed
- WHEN user taps the Edit tool to open SidebarFileView
- THEN the sidebar shows the full file content (or diff context) not just old_string/new_string

### AC2: AskUserQuestion answers persist across navigation
- GIVEN user has answered an AskUserQuestion and navigated away
- WHEN user returns to the conversation containing that tool call
- THEN the submitted answers are displayed (not dashes or empty)

### AC3: Subagent sidebar shows internal messages
- GIVEN an Agent/Task tool call with subagent activity
- WHEN user opens the subagent sidebar conversation
- THEN text messages and TodoWrite tool calls from the subagent are visible

### AC4: Bash tool truncation confirmed
- GIVEN a Bash tool call with long output
- WHEN rendered inline
- THEN output is truncated to 3 lines with maxHeight: 80

### AC5: Detail page sidebar behavior confirmed
- GIVEN user navigates to a tool detail page
- WHEN the page opens
- THEN the right sidebar closes (closeSidebar() called in handlePress)
