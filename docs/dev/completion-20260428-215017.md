## Root Cause

**Symptom**: 5 of 5 codex sessions running on `happy-daemon-dev` (PID 275490) were absent from `/root/.happy-dev/session_dirs.txt`. All 5 claude sessions on the same daemon were present.

**Root cause**: Asymmetric metadata propagation between protocols.
- Claude path (`packages/happy-cli/src/claude/session.ts:112-124`): post-spawn webhook re-notification calls `notifyDaemonSessionStarted` with `claudeSessionId`, populating the daemon's `TrackedSession.happySessionMetadataFromLocalWebhook`.
- Codex path (`packages/happy-cli/src/codex/runCodex.ts:710-713` and `codex/resumeExistingThread.ts:35-38`): only updates the API-side `session.updateMetadata(codexThreadId)`; **never** calls `notifyDaemonSessionStarted`.

The daemon's `/list` response builder at `daemon/controlServer.ts:82` reads only the `claudeSessionId` field, so even if codex metadata existed in `TrackedSession`, it would not surface to the recovery script.

**Root cause commit**: `4381eaf5` (cycle 2 codex protocol activation) — codex registration was never wired through the same post-spawn webhook the claude path uses.

## Implementation
