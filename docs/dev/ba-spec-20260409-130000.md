# BA Specification: Sidechain Messages Not Rendering in Sidebar/Detail View

**Request ID**: dev-20260409-130000
**Created**: 2026-04-09T13:00:00Z

## Goal

Fix sidechain (Agent/Task subagent) messages not appearing as children in the tool detail view despite the CLI correctly sending all 6 envelope types and the server storing them.

## Context

The session protocol sidechain feature sends subagent messages (start, sidechain root, text, tool-call-start, tool-call-end, stop) with a shared CUID2 `subagent` identifier. The inline chat view shows the Agent tool call with its header (Description + status), but clicking into the detail/sidebar view shows only Description + Input Parameters + Output -- no child messages from the subagent execution.

## Root Cause Analysis

**PRIMARY BUG -- Missing full-view registry entry (UI layer)**

`toolFullViewRegistry` in `packages/happy-app/sources/components/tools/views/_all.tsx` (line 52-54) only registers `MultiEdit`. It does NOT register `Task` or `Agent`. When `ToolFullView` renders (line 109-128 of `ToolFullView.tsx`), `getToolFullViewComponent('Agent')` returns `null`, so the `TaskViewFull` component (which renders child messages) is never instantiated. The detail view falls through to the generic layout: Description + Input + Output.

**SECONDARY BUG -- Tracer orphan handling for CUID2 parent references (data layer)**

In `reducerTracer.ts` (line 288), when a sidechain child message has `parentUUID` = CUID2 and the parent tool-call hasn't been processed yet, the `isUuidLike()` check returns `false` (CUID2 is not UUID v1-v5 format). Instead of buffering the child as an orphan (the correct behavior for out-of-order messages), it processes it as a standalone message with no `sidechainId`. This means it joins `nonSidechainMessages` instead of `sidechainMessages`, and its content is never added to `state.sidechains`.

In normal operation (messages arrive in order), this is not triggered because the Agent tool-call-start registers `toolCallToMessageId[CUID2]` before children arrive. But during page reload or message re-fetch, batch boundaries could cause out-of-order processing.

## Requirements (MoSCoW)

### Must Have
- Register `Task` and `Agent` in `toolFullViewRegistry` so `TaskViewFull` renders in the detail/sidebar view
- Verify that the inline `TaskView` correctly receives and renders child messages (sub-tool status rows)

### Should Have
- Fix the `isUuidLike` gate in `reducerTracer.ts` to also buffer CUID2-keyed orphans (prevent data loss on out-of-order message arrival)

### Could Have
- Add a unit test for the tracer with CUID2 parent references arriving before the parent tool-call message

### Won't Have (Non-Goals)
- Changing the CLI envelope format
- Modifying server-side message storage or ordering
- Changing the session protocol schema

## Edge Cases & Risks

- If `TaskViewFull` is registered but children data is empty (due to secondary bug), the full view will render an empty "Sub Tools" section -- this is acceptable as a degraded state
- The `isUuidLike` fix must not break UUID-based orphan buffering (existing behavior for legacy messages)
- Ensure `Task` tool (not just `Agent`) also works, since both use the same codepath

## Acceptance Criteria

### AC1: Detail view shows subagent children
- GIVEN a session with an Agent tool call that has sidechain child messages
- WHEN the user opens the tool detail view (sidebar or full-screen)
- THEN the TaskViewFull component renders with expandable "Sub Tools" section showing child messages

### AC2: Inline view shows sub-tool status rows
- GIVEN a session with an Agent tool call that has sidechain child messages
- WHEN the user views the chat message list
- THEN the Agent tool card shows the TaskView with sub-tool names and status icons

### AC3: Out-of-order CUID2 orphans are buffered
- GIVEN sidechain child messages that arrive before their parent tool-call message
- WHEN the tracer processes the child messages
- THEN they are buffered as orphans (not processed standalone) and linked when the parent arrives

## Technical Hints

- Primary fix file: `packages/happy-app/sources/components/tools/views/_all.tsx` line 52-54
- Secondary fix file: `packages/happy-app/sources/sync/reducer/reducerTracer.ts` line 288
- The `TaskViewFull` component already exists and works -- it just needs to be registered
- `isUuidLike` check should be relaxed or CUID2 references should also trigger orphan buffering
- Related: `shouldHideParentToolCall` in CLI mapper returns `true` only for `Task`, not `Agent` -- this is intentional (Agent shows as a visible tool-call in the chat, Task is hidden)
