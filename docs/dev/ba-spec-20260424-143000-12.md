## Goal

Document the second non-adaptive top-bar layout case (§5.5) as an explicit verification scenario for the §5.4 fix. No separate code changes are required; the §5.4 fix must resolve both cases. This spec exists so QA can confirm coverage of the §5.5 configuration when verifying the §5.4 fix.

## Context

The user reported two separate screenshots of the same class of bug: the top-bar happy logo and user avatar do not track the main-content column width when sidebars open/close. §5.4 captured the primary case (right Bash popup open, wide desktop). §5.5 captures a second configuration (right TodoList sidebar open, narrower viewport) that exposes the same root cause under different conditions.

Per the user's own framing: "treat as a continuation of §5.4: same class of bug, different concrete case captured for dev/QA reproduction. The fix approach for §5.4 must resolve the case shown here too; if not, it is not complete."

The §5.4 BA spec (`docs/dev/ba-spec-20260424-143000-11.md`) contains all root-cause analysis, code locations, and the development approach. This spec provides only the scenario delta.

## Evidence (Contract A)

- **Observed**: "没有自适应的另外一个案例" — a second example of non-responsive layout in the same top-bar / chrome region (verbatim from §5.5 acceptance criterion in spec-20260424-084848.md).
- **Measured** (inferred from screenshot `9d264db4-cc7e-4fc4-abf7-d5f5e393d635-4132.png`): Right sidebar open showing TodoList with green/grey checkmark items. Header title "Redesign /spec command" appears left-shifted, not centered in the remaining main-column space. The happy logo (H, top-left) and avatar (dark circle, top-right) remain anchored to window edges rather than to the main-column boundary. The sidebar occupies the right portion of the viewport — the header content does not compensate.
- **Expected**: Header center-container and logo/avatar positions should be functions of `windowWidth − leftDrawerWidth − (rightSidebarWidth when open)`, matching the available main-column width. This is the same expected behavior as §5.4.
- **Gap**: Same gap as §5.4 — `layout.headerMaxWidth` is a static clamp unaware of the 450 px right sidebar reservation, and `MainView.tsx` `sidebarContentContainer` has no right-sidebar-open awareness that feeds back to the header.
