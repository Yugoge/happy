# BA Specification: Revert Broken SidebarBashView Horizontal Scroll

**Request ID**: dev-20260408-150000
**Created**: 2026-04-08T15:00:00Z

## Goal

Revert the recent change to SidebarBashView.tsx that wrapped a horizontal ScrollView inside a vertical ScrollView, breaking horizontal scrollbar functionality. Then investigate the root cause of why the horizontal scrollbar was not appearing in the original implementation.

## Context

SidebarBashView.tsx renders bash command output in the sidebar panel. The original implementation used a plain `<View>` container with a horizontal `<ScrollView>` inside it, with `showsHorizontalScrollIndicator={true}`. A recent change (commit `5973f3ed`) replaced the outer `<View>` with a vertical `<ScrollView>`, which broke the horizontal scrollbar -- nesting a horizontal ScrollView inside a vertical ScrollView causes layout conflicts on web.

The original code (before the breaking change) already had `showsHorizontalScrollIndicator={true}` but the user reports the horizontal scrollbar was not appearing even before this wrapping change. The investigation should focus on why the original horizontal scroll indicator doesn't render.

## Requirements (MoSCoW)

### Must Have
- Revert SidebarBashView.tsx to the pre-change state: outer container must be a `<View>`, not a `<ScrollView>`
- Restore original styles (single `container` style with `paddingTop: 12`, remove `verticalContent` style)
- Investigate why `showsHorizontalScrollIndicator={true}` does not produce a visible scrollbar on web

### Should Have
- Fix the horizontal scrollbar visibility if root cause is identified
- Ensure the fix follows patterns used in BashViewFull.tsx (which has the same structure)

### Could Have
- Add vertical scrolling for very long output (but NOT by nesting ScrollViews)

### Won't Have (Non-Goals)
- Changes to CommandView.tsx internals
- Changes to BashView.tsx (inline preview, different component)
- Mobile-specific scroll fixes (web is the platform where this matters for sidebar)

## Edge Cases & Risks

- Content that fits within the container width should NOT show a scrollbar
- The `minWidth: '100%'` on `commandWrapper` combined with `flexGrow: 1` on `scrollContent` may prevent the horizontal ScrollView from ever being wider than its container, making the scrollbar unnecessary from the layout engine's perspective
- On web, React Native ScrollView renders as a `<div>` with `overflow: auto/scroll` -- CSS `overflow-x` behavior depends on the inner content actually exceeding the container width

## Acceptance Criteria

### AC1: Revert succeeds
- GIVEN the current SidebarBashView.tsx has nested ScrollViews
- WHEN the revert is applied
- THEN the outer element is a `<View>` with `flex: 1, paddingTop: 12`, the inner is a horizontal `<ScrollView>`, and the `verticalContent` style is removed

### AC2: Horizontal scrollbar visible for wide content
- GIVEN a bash command with output wider than the sidebar panel
- WHEN the sidebar displays the command
- THEN a horizontal scrollbar is visible and functional

### AC3: No regression on normal content
- GIVEN a bash command with output that fits within the sidebar width
- WHEN the sidebar displays the command
- THEN no horizontal scrollbar appears and content renders normally

## Technical Hints

- Affected files: `packages/happy-app/sources/components/sidebar/SidebarBashView.tsx`
- Related patterns: `BashViewFull.tsx` uses identical structure (View > horizontal ScrollView > View > CommandView) and works correctly
- Root cause hypothesis: The `commandWrapper` style has `minWidth: '100%'` which ensures the inner content is always at least as wide as the scroll container. Combined with `flexGrow: 1` on `scrollContent`, the content may never exceed the container width because text inside CommandView wraps with `flexWrap: 'wrap'` on the command line. The `flex: 1` on `commandText` causes the text to wrap rather than extend, so horizontal overflow never triggers.
- Key difference from BashViewFull: BashViewFull is rendered in a full-page view where the container is wider, so overflow is less likely. In the sidebar, the container is narrow, making overflow more likely -- but the flexWrap prevents it.
- Potential fix direction: On the `commandText` style in CommandView, `flex: 1` causes text wrapping. For horizontal scroll to work, the inner content must be allowed to exceed the container width. The `line` style has `flexWrap: 'wrap'` which explicitly prevents overflow. For the sidebar bash view, either the commandWrapper needs `minWidth` removed or the text needs `flexWrap: 'nowrap'` / `flexShrink: 0`.
