- **Terminal AC3 is not fully evidenced.** The draft claims Terminal inline/detail pass, but AC3 also requires command text appears once and stdout/stderr/exit status are reachable. The trace excerpt suggests the command may appear both in the header and body, and the summary does not prove exit status/stderr/stdout reachability.

- **“No page-level horizontal overflow” is too weak.** `documentScrollWidth === clientWidth` does not prove the tool card/detail content is not clipped. Need element-level `scrollWidth/clientWidth`, computed overflow/wrapping, or visual proof that long command/diff text is readable/scrollable.

- **Markdown/rich is not a full row pass.** Draft says no separate detail surface was found for plain text, but AC2 requires inline/detail/mobile unless intentionally hidden by product design. This needs either detail evidence or explicit “no detail surface by design” rationale.

- **Patch/file-update evidence may be weaker than claimed.** “Detail shows Applying patch to 1 file and diff JSON” sounds possibly like raw JSON leakage, not a complete specialized diff view. Need evidence of filename/action/status and readable hunks/result, not just protocol JSON.

- **Attachment evidence does not satisfy image/view_image.** `file-10mb.bin` proves binary attachment affordance only. It should not count toward image thumbnail/view_image rendering. The draft correctly says image/view_image is target-missing; keep it out of positive pass accounting.

- **MCP permission card is not MCP/resource coverage.** Good that the draft notes this, but avoid listing it as meaningful matrix evidence unless there is a separate permission-card row. It does not cover `resources.read`, `mcp__*`, or resource result rendering.
