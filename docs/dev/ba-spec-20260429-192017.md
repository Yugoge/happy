#### M-PATHSCAN — Static-scan defense (Pass 1 #6, Pass 3 #1)
- M-PATHSCAN.1: `path_scan_rewritten <file>` runs after rewrite, before any sandbox-script invocation.
- M-PATHSCAN.2: Regex MUST detect `/root` `/var` `/usr` paths. Use `grep -nE '/(root|var|usr)/[A-Za-z._-]'` (Pass 1 #6 — `[A-Za-z._-]` covers `.happy`, `_underscore_`, dashes — must NOT use `[a-z]` alone).
- M-PATHSCAN.3: Allowlist is line-pattern based (Pass 1 #7 — comment lines CAN have `/root/...` as operator hints, log-text strings CAN reference `/root/...` as production instructions to operators):

- M-PATHSCAN.4: Scan failure exits the WHOLE test run with exit code 2 (setup-fail) and message `[PATHSCAN FAIL] <file>:<line>: leaked path '<X>' outside allowlist`.

#### M-NPMSHIM — npm PATH shim
- M-NPMSHIM.1: `tests/bin/npm` is a bash recording shim:
  ```
  #!/bin/bash
  # records argv to NPM_SHIM_LOG; default exit 0; failure injection via NPM_SHIM_FAIL=1
  echo "$(date -Iseconds) PWD=$PWD ARGV=$*" >> "${NPM_SHIM_LOG:?NPM_SHIM_LOG must be set}"
  if [ "${NPM_SHIM_FAIL:-0}" = "1" ]; then exit 1; fi
  if [ -n "${NPM_SHIM_FAIL_FIRST_N:-}" ]; then
    counter_file="${NPM_SHIM_LOG}.counter"
    n=$(cat "$counter_file" 2>/dev/null || echo 0)
    n=$((n + 1))
    echo "$n" > "$counter_file"
    if [ "$n" -le "$NPM_SHIM_FAIL_FIRST_N" ]; then exit 1; fi
  fi
  exit 0
  ```
- M-NPMSHIM.2: NPM_SHIM_FAIL_FIRST_N supports stateful "fail first N calls, succeed after" pattern (Pass 2 #11) — used by S07 to test rollback-install-after-failed-install path.

**Implementation hint for dev (REVISED iter3 OBJ-3 fix — empirically verified)**: define a helper in `tests/lib/static-audit.sh` (NEW lib file, Phase 3 deliverable):
```bash
# audit_no_executable <pattern> <file> -> echoes count of executable matches
# OBJ-3 fix: Each grep that may exit 1 in the success path (no matches / all
# filtered) is wrapped in { ...; || true; } so set -euo pipefail does not
# abort the caller. Precheck guards against missing-file / unreadable-file
# (codex iter3 caveat: || true masks real grep errors otherwise).
audit_no_executable() {
  local pattern="$1" file="$2"
  if [ ! -r "$file" ]; then
    echo "[audit_no_executable] file not readable: $file" >&2
    return 2
  fi
  { grep -nE "$pattern" "$file" 2>/dev/null || true; } \
    | { grep -vE '^[0-9]+:[[:space:]]*(#|log[[:space:]]|echo[[:space:]]|printf[[:space:]])' || true; } \
    | { grep -vE '^[0-9]+:.*<<' || true; } \
    | wc -l
}
```
Then S17 calls `assert_count 0 "$(audit_no_executable '\bgit fetch\b' $SANDBOX/scripts/rollback.sh)" "no executable git fetch in rollback (advisory copy-strings excluded)"` etc.

**Known limitation (carry-forward to § Known Coverage Limitations item L14)**: the post-filter heuristic does not handle multi-line `log "..." \` continuation lines (continuation appears as `    "..."` with no `log ` prefix). rollback.sh and deploy.sh currently have zero such constructs (verified). **Codex caveat note (iter3)**: codex pass observed that `|| true` also masks real grep errors (e.g., regex compilation failure exit 2). Mitigation: the `[ -r "$file" ]` precheck above catches missing/unreadable files explicitly with `return 2`; for grep regex-compilation errors (exit 2) we accept the trade-off — these are dev-time errors that surface as `wc -l` returning a count that does not match assertion expectations, and the resulting test FAIL message will lead the developer to inspect the helper invocation. A stricter alternative (preserve grep exit 2 while masking only exit 1) would require a per-grep wrapper function and was rejected as scope creep for this cycle. Documented in L14b for future-cycle awareness.

## Edge Cases & Risks

- **Sed-rewrite drift**: future cycle adds `/root/X` constant to deploy.sh that the rewriter doesn't know about → tests would silently leak to real `/root/X`. **Mitigation**: M-PATHSCAN runs after every rewrite, before any invocation. Must be Phase 1.
- **DAEMON_HOMES multi-line array**: anchored single-line sed leaves `/root/.happy*` strings intact. **Mitigation**: M-REWRITE.2/3 require block replacement with element-count assertion.
- **Rollback's `[ -x /root/bin/safe-daemon-restart.sh ]` runtime check** at line 146: architect missed this; without rewrite, the test outcome depends on real `/root/bin/`. **Mitigation**: M-REWRITE.3 explicitly rewrites this line.
- **`$SANDBOX` in rewritten copy**: under `set -u`, any unset SANDBOX would crash. **Mitigation**: M-REWRITE bakes the absolute resolved sandbox path into the copy (no literal `$SANDBOX` in the rewritten file).
- **Static-scan false positives**: regex `/(root|var|usr)/[A-Za-z._-]` matches operator-hint text in log strings. **Mitigation**: M-PATHSCAN.3 line-aware allowlist (comment lines, log/echo string-literal lines).
- **Per-scenario timeout**: a scenario that hangs would block the whole runner. **Mitigation**: M-RUNNER.3 uses `timeout 45s` per scenario.
- **Test data directory `/dev/shm`**: `/tmp` may be tmpfs-backed and small; mktemp default uses `$TMPDIR`. **Mitigation**: M-SANDBOX.1 explicitly uses `/tmp` (where tmpfs is sized for general use); if that's a problem on a specific dev machine, dev should set `TMPDIR=/dev/shm/test-tmp`.
- **Stdin injection for confirm()**: production scripts use multiple confirms in sequence; a single `echo y` won't satisfy them. **Mitigation**: each scenario specifies the exact stdin payload (e.g., `printf 'y\ny\ny\n'` for 3 confirms).
