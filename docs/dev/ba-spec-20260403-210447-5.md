# BA Specification: Fix TaskView Title Duplication in ToolView

**Request ID**: dev-20260403-210447-5
**Created**: 2026-04-03T21:04:47Z

## Goal

Eliminate the duplicate header that appears when Task/Agent tool calls are rendered, where the outer ToolView header and the inner TaskView TaskSummary both display tool name/description, creating two stacked headers for the same tool call block. Additionally, add a visual divider between the ToolView header and its content area.

## Context

ToolView is the universal wrapper for all tool call blocks. It always renders a header row (icon + toolTitle + status). For Task/Agent tools, ToolView delegates its content area to TaskView via `getToolViewComponent()`. TaskView then renders its own TaskSummary header (tool titles with status icons and expand/collapse chevron), creating a redundant second header directly below the first.

The render chain is:
1. ToolView renders header (toolTitle from `taskLikeTool.title()` which returns `tool.input.description` or "Task")
2. ToolView renders content area containing TaskView
3. TaskView renders TaskSummary (showing the same filtered tool titles with status icons)

This produces two visually distinct but informationally redundant header rows stacked on top of each other.

## Requirements (MoSCoW)

### Must Have
- Remove the duplicate header by having TaskView skip its own TaskSummary when rendered inside ToolView's content area
- Ensure the outer ToolView header remains the single source of truth for the tool call title
- Preserve TaskSummary's expand/collapse functionality (chevron toggle) by moving it to the ToolView header or keeping it accessible
- Add a subtle visual divider (border or separator) between ToolView's header and its content area

### Should Have
- Maintain the tool status icons (running spinner, completed checkmark, error icon) that TaskSummary currently shows for child tools -- these should appear somewhere in the consolidated view
- Keep the "N more tools" count indicator visible

### Could Have
- Consolidate the child tool status summary into the ToolView header row itself (e.g., show status icons inline with the title)

### Won't Have (Non-Goals)
- Redesigning the entire ToolView layout
- Changing how non-Task/Agent tools render
- Modifying the expand/collapse behavior for child messages

## Edge Cases & Risks

- TaskView with zero filtered tools and zero messages returns null -- ToolView must handle this gracefully (already does via minimal check)
- TaskView is also rendered recursively inside ChildMessageBlock for nested tool calls -- ensure the fix does not break nested rendering
- The expand/collapse state for viewing child messages must remain functional after removing the inner header

## Acceptance Criteria

### AC1: No duplicate headers for Task/Agent tool calls
- GIVEN a session with a Task or Agent tool call that has child tool-call messages
- WHEN the tool call block is rendered
- THEN only ONE header row is visible showing the tool name/description

### AC2: Expand/collapse still works
- GIVEN a Task/Agent tool call with child messages
- WHEN the user taps the tool call block
- THEN the child messages expand or collapse as before

### AC3: Visual divider between header and content
- GIVEN any ToolView with non-minimal content (not just Task/Agent)
- WHEN the content area is rendered below the header
- THEN a subtle divider (border) separates the header from the content

### AC4: Child tool status remains visible
- GIVEN a Task/Agent tool call with running/completed/error child tools
- WHEN the tool call block is rendered in collapsed state
- THEN the status of child tools is still conveyed visually (either in the header or summary area)
