# BA Specification: 1M-Context Claude Models — Context-Usage Display Fix

**Request ID**: dev-20260424-143000-6
**Created**: 2026-04-24T14:30:00+00:00

## Goal

Replace the hardcoded `MAX_CONTEXT_SIZE = 190000` constant in `AgentInput.tsx` with a per-model context-window lookup so that 1M-context Claude sessions display a correct, non-zero percentage in the status bar.

## Context

The status-bar percentage "N% left" is computed as `(contextSize / MAX_CONTEXT_SIZE) * 100`. For any 1M-context session whose `contextSize` exceeds 190 000 tokens the numerator exceeds the denominator, `percentageUsed > 100`, and `Math.max(0, …)` clamps the display to `0% left`. The user reported this for every 1M Claude model variant. The fix requires introducing a `getModelContextWindow(modelKey)` helper that returns the correct denominator for the resolved model key, then threading that value into `getContextWarning`.

## Edge Cases & Risks

- **`modelMode?.key === 'default'`**: the user selected "default model". The actual model being used is in `session.metadata?.currentModelCode`. The fix must fall through to `currentModelCode` when the picker key is `'default'` or `null` to pick up the real 1M model ID.
- **Server-provided models**: when `metadata.models` is non-empty, `getAvailableModels` returns those instead of the hardcoded list. Their `key` values are the raw model IDs (e.g., `claude-opus-4-7-20260301-1m`). `getModelContextWindow` must handle these raw IDs via substring pattern matching (`/1m/i` suffix or `1m` anywhere in the key).
- **No model key available**: when both `modelMode?.key` and `currentModelCode` are `null`/`undefined`, use 200 000 as the safe default (non-1M behaviour — never worse than before).
- **190 000 → 200 000 for non-1M models**: this is a minor improvement (fixes the artificially early warning trigger); it is low-risk since the warning thresholds are percentage-based. Document explicitly so QA can verify the warning band shifts slightly for existing sessions.

### 1M model-key detection

The current hardcoded model keys in `getClaudeModelModes()` do NOT include any 1M entries — they are `'default'`, `'opus'`, `'sonnet'`, `'haiku'`. However, when the server provides model options (via `metadata.models`), the `key` field is the raw model ID string (e.g., `claude-sonnet-4-7-20260301-1m`). Detection logic:

```ts
export function getModelContextWindow(modelKey: string | null | undefined): number {
    if (!modelKey) return 200_000;
    // Match Anthropic 1M-context model naming convention
    if (/1m$/i.test(modelKey) || modelKey.includes('-1m-') || modelKey.includes(':1m')) {
        return 1_000_000;
    }
    return 200_000;
}
```
