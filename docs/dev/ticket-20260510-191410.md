## Goal

Add two atomic edits to `~/.claude/commands/spec.md` so the /spec orchestrator stops inventing nested `§5.X.A/B/C/D…` checklists under Section 5, and so /spec gains the same `--codex` opt-in adversarial-review mode that /dev already has. Both edits live in a single file; no new hooks, no validators, no schema, no system-level enforcement.

## Context

`commands/spec.md` line 49 already says `Section 5 → user's requirement verbatim`. Step 4 (lines 76-81) defines the legitimate multi-turn append shape — `### 5.N: <brief title>` followed by the verbatim requirement text. There is no prose, however, that forbids the orchestrator from going one level deeper and inventing `#### A. …` / `#### B. …` sub-sections that decompose the user's natural-language paragraph into a machine-voice checklist. A real instance is `docs/dev/specs/spec-20260506-203844.md`, where Section 5 contains §5.3.A through §5.3.K (eleven invented sub-headings rendered as `#### A. 总体分类与验收`, `#### B. 图片/图形渲染`, …). The user did not write that structure — the orchestrator did, while believing it was being helpful. Same pattern as the prior push.md drift (commit `5ffe628`): a prose rule existed but had no explicit DO NOT, and the orchestrator drifted toward "structuring".

Separately, /dev recently gained an opt-in `--codex` flag (`commands/dev.md` line 77) that, when set, propagates `codex_required: true` into every BA / QA / dev dispatch prompt so each subagent's "Codex adversarial consultation" block activates. /spec has no equivalent — its spec-subagent and split-QA dispatches always self-review, never debate against codex. The user wants the same opt-in capability available to /spec.

Investigation this session by `git-edge-case-analyst` confirmed that the §5.X.A/B/C inflation happens in the /spec orchestrator (the Claude session running `commands/spec.md`), NOT in the spec-subagent (`agents/spec.md`). Therefore the fix is single-file: `commands/spec.md`. Do not modify `agents/spec.md`.
