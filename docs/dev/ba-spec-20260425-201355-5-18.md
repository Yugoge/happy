# BA Specification: 5.18 — CronList inline card must show input line (bash-card style)

**Request ID**: dev-20260425-201355-5-18
**Created**: 2026-04-25T20:21:00Z

## Goal

Restore an input-summary row to the CronList tool's inline card so it visually
matches the Bash card pattern (a header row + a single dimmed `$ <args>`-style
body row). Today the inline card collapses to **only** the tool-name header
("CronList"); the user's verbatim requirement says the inline must "学习 bash +
subagent 的渲染模式 **展示 input 就行**" — i.e. show the input line, even when
input is `{}`.

## Context

In Cycle 5 of spec-20260424-084848, dev "simplified" CronList by stripping all
content below the header. QA wrote "PASS — only `CronList`, no INPUT/OUTPUT".
User pushed back (Cycle-5 audit): the prior PASS was a misreading. "展示 input"
means **render the input row in compact form** (like `$ ls -la` for Bash), not
**delete the input row**. Section 7 Cycle 5 correction (line 2889) is explicit:
"当前 inline 只剩 'CronList' 4 字。要参照 bash card 的 inline 渲染模式，把 input
行加回去（即使是 `{}` 也显示）。学习对象：bash card 的 `$ ls -la /tmp` 那种格式。"

## Requirements (MoSCoW)

### Must Have

- M1. The CronList inline card renders **two visual rows** in the conversation
  surface: (a) the existing header row (icon + "CronList"), AND (b) a NEW second
  row that summarizes the tool's input.
- M2. The second row renders **even when `tool.input` is `{}`** (no input
  arguments). When empty, it MUST display a literal placeholder such as `{}`,
  `cron()`, or equivalent — never an empty string and never null.
- M3. The second row's visual style MUST be derived from the Bash card's
  `commandLine` row pattern: monospace, dimmed/secondary color, single line,
  optional prompt glyph at the start. Same font family as Bash's command line.
- M4. Both desktop (1440x900) and mobile (390x844) viewports MUST show the
  second row without truncation of the placeholder portion.
- M5. The right-side detail panel (sidebar) — already shipped in Cycle 4 with
  Description / Input Parameters / Output sections — MUST remain unchanged.

- S1. When `tool.input` has actual keys, the second row should display a

## Edge Cases & Risks

- **Empty input** (`{}`): MUST still render — primary failure mode of Cycle 4.
- **Large input objects**: truncate to ~40 chars + ellipsis (existing logic in
  `extractDescription`).
- **Mobile viewport overflow**: the second row must wrap or truncate cleanly;
  no horizontal overflow of the message-card. Verify at 390px width.
- **i18n**: the placeholder `{}` should be language-neutral (literal braces) —
  do NOT pipe through `t()` for a literal JSON token.
- **No regression on Bash**: the fix is additive on CronList only; do not
  modify Bash's knownTools entry.
- **No regression on other tools**: do not change ToolView.tsx's render path,
  do not rename `extractSubtitle`. Move CronList's logic from
  `extractDescription` → `extractSubtitle` only on the CronList entry.
- **`extractDescription` cleanup**: leaving a no-op `extractDescription` is
  harmless; the simplest patch is to RENAME the existing function to
  `extractSubtitle`. Removing the dead `extractDescription` afterwards is
  optional cleanup.

## Technical Hints

- **Affected files** (this fix touches exactly ONE file):
  - `packages/happy-app/sources/components/tools/knownTools.tsx:952-967`
    (CronList entry).
- **Suggested patch shape** (smallest, lowest-risk):
  - Add an `extractSubtitle` to the CronList entry that returns the same
    string the current `extractDescription` returns (so the renderer actually
    consumes it). Optionally remove the now-redundant `extractDescription`.
  - Example shape (NOT prescriptive — dev decides exact text):
    ```ts
    extractSubtitle: (opts) => {
        const input = opts.tool.input || {};
        const keys = Object.keys(input);
        if (keys.length === 0) return '{}';
        const summary = JSON.stringify(input);
        return summary.length > 40 ? summary.slice(0, 40) + '...' : summary;
    }
    ```
- **Why this works**: `ToolView.tsx:161-164` reads `extractSubtitle` and
  feeds it into `cfg.description`, which `ToolView.tsx:93-97` renders as the
  second row (`<Text style={styles.toolDescription}>`). That second-row Text
  element exists in the JSX today; it is simply not populated for CronList
  because the field name is wrong.
- **Alternative (heavier, only if the subtitle row's styling is rejected as
  not "monospace enough")**: register a tiny `CronListView` in
  `views/_all.tsx` that mimics BashView's `commandLine` row (single
  `<View commandLine><Text prompt>...$ </Text><Text command>{summary}</Text>
  </View>`). This makes the dimmed monospace look pixel-identical to Bash.
  Prefer the lightweight `extractSubtitle` patch first; escalate only if
  visual review rejects.
- **Constraints**:
  - Do NOT remove the right-sidebar detail rendering — that's controlled by
    the generic ToolContent path opened on click and is correct as-is.
  - Do NOT mutate the `title`, `icon`, `minimal`, or `input` fields on the
    CronList entry.
  - Run `yarn typecheck` in `packages/happy-app` after the change.
