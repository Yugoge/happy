CONTEXT
The bug: codex-flavor sessions spawned by happy-daemon-dev never call notifyDaemonSessionStarted with their codexThreadId, so the daemon /list response (which only reads claudeSessionId) lists them with claudeSessionId=undefined. The user-only recovery script therefore cannot resume them after a daemon restart.

2. packages/happy-cli/src/codex/resumeExistingThread.ts lines 38-41 — symmetric pattern on resume path; widened ResumeThreadSession structural type with `readonly sessionId: string`.
