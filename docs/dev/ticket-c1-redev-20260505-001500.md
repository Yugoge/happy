### Step A3 — Atomic apply (extract → validate → swap)

```bash
TMP=$(mktemp /tmp/happy-restart-stage.XXXXXX) && \
cat /dev/shm/dev-workspace/happy-dev/docs/dev/proposal-c1-happy-restart-refactor-20260504-223115.sh.md \
  | tr -d '\r' \
  | awk '/^=== BEGIN happy-restart\.sh ===$/,/^=== END happy-restart\.sh ===$/' \
  | sed '1d;$d' \
  > "$TMP" && \
LINES=$(wc -l < "$TMP") && \
echo "staged_lines=$LINES" && \
[ "$LINES" -ge 400 ] && \
head -1 "$TMP" | grep -q '^#!/bin/bash$' && \
tail -1 "$TMP" | grep -q '^log "Services:\$SUMMARY_PARTS"$' && \
mv "$TMP" /root/bin/happy-restart.sh && \
chmod +x /root/bin/happy-restart.sh && \
echo "APPLY_OK"
```

**Why this form (codex-substituted self-review answers a, b, d, embedded)**:

- `tr -d '\r'` defends against accidental CRLF in the markdown source. (answer d.i)
- `awk '/^=== BEGIN happy-restart\.sh ===$/,/^=== END happy-restart\.sh ===$/'` selects lines 121..527 inclusive (407 lines) given confirmed markers. (answer a)
- `sed '1d;$d'` strips the BEGIN and END marker lines, leaving 405 script lines (122..526). (answer b)
- `[ "$LINES" -ge 400 ]` fail-fast guard: if extraction ever produces fewer than 400 lines, the apply ABORTS at the temp file — destination is NEVER touched. This is the single most important defense against the prior failure mode. (answer d.iv)
- `head -1 / tail -1` content-integrity spot-check: confirms the first line is the bash shebang and the last line is the `log "Services:..."` summary. If either fails, ABORT.
- `mv "$TMP" /root/bin/happy-restart.sh` is an atomic rename on the same filesystem, so a partial-write or disk-full mid-extraction CANNOT corrupt the destination. (answer d.iv)
- The closed-form (with `happy-restart\.sh`) is preferred over the open-prefix (recommended at proposal line 31) because we want maximum specificity and fail-loud-on-marker-drift behavior; Grep confirmed there are exactly two `^=== (BEGIN|END)` lines in the markdown so the open-prefix would also work, but closed-form is strictly safer here. (answer c)
- Single-line form (joined with `&&` and backslash continuations) — copy-paste as a single shell input to eliminate line-continuation hazard. (answer d.ii)
- Symlink-following: `mv` to a destination that is a regular file replaces it; `mv` to a symlink replaces the symlink itself with the file (since the source is a regular file). The destination is a regular file per orchestrator-asserted state, so `mv` produces the expected result. (answer d.iii)

If the pipeline succeeds, the final command echoes `APPLY_OK`. Any earlier failure short-circuits via `&&` and leaves `/root/bin/happy-restart.sh` UNTOUCHED (because the swap step is the last step).

## Edge Cases & Risks

- **Markdown edited between BA verification and user apply**: if anyone modifies the proposal markdown between now and when the user runs A3, the apply could pick up unintended content. Mitigation: A1's `grep -nE` re-verifies markers (and that there are exactly TWO of them at the expected line numbers); A3's `wc -l ≥ 400` and `head/tail` checks would catch shape changes. Residual: silent edits within the body (lines 122..526) would not be caught — accepted risk; the markdown is in an in-RAM workspace and the user is the only modifier.
- **Filesystem-full at `/tmp` mid-extraction**: `mktemp` would fail before `awk`, so no partial write. If `/tmp` fills DURING the awk run, the temp file would be truncated and `wc -l ≥ 400` would fail; destination is never touched. Recovery: free `/tmp` and retry.
- **`/root/bin/happy-restart.sh` is a symlink**: orchestrator-asserted to be a regular file. If it were a symlink, `mv` would replace the symlink itself with the new file (atomic-on-rename), which is also acceptable. `cp -p` for backup would copy the link target (since `-p` preserves but does not dereference); to be safe across both cases the user can add `-L` to `cp` to force following symlinks. Residual risk minimal.
- **Atomic-mv across filesystems**: `/tmp` and `/root/bin/` may be on different filesystems on some setups. If `mv` falls back to copy+unlink, the atomicity weakens (a failure mid-copy could leave a partial destination). Mitigation: stage in `/root/bin/.happy-restart.staged.$$` instead of `/tmp` to guarantee same-filesystem atomic rename. Optional improvement noted but the `/tmp` path works on this server (single-disk NVMe per CLAUDE.md).
- **Codex consultation hook-blocked**: codex skill invocation contains the substring `happy-restart` and is blocked by `pretool-bash-safety.sh`. Per BA codex graceful-fallback protocol, BA substituted self-review of all six adversarial questions; documented in `context.json` `codex_consult` field with `status: failed_hook_blocked`.
