## Goal

Permanently and completely forbid Claude (orchestrator AND every subagent, in this and any future session) from restarting **OR otherwise disrupting** any `happy-daemon-*` systemd unit, by any path — direct, chained, wrapper-script, env-shifted, time-shifted, dbus, dispatch-via-prompt, unit-file-edit, **OR alternative-systemctl-verb (reload / kill / try-restart / reload-or-restart)**. The ONLY admissible path is an explicit, time-bounded grant created by the user from a real TTY. The grant is single-shot, target-specific, and audited.

This is a **policy change**, not a regex hardening. The current global Bash hook (`/root/.claude/hooks/pretool-bash-safety.sh`) explicitly allow-lists `happy-daemon-dev` for `systemctl restart`/`stop`/`disable`/`enable`; that allowlist was correct policy until 2026-05-04 22:16 (when the orchestrator used it to chain a daemon restart that the user had not authorised) and is now policy-wrong under the user's verbatim directive: "进一步完善hook彻底永久根本禁止你使用任何途径自己重启，除非我使用allow command".

Iteration-2 expansion (per QA OBJ-3-A): `任何途径` is read literally — `systemctl reload`, `systemctl kill [-s SIG]`, `systemctl try-restart`, `systemctl reload-or-restart` are direct (non-wrapper) systemctl paths that produce daemon-state-disrupting outcomes equivalent to restart from the user's perspective; the existing hook gate at line 428 (`(stop|restart|disable|enable)`) does not cover them, so they fall through to exit 0 today even though `happy-daemon-dev` is no longer whitelisted under R1 of this spec. The fix extends the verb set.

## Edge Cases & Risks

- **Race**: user types `claude-allow-restart dev` but Claude is already mid-Bash. Mitigation: hook consume is atomic flock.
- **Crash mid-grant**: TTL ≤60s self-cleans.
- **Wrapper-class false positives**: `bash /tmp/*.sh` block is broad — accepted tradeoff per user directive.
- **Hook self-modification race**: settings.json `Write/Edit(.claude/hooks/**)` is in `ask` (already), so user is prompted; this is the intended UX. **Iter-2 spec does not change this layer (iter-1 was wrong to think it needed changing).**
- **Subagent dispatch indirection**: orchestrator dispatches subagent X, X writes a `/tmp/foo.sh`, subagent X invokes `bash /tmp/foo.sh`. Mitigation: rule on `bash /tmp/*.sh` blocks for orchestrator AND subagents.
- **Verb-set completeness — risk of further omission**: `man systemctl` (8) lists state-mutating verbs as approximately {start, stop, restart, reload, try-restart, reload-or-restart, kill, isolate, set-property, mask, unmask, enable, disable, link, revert, edit}. Iter-2 covers {stop, restart, disable, enable, reload, kill, try-restart, reload-or-restart}. Verbs NOT covered: `start`, `isolate`, `set-property`, `mask`, `unmask`, `link`, `revert`, `edit`. **Rationale for exclusion**: `start` is non-disruptive (only fires if unit not active; happy-daemon-dev is always active under systemd `Restart=on-failure`); `isolate` would take down most of the system and is blocked by other safety rules; `mask`/`unmask`/`link`/`revert`/`edit` modify the unit definition rather than runtime state and are covered by Layer 2 Edit/Write blocks on `/etc/systemd/system/happy-daemon-*.service.d/`. If the user later requests these verbs added to coverage, a one-line regex extension suffices.

## Acceptance Criteria

### AC1: Bare systemctl restart of happy-daemon-dev is blocked

- **GIVEN** no sentinel grant present at `/tmp/claude-allow-daemon-restart-dev.flag`
- **WHEN** any tool source (Bash, orchestrator or subagent) issues the command `systemctl restart happy-daemon-dev` or `sudo systemctl restart happy-daemon-dev`
- **THEN** the bash hook exits with code 2
- **AND** stderr contains literal substring `BLOCKED:` AND `daemon-restart-prohibition`
- **AND** no daemon process is restarted (verify via `systemctl show happy-daemon-dev -p ActiveEnterTimestamp` unchanged before/after).

### AC2: Chained / wrapped systemctl restart is blocked

- **GIVEN** no sentinel grant present
- **WHEN** any of these commands is issued:
  - `systemctl restart happy-daemon-dev && echo ok`
  - `bash -c "systemctl restart happy-daemon-dev"`
  - `eval "systemctl restart happy-daemon-dev"`
  - `nohup systemctl restart happy-daemon-dev &`
  - `systemd-run --unit foo systemctl restart happy-daemon-dev`
  - `timeout 30 systemctl restart happy-daemon-dev`
  - `python3 -c "import subprocess; subprocess.run(['systemctl','restart','happy-daemon-dev'])"`
  - heredoc body containing the systemctl invocation
- **THEN** the bash hook exits with code 2 for each
- **AND** stderr contains literal substring `BLOCKED:` AND one of `daemon-restart-prohibition`, `daemon-restart-wrapper`.

### AC2.5: Alternative-verb systemctl invocations are blocked (NEW iter-2 — addresses OBJ-3-A)

- **GIVEN** no sentinel grant present
- **WHEN** any of these commands is issued (each tested independently):
  - `systemctl reload happy-daemon-dev`
  - `systemctl kill happy-daemon-dev`
  - `systemctl kill -s SIGTERM happy-daemon-dev`
  - `systemctl kill --signal=HUP happy-daemon-dev`
  - `systemctl try-restart happy-daemon-dev`
  - `systemctl reload-or-restart happy-daemon-dev`
  - `sudo systemctl reload happy-daemon-dev` (sudo prefix variant)
  - `systemctl reload happy-daemon` (production target — must also block)
  - `systemctl reload happy-daemon-jade` (production-jade variant — must block)
- **THEN** the bash hook exits with code 2 for each
- **AND** stderr contains literal substring `BLOCKED:` AND `daemon-restart-prohibition`
- **AND** no daemon state changes (verify via `systemctl show happy-daemon-dev -p ActiveState,SubState` unchanged before/after, AND for `kill` variants verify the daemon's main PID unchanged via `systemctl show -p MainPID`).

### AC3: Wrapper script invocation is blocked

- **GIVEN** any file at `/tmp/foo.sh`, `/var/tmp/bar.sh`, or `/dev/shm/baz.sh`
- **WHEN** `bash /tmp/foo.sh` (or the other paths) is issued by orchestrator OR subagent
- **THEN** the bash hook exits with code 2
- **AND** stderr contains literal substring `BLOCKED:` AND `daemon-restart-wrapper`

### AC4: Daemon HTTP /stop is blocked unconditionally (revised iter-2 — addresses OBJ-3-E and OBJ-3-F)

- **GIVEN** no sentinel grant present
- **WHEN** any of these commands is issued:
  - `curl -X POST http://localhost:42173/stop`
  - `curl -X POST http://127.0.0.1:9000/stop`
  - `wget --method=POST http://localhost:8080/stop`
  - `nc localhost 42173` followed by `POST /stop`
  - `curl http://127.0.0.1:42173/stop` (GET — also blocked)
  - `python3 -c "import requests; requests.post('http://127.0.0.1:42173/stop')"`
- **AND** none of the above command bodies contain the literal token "daemon" or "happy-daemon" anywhere
- **THEN** the bash hook exits with code 2
- **AND** stderr contains literal substring `BLOCKED:` AND `daemon-restart-http-stop`
- **Rationale**: the daemon HTTP `/stop` endpoint is the only documented use of the path `/stop` on a localhost port in this project; false-positive risk on other localhost services is accepted per `彻底永久根本禁止`.

### AC5: Edit/Write to systemd unit files is blocked

- **GIVEN** no sentinel grant present
- **WHEN** Edit or Write tool targets any of:
  - `/etc/systemd/system/happy-daemon-dev.service`
  - `/etc/systemd/system/happy-daemon.service`
  - `/etc/systemd/system/happy-daemon-jade.service`
  - `/etc/systemd/system/happy-daemon-qijie.service`
  - `/etc/systemd/system/happy-daemon-dev.service.d/override.conf`
- **THEN** the production-files hook exits with code 2
- **AND** stderr contains literal substring `BLOCKED:` AND `daemon-restart-edit`

### AC6: Edit/Write to grant sentinel is blocked

- **WHEN** Edit, Write, or Bash redirect (`>`, `>>`, `tee`, `cp`, `mv`) targets `/tmp/claude-allow-daemon-restart-*.flag`
- **THEN** the appropriate hook exits with code 2
- **AND** stderr contains literal substring `BLOCKED:` AND `daemon-restart-sentinel-write`

### AC7: settings.json `permissions.deny` extends to all six newly-covered verbs (revised iter-2 — addresses OBJ-3-D)

### AC8: Agent dispatch with daemon-restart prompt is blocked at the prompt-purity layer (revised iter-2 — addresses OBJ-3-B)

- **GIVEN** the prompt-purity hook is loaded with the new category-conditional logic (`/root/.claude/hooks/pretool-orchestrator-prompt-purity.py:339` is updated from unconditional `return 0` to `return 2 if category == 'daemon-restart-prescription' else 0`)
- **WHEN** an Agent-tool dispatch's prompt contains `(restart|reload|stop|disable|kick|cycle|bounce|kill|try-restart|reload-or-restart)` within ~30 tokens of `(happy-daemon|systemctl)` (hard regex hit, daemon-restart-prescription category)
- **THEN** the prompt-purity hook exits with code 2 (escalating from the prior warn-only mode for THIS category specifically)
- **AND** stderr contains literal substring `BLOCKED:` AND `daemon-restart-prompt`
- **AND** the existing warn-only behavior is preserved for ALL OTHER categories — verify by triggering a tool-name-prescription hit (e.g. prompt containing `use the Edit tool to ...`) and confirming the hook still exits 0 with the legacy STDERR_HEADER, NOT exit 2.
- **AND** subagent-emitted dispatches that would have been exempted by the line-315 `agent_id` check ALSO trigger the block for the daemon-restart-prescription category (subagent exemption removed for THIS category only; preserved for all others).

### AC8.5: Soft-hit and hard-hit audit log entries are written (NEW iter-2 — addresses OBJ-3-B audit-log gap)

- **GIVEN** the prompt-purity hook fires (hard or soft hit) for the daemon-restart-prescription category
- **WHEN** the hook completes (regardless of exit code)
- **THEN** a new line is appended to `~/.claude/logs/claude-daemon-restart-grants.log`
- **AND** the line is valid JSON containing fields `ts` (ISO-8601), `sid` (string), `source: "prompt-purity"`, `category: "daemon-restart-prescription"`, `hit_kind` (one of `"hard"`, `"soft"`), `snippet` (string, ≤200 chars), `exit_code` (integer 0 or 2)
- **AND** the file's permissions are user-writable (mode 0644 or 0640).

### AC9: Sentinel grant unlocks exactly one restart (revised iter-2 — addresses OBJ-3-C log path)

- **GIVEN** user runs `claude-allow-restart dev --ttl 30 --reason "patch test"` from a real TTY (no sudo required)
- **AND** the script writes `/tmp/claude-allow-daemon-restart-dev.flag` with target=dev, expires_at=now+30s, session_id=<active-claude-sid>, single_shot=true
- **WHEN** Claude (orchestrator or subagent) within 30s issues `systemctl restart happy-daemon-dev`
- **THEN** the bash hook exits with code 0
- **AND** the sentinel file is unlinked
- **AND** an entry is written to `~/.claude/logs/claude-daemon-restart-grants.log` with `outcome=consumed`
- **AND** a second `systemctl restart happy-daemon-dev` (still within 30s) exits with code 2 (single-shot preserved)
- **AND** stderr of the second contains `BLOCKED:` AND `daemon-restart-prohibition`.

### AC10: Sentinel grant TTL expires (revised iter-2 — log path)

- **GIVEN** user runs `claude-allow-restart dev --ttl 5` from a real TTY (no sudo required)
- **WHEN** Claude waits ≥6 seconds, then issues `systemctl restart happy-daemon-dev`
- **THEN** the bash hook exits with code 2
- **AND** stderr contains literal substring `BLOCKED:` AND `daemon-restart-prohibition`
- **AND** an entry is written to `~/.claude/logs/claude-daemon-restart-grants.log` with `outcome=expired`.

### AC11: Sentinel grant target mismatch fails closed

- **GIVEN** user runs `claude-allow-restart dev --ttl 30`
- **WHEN** Claude issues `systemctl restart happy-daemon` (production target, not dev)
- **THEN** the bash hook exits with code 2
- **AND** stderr contains literal substring `BLOCKED:` AND `daemon-restart-prohibition`
- **AND** the sentinel for `dev` is NOT consumed (still valid for a subsequent `dev` restart within TTL).

### AC12: Sentinel grant session mismatch fails closed

- **GIVEN** user runs `claude-allow-restart dev --ttl 30` while session A is active
- **WHEN** session A ends and session B starts within 30s
- **AND** session B issues `systemctl restart happy-daemon-dev`
- **THEN** the bash hook exits with code 2 (session_id mismatch)
- **AND** the sentinel is NOT consumed.

- **THEN** the script exits with code 1
