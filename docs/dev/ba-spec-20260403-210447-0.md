# BA Specification: Restore LaTeX Rendering in MarkdownView

**Request ID**: dev-20260403-210447-0
**Created**: 2026-04-03T21:04:47Z

## Goal

Restore LaTeX math rendering support that was accidentally removed in commit `1612a409` ("fix: 19 bug fixes from BUG-FIXES.md audit"). Both the `$$...$$` parser in `parseMarkdownBlock.ts` and the `latex` case branch + import in `MarkdownView.tsx` were stripped out, causing all LaTeX content to be silently dropped.

## Context

Commit `f8b208fa` ("feat: F1 LaTeX/Mermaid + F2 image upload") originally added complete LaTeX support: parsing `$$...$$` blocks in `parseMarkdownBlock.ts`, a `latex` type in the `MarkdownBlock` union (`parseMarkdown.ts`), a full KaTeX-based renderer (`LatexRenderer.tsx`), and a case branch in `MarkdownView.tsx`. Subsequent commit `1612a409` (overnight bug-fix batch) inadvertently removed the parser and renderer wiring while the type definition and renderer component file were left intact. The result: `LatexRenderer.tsx` is a complete, working component that is never invoked.

## Requirements (MoSCoW)

### Must Have
- Restore `$$...$$` LaTeX block parsing in `parseMarkdownBlock.ts` (single-line and multi-line)
- Restore `import { LatexRenderer } from './LatexRenderer'` in `MarkdownView.tsx`
- Restore `else if (block.type === 'latex')` case in `MarkdownView.tsx` `renderContent()`, rendering `<LatexRenderer content={block.content} key={index} />`
- LaTeX parsing must be placed BEFORE the code-block parser (since `$$` could be confused with other markers if checked later)

### Should Have
- Ensure `katex` package is in `package.json` dependencies (verify, do not add if already present)

### Could Have
- Inline LaTeX (`$...$`) support (not in original implementation, out of scope for this fix)

### Won't Have (Non-Goals)
- Changes to `LatexRenderer.tsx` itself (it is complete and correct)
- Changes to `parseMarkdown.ts` type definitions (the `latex` type already exists in the union)
- New KaTeX configuration options
- Inline math (`$...$`) parsing

## Edge Cases & Risks

- Single-line `$$E = mc^2$$` must be parsed correctly (content between the `$$` markers)
- Multi-line blocks must consume lines until closing `$$`
- A `$$` that starts a line but never closes should not hang the parser (original impl handles this by consuming to EOF)
- The `latex` type already exists in the `MarkdownBlock` union in `parseMarkdown.ts`, so no TypeScript changes needed there

## Acceptance Criteria

### AC1: Single-line LaTeX rendering
- GIVEN a message containing `$$E = mc^2$$` on a single line
- WHEN the message is rendered in MarkdownView
- THEN the LaTeX formula is rendered via KaTeX (not displayed as raw text, not silently dropped)

### AC2: Multi-line LaTeX rendering
- GIVEN a message containing a multi-line LaTeX block starting with `$$` and ending with `$$` on separate lines
- WHEN the message is rendered in MarkdownView
- THEN the full LaTeX content between the markers is rendered via KaTeX

### AC3: Non-LaTeX content unaffected
- GIVEN a message with no `$$` markers
- WHEN the message is rendered in MarkdownView
- THEN all existing block types (text, headers, code, mermaid, tables, lists, images, options) render identically to before

### AC4: TypeScript compilation
- GIVEN the restored code
- WHEN `yarn typecheck` is run in happy-app
- THEN no type errors are introduced

## Technical Hints

- Affected files:
  - `packages/happy-app/sources/components/markdown/parseMarkdownBlock.ts` (restore `$$` parser before code-block section)
  - `packages/happy-app/sources/components/markdown/MarkdownView.tsx` (restore import + case branch)
- Reference commit: `f8b208fa` contains the exact code to restore
- Regression commit: `1612a409` removed the code
- `LatexRenderer.tsx` and `parseMarkdown.ts` (type union) need NO changes
- Follow existing pattern: mermaid is detected inside code-block parser; latex has its own `$$` detection before the code-block parser
