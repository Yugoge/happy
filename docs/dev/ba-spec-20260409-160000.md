# BA Specification: Forward Subagent Sidechain Messages from JSONL to Server

**Request ID**: dev-20260409-160000
**Created**: 2026-04-09T16:00:00Z

## Goal

Forward `isSidechain: true` messages from Claude's JSONL session file to the happy-server so the app can display subagent internal operations (child tool calls, text output, thinking) in the sidebar conversation view.

## Context

When Claude uses Agent/Task tools, the SDK's stream-json stdout only emits the parent `tool_use` and final `tool_result`. The subagent's internal operations (child tool calls, text, thinking) are written to the JSONL file with `isSidechain: true` but never forwarded to the server. The entire downstream pipeline (sessionProtocolMapper, typesRaw normalization, reducerTracer, reducer Phase 4, SidebarAgentConversation) already works correctly -- verified by existing tests with `task_non_sdk.jsonl` fixture. The only gap is the CLI not forwarding sidechain messages from JSONL to the server.

An existing pattern already solves an identical problem: `isMeta: true` skill prompts are also not emitted by the SDK but are written to JSONL. The session scanner already forwards these in the `sendExisting: false` path (sessionScanner.ts line 55) and via the meta-scanner callback (claudeRemoteLauncher.ts line 438-441). The fix extends this same pattern to sidechain messages.

## Requirements (MoSCoW)

### Must Have
- Forward `isSidechain: true` messages from JSONL to server via session scanner
- Deduplicate sidechain messages (SDK may emit some via stdout that are also in JSONL)
- Remove the fake Task sidechain root (`convertSidechainUserMessage` call at lines 329-342) since real sidechain messages from JSONL include the actual root
- Reset dedup state between Claude launches (in finally block)

### Should Have
- Maintain existing `isMeta` forwarding behavior unchanged
- Keep message ordering consistent (sidechain messages interleaved with live SDK messages)

### Could Have
- Debug logging for sidechain message forwarding count

### Won't Have (Non-Goals)
- Changes to sessionProtocolMapper.ts (already handles sidechain correctly)
- Changes to app-side code (reducerTracer, reducer, SidebarAgentConversation)
- Changes to typesRaw.ts normalization
- Changes to the recovery-mode scanner (sendExisting: true path)

## Edge Cases & Risks

- **Deduplication**: If SDK ever starts emitting sidechain messages via stdout, they would be converted by sdkToLogConverter AND read from JSONL. The `sentSidechainUuids` Set prevents duplicates.
- **Timing**: Sidechain messages written to JSONL after scanner marks existing messages as processed will be picked up by the file watcher naturally (same mechanism as isMeta).
- **Message ordering**: Sidechain messages from JSONL may arrive slightly after the SDK-emitted parent tool_use. This is acceptable because the reducer uses UUID-based linking, not insertion order.
- **Fake sidechain root removal**: The `convertSidechainUserMessage` created a synthetic sidechain root for Task tools. Real JSONL sidechain messages include the actual user message with `isSidechain: true`, making the synthetic one redundant and potentially causing duplicates.

## Acceptance Criteria

### AC1: Sidechain messages forwarded from JSONL
- GIVEN Claude uses an Agent/Task tool that spawns a subagent
- WHEN the subagent performs internal operations (tool calls, text output)
- THEN the sidechain messages appear in the app sidebar as `message.children`

### AC2: No duplicate messages
- GIVEN sidechain messages are forwarded from JSONL
- WHEN the SDK also emits some sidechain messages via stdout
- THEN each message appears exactly once (dedup via UUID set)

### AC3: Existing functionality preserved
- GIVEN the changes to sessionScanner and claudeRemoteLauncher
- WHEN Claude performs normal (non-subagent) operations
- THEN all existing behavior (isMeta forwarding, tool call delay, plan mode hack) works unchanged

### AC4: Tests pass
- GIVEN the code changes
- WHEN `yarn test` is run in happy-cli
- THEN all existing tests pass
