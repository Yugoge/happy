## Behavioral Impact (Iteration 1 — resolving OBJ-1)

This section explicitly documents the runtime semantics on Android post-fix, addressing QA's OBJ-1 concern that the user's `不要损害我的预期行为` clause must not be silently violated.

**Android tap semantics post-fix** (verified by codex iteration-1 consultation, output `/var/tmp/codex-outputs/codex-iter1-obj1-resolution.txt`):

- The upstream blob wraps `children` in `<DropdownMenu.Trigger>`. Codex inspected `@expo/ui@55.0.6` source at `package/src/jetpack-compose/DropdownMenu/index.tsx:77-79` and confirmed: **`DropdownMenu.Trigger` is NOT an event wrapper — it returns its children inside an anchor/rendering container only**.
- The Android native side (`package/android/src/main/java/expo/modules/ui/menu/DropdownMenu.kt:21-28`) renders the Compose `DropdownMenu` with `expanded = props.expanded`. The TS-side `DropdownMenuProps` defaults `expanded` to `false` (per `DropdownMenuRecords.kt:8-18`) and exposes no `activationMethod` field on the typed surface in 55.0.6.
- Result: a regular tap on the avatar `Pressable` reaches `Pressable.onPress` and **`handleAvatarPress` fires** (avatar navigation preserved). The `DropdownMenu` does NOT open from this tap because the upstream blob does not supply a controlled `expanded` state.

**Comparison to user-baseline expected behavior**:

- The "expected behavior" baseline is the last CI-green build's runtime semantics. The currently-broken HEAD does not typecheck, so no CI-gated release with the broken file ever shipped to Android end-users. The user-visible baseline on Android is the last working build, in which avatar tap fired `handleAvatarPress` (navigation).
- **Post-fix avatar tap on Android: `handleAvatarPress` fires (navigation) — IDENTICAL to the user-baseline behavior**. The user's `不要损害我的预期行为` clause is preserved for the avatar tap interaction.

**Known Android quick-actions reachability gap (path-external observation)**:

- The Android long-press / context menu reachability via `<DropdownMenu>` is not guaranteed in `@expo/ui@55.0.6` because the upstream blob does not wire controlled `expanded` state. This is the same reachability gap that existed in the broken HEAD (where the menu did not function at all due to typecheck failure preventing build). The fix preserves the avatar tap navigation; making the Android quick-actions menu reachable is a separate user-need cycle requiring either an `@expo/ui` upgrade or a controlled-state wrapper, both of which expand scope beyond the user's "minimum single-file fix" directive.
