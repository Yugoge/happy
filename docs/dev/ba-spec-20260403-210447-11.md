# BA Specification: Enable Gzip Compression in Nginx for Web App

**Request ID**: dev-20260403-210447-11
**Created**: 2026-04-03T21:04:47Z

## Goal

Add gzip compression directives to the nginx configuration in Dockerfile.webapp to reduce the 7.4MB uncompressed JS bundle transfer size.

## Context

The nginx configuration in Dockerfile.webapp (stage 3, lines 54-96) serves the Expo web export as static files but does not include any gzip directives. The main JS bundle is 7.4MB uncompressed, which significantly impacts initial page load time. Nginx supports both on-the-fly gzip compression and serving pre-compressed .gz files via gzip_static.

## Requirements (MoSCoW)

### Must Have
- Add `gzip on;` directive to enable on-the-fly compression
- Add `gzip_types` covering JavaScript, CSS, HTML, JSON, SVG, and other text formats
- Set reasonable compression level (`gzip_comp_level 6`)
- Set `gzip_min_length 256` to avoid compressing tiny responses

### Should Have
- Add `gzip_static on;` to serve pre-compressed .gz files if Expo build generates them
- Add `gzip_vary on;` for correct caching with CDN/proxies (Cloudflare)
- Add `gzip_proxied any;` since traffic goes through Cloudflare tunnel

### Could Have
- Add `gzip_buffers` tuning for large responses

### Won't Have (Non-Goals)
- Brotli compression (requires nginx module not in alpine image)
- CDN-level compression configuration (Cloudflare handles its own layer)
- Build pipeline changes to pre-compress assets

## Edge Cases & Risks

- Cloudflare tunnel may already apply some compression, but origin compression still helps for direct access and reduces tunnel bandwidth
- gzip_static requires .gz files to exist alongside originals -- if Expo doesn't generate them, it silently falls back to on-the-fly compression
- Very high compression levels (7-9) increase CPU usage with diminishing returns

## Acceptance Criteria

### AC1: JS bundle served compressed
- GIVEN a browser request for the main JS bundle with Accept-Encoding: gzip
- WHEN nginx serves the response
- THEN Content-Encoding: gzip header is present and transfer size is significantly smaller than 7.4MB

### AC2: HTML served compressed
- GIVEN a browser request for index.html
- WHEN nginx serves the response
- THEN the response is gzip-compressed

### AC3: Non-compressible types unaffected
- GIVEN a request for an image file (PNG, JPEG)
- WHEN nginx serves the response
- THEN no gzip compression is applied (already compressed format)

## Technical Hints

- Affected file: `Dockerfile.webapp` (lines 54-96, nginx config RUN block)
- Insert gzip directives inside the `server { }` block, before the `location` blocks
- Both production (`happy-app:message-fixes`) and dev (`happy-app:dev`) images use this Dockerfile
- After change, both images need rebuilding to take effect
- Test with: `curl -H 'Accept-Encoding: gzip' -sI http://localhost:8097/ | grep -i content-encoding`
