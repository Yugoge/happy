# BA Specification: Fix MCP change_title Tool Failure

**Request ID**: dev-20260404-110000
**Created**: 2026-04-04T11:00:00Z

## Goal

Fix the `mcp__happy__change_title` tool so it actually changes the session title instead of failing every time. The tool call is blocked by the `pretool-workflow-gate.py` PreToolUse hook before it even reaches the MCP bridge/server.

## Context

The `change_title` MCP tool worked correctly until mid-March 2026 (last 100% success: March 15 in jade daemon logs). Starting March 16, the `pretool-workflow-gate.py` hook was introduced as a global PreToolUse hook with NO matcher (runs on every tool). This hook blocks any tool call when there is an active workflow bookmark and TodoWrite has not been acknowledged. Since `mcp__happy__change_title` is an infrastructure tool (not a dev tool), it should be exempt from workflow gating -- but it is not.

Additionally, a previous overnight dev session made incorrect changes to `knownTools.tsx` (removed hidden:true, added mcp__happy__change_title entry) and `messageToEvent.ts` (removed change_title interception). These changes must be REVERTED as the user confirmed the native service message rendering is correct.

## Requirements (MoSCoW)

### Must Have
- Exempt `mcp__happy__change_title` from `pretool-workflow-gate.py` hook checks (root cause fix)
- Revert overnight changes to `knownTools.tsx` (restore hidden:true, minimal:true, noStatus:true)
- Revert overnight changes to `messageToEvent.ts` (restore mcp__happy__change_title interception)

### Should Have
- Verify the fix works by checking that title changes succeed in a real session

### Could Have
- Add other MCP infrastructure tools to the exemption list if any exist

### Won't Have (Non-Goals)
- Changes to how change_title renders in the UI (user confirmed it is fine)
- Changes to the STDIO bridge or HTTP MCP server architecture (they work correctly)
- Changes to the MCP SDK version or transport layer

## Edge Cases & Risks

- The hook exemption must use exact tool name matching to avoid bypassing workflow controls for unintended tools
- The revert of messageToEvent.ts must preserve any other legitimate changes made in the same commit (check diff carefully)
- The global settings.json hook configuration has no matcher for pretool-workflow-gate.py, so the fix must be in the Python script itself

## Acceptance Criteria

### AC1: Title change succeeds during active workflow
- GIVEN a session with an active workflow bookmark
- WHEN Claude calls `mcp__happy__change_title` with a title string
- THEN the tool call is not blocked by the workflow gate hook
- AND the title is persisted to session metadata
- AND a service message "Title changed to X" appears in the message stream

### AC2: Overnight UI changes reverted
- GIVEN the files knownTools.tsx and messageToEvent.ts
- WHEN compared to their pre-overnight state
- THEN knownTools.tsx has change_title with hidden:true, minimal:true, noStatus:true
- AND messageToEvent.ts intercepts mcp__happy__change_title and converts to event

### AC3: Workflow gate still works for other tools
- GIVEN a session with an active workflow bookmark where TodoWrite not acknowledged
- WHEN Claude calls any non-exempt tool (e.g., Bash, Edit, Read)
- THEN the workflow gate still blocks with the appropriate error message
