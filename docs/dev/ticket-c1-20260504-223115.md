## Goal

Refactor `/root/bin/happy-restart.sh` (currently 142 lines, hardcoded to the three production daemons + production Docker) into a target-dispatch architecture so the user can restart exactly ONE happy stack — `dev`, `default`, `jade`, `qijie`, or all-in-one (`all`). Why: today, restarting one daemon (e.g. dev) requires touching all three production daemons + production Docker as collateral, which is unsafe and contradicts the project's daemon-isolation invariants.

## Context

The script is the user's single sanctioned restart entry point (Bash hook PERMANENTLY blocks Claude from invoking it; only the user runs it from a TTY). Today its hardcoded shape (3 prod daemons + Docker) means the user has no way to restart only the dev stack — they must either invoke the script (collateral damage to production) or hand-craft systemctl invocations (no audit, no health gate, no session save). The architect report (`docs/dev/architect-happy-restart-and-daemon-prohibition-20260504-223115.md`) enumerates 9 structural problems and recommends a target dispatch table.

## Edge Cases & Risks

- **E1**: Unknown `--target` value (e.g. `--target prod` typo) → script must `exit 2` with `BLOCKED: unknown target 'prod'. Valid: dev, default, jade, qijie, all, all-prod` and a list of valid targets. Do NOT default-fall-through to all-prod.
- **E2**: `--target dev` invoked while dev binary missing (worktree dist not built) → binary gate must fail-closed and exit 1 with FIX hint pointing at `cd /dev/shm/dev-workspace/happy-dev/packages/happy-cli && yarn build`.
- **E3**: `--target all` simultaneously runs dev + production. Concurrent dev daemon restart while production daemons are mid-stop is fine (no shared state); but the binary gate must validate BOTH dist trees before any stop occurs (fail-fast prevents half-restart).
- **E4**: `--target dev --no-sessions` should parse correctly; existing positional `$1=--no-sessions` must be replaced by proper flag parsing or the regression-guard contract breaks. Implementation gotcha: today's `SKIP_SESSIONS="${1:-}"` pattern fails when target flag arrives first.
- **E5**: Production Docker `up -d` recreates BOTH `happy-server` and `happy-web` even if only `--target jade` is asked — but those Docker containers are shared across all 3 production daemons. Acceptable: the Docker step runs at most ONCE per invocation, regardless of which prod daemon is the target. (Single Docker recreate is cheaper than the daemon stop/start cost.)
- **E6**: Concurrent invocations: `--target dev` and `--target jade` simultaneously should both succeed. Same target twice (e.g. two `--target dev`) must serialize via flock to avoid binary-gate / PID-verify race.
- **E7**: `set -euo pipefail` interaction with the new arg parser — must use `${VAR:-default}` patterns to avoid unbound-variable errors when only some flags are present.
- **R-Risk**: introducing arg parsing breaks the `${1:-}` regression for users who muscle-memory invoke `bash /root/bin/happy-restart.sh --no-sessions`. Test case must cover this exact form.

## Acceptance Criteria

### AC1: Target dispatch table is data-driven, not branch-driven

- **GIVEN** the refactored script
- **WHEN** the user reads the script source
- **THEN** there exists a single declarative data structure (associative array, here-doc, or function table) mapping `dev | default | jade | qijie | all-prod | all` to a record `{systemd_unit, home_dir, binary_dist_glob, docker_services, server_url_default}`
- **AND** the stop loop, start loop, binary-check loop, PID-verify loop all iterate over the chosen target's record(s) — NOT over a hardcoded daemon-name list inside the loop body
- **AND** `--target all` iterates dev + default + jade + qijie + production Docker; `--target all-prod` iterates default + jade + qijie + production Docker (preserves today's default behavior); `--target dev` iterates ONLY dev daemon (no Docker step).
- **MEASURABLE**: grep the refactored script for hardcoded daemon unit names. Hits inside the dispatch table = expected. Hits in stop/start/verify loop bodies (outside the table) = AC1 fail.

### AC2: Per-target binary health gate validates the right binary

- **GIVEN** `--target dev`
- **WHEN** the binary gate runs
- **THEN** it globs `/dev/shm/dev-workspace/happy-dev/packages/happy-cli/dist/*.mjs` (NOT `/usr/lib/node_modules/happy-coder/dist/`)
- **AND** the same 3 token checks (`shouldHideParentToolCall` absence, `Task||Agent` presence, `sendExisting` presence) are applied
- **GIVEN** `--target default | jade | qijie`
- **THEN** the gate globs `/usr/lib/node_modules/happy-coder/dist/*.mjs` (today's path; preserves prod behavior)
- **GIVEN** `--target all`
- **THEN** BOTH globs are checked; ANY failure aborts BEFORE any daemon is stopped (fail-fast).
- **MEASURABLE**: with dev dist deleted, `--target dev` exits 1 with FIX hint citing the worktree path; production targets are unaffected by missing dev dist.

### AC3: Docker step is target-conditional

- **GIVEN** `--target dev`
- **WHEN** the Docker step would run
- **THEN** the Docker recreate is SKIPPED entirely (the line for `cd /root/deploy && docker compose up -d happy-server happy-web` does NOT execute)
- **AND** the log records `target=dev: skipping Docker recreate (dev Docker managed by dev-overnight-build-deploy.sh)`
- **GIVEN** `--target default | jade | qijie | all-prod | all`
- **THEN** the Docker recreate runs EXACTLY ONCE (not once per target) and recreates `happy-server` + `happy-web`
- **MEASURABLE**: `docker ps --format '{{.Names}} {{.CreatedAt}}'` for `happy-server` shows the same `CreatedAt` after `--target dev` invocation as before; `--target jade` makes `CreatedAt` advance.

### AC4: Default-no-arg behavior is preserved (regression guard)

- **GIVEN** `bash /root/bin/happy-restart.sh` (no args)
- **WHEN** the script runs
- **THEN** behavior is IDENTICAL to today: stops `happy-daemon`, `happy-daemon-jade`, `happy-daemon-qijie`; recreates `happy-server` + `happy-web`; starts the same 3 daemons; verifies `~/.happy/`, `~/.happy-jade/`, `~/.happy-qijie/` daemon.state.json
- **AND** dev daemon is NOT touched (mirrors today's exclusion)
- **AND** the script's first log line names the target as `all-prod` (not `all`) for audit clarity
- **GIVEN** `bash /root/bin/happy-restart.sh --no-sessions` (legacy single-flag invocation)
- **THEN** behavior is identical to today (no session recovery; production-only restart)
- **MEASURABLE**: diff of `/var/log/happy-restart.log` lines between pre-refactor and post-refactor no-arg runs shows only the new `target=all-prod` audit tag and the new TASK-ID echo; functional steps are equivalent.

### AC5: TASK-ID emitted verbatim

- **GIVEN** any invocation of the script
- **WHEN** the script logs its first line
- **THEN** the log shows `TASK-ID: c1-20260504-223115` so the audit log records which refactor cycle produced this version
- **MEASURABLE**: `grep "TASK-ID: c1-20260504-223115" /var/log/happy-restart.log` returns ≥1 hit per invocation.

### AC6: Per-target session save uses existing `--home` arg

- **GIVEN** `--target dev`
- **WHEN** session save runs
- **THEN** the script invokes `bash /root/bin/happy-session-recovery.sh save --home /root/.happy-dev` (NOT a global save)
- **GIVEN** `--target jade`
- **THEN** the invocation is `... save --home /root/.happy-jade`
- **GIVEN** `--target all` or no-arg
- **THEN** the invocation is `... save` (no `--home`, global save — preserves today's behavior)
- **MEASURABLE**: `tail /var/log/happy-session-recovery.log` after `--target dev` shows `Scoped save: only /root/.happy-dev`; after `--target all`/no-arg shows the global save line.

### AC7: PID-state verify reads the right state file

- **GIVEN** `--target dev`
- **WHEN** verification runs after daemon start
- **THEN** the script reads `/root/.happy-dev/daemon.state.json`, extracts `pid`, runs `kill -0 <pid>` and logs `Daemon (dev) running OK (PID <pid>)` on success or `ERROR: Daemon (dev) not running after restart!` on failure

- **MEASURABLE**: a fake-corrupted `/root/.happy-dev/daemon.state.json` causes `--target dev` to log the ERROR; `--target jade` is unaffected.

### AC8: Unknown target rejected fail-closed

- **GIVEN** `--target prod` (typo) or `--target xxx`
- **WHEN** arg parser runs
- **THEN** script exits non-zero (`exit 2`) with stderr `BLOCKED: unknown target '<value>'. Valid: dev, default, jade, qijie, all-prod, all`
- **AND** no daemon is touched, no session save runs, no Docker recreate runs (fail-closed before any side effect)
- **MEASURABLE**: `bash /root/bin/happy-restart.sh --target prod; echo $?` prints `2` and `/var/log/happy-restart.log` has zero new lines.
